Astra vs Sol vs Fable 후기 비교

Astra 사용 후 Sol이 상대적으로 멍청해진 것 같다는 체감이 나오며 여러 사용자가 후기를 공유했다. Astra는 알아서 잘 처리하지만 중간에 딱 끊는 특성이 있고, /goal을 걸어두면 끝까지 잘 진행한다는 팁도 나왔다. Fable과 Astra를 둘 다 써본 사용자는 각각 잘하는 영역이 다르다며(예: 영상 프롬프트 자동화는 Fable이 낫고, 막힌 작업은 Astra가 잘 뚫어줌) 구매 여부를 고민하는 대화가 이어졌고, Astra 토큰 소모가 Fable보다도 빠르다는 의견도 있었다.

  • Astra 사용 후 Sol이 상대적으로 성능 저하된 것처럼 체감된다는 후기 다수
  • Astra는 지시를 알아서 잘 수행하지만 중간에 작업을 끊는 특성, /goal 설정하면 끝까지 진행
  • Fable과 Astra는 잘하는 영역이 다름(예: 영상 프롬프트 자동화는 Fable, 막힌 작업 뚫기는 Astra)
  • Astra 토큰 소모 속도가 Fable보다 빠르다는 의견, medium 설정으로 절약 권장
  • 이미 Fable 결제한 사용자가 Astra 추가 결제를 고민하다 결국 구매

Astra 세션 소모 및 사용 전략

Astra 모델을 계획과 구현 모두 익스트라 하이로 쓰면 너무 느리다는 고민이 나왔고, medium을 상한으로 low를 기본으로 쓴다는 답변이 나왔다. 다른 사용자는 계획은 엑하, 구현은 sol 엑하, 검증만 아스트라 엑하로 역할을 나눠 쓴다는 전략을 공유했다. 2시간 작업에 세션 75% 소모됐다는 불만도 있었다.

  • 아주 빡센 경우 아니면 medium을 상한, 평소엔 low 사용 추천
  • 계획은 엑하, 구현은 sol 엑하, 검증만 astra 엑하로 역할 분담하는 사용 전략도 공유됨
  • astra는 토큰 소모가 커서 2시간 작업에 세션 75% 소진되는 사례 있음

  • 초기화권 없이 사용량이 100%로 자동 리셋되는 사례 다수 보고
  • 초기화권을 썼는데 기대치보다 적게 회복된 사례도 존재
  • 63%에서 78%로 오르는 등 표시 시스템 버그로 추정되는 현상 발생

  • X(트위터)를 통해 전세계적으로 같은 증상 확인됨
  • 일부 사용자는 장애 중 리셋을 받기도 함
  • 이후 정상 복구, 보상성 리셋권을 기대하는 분위기

에이전트 앱빌딩과 추상화 논의

에이전트로 앱을 빌딩하면 MVP 단계까지는 프로그래밍 언어를 몰라도 된다는 의견이 나왔고, 스케일업 시점에 유지보수를 위해 언어를 배워도 된다는 실용적 접근이 공유됐다. OOP의 추상화 원칙이 현재 에이전트 시대에도 유효하다는 점, 네트워크 control plane 개념이 에이전트에도 적용된다는 점이 흥미롭다는 반응이 있었다. ADK를 포크해 러스트 엔진으로 최적화해보고 싶다는 계획도 언급됐다.

  • MVP까지는 노코드/에이전트로 충분, 스케일업 단계에서 유지보수 위해 언어 학습 필요
  • OOP 4대 원칙 중 추상화가 에이전트 시대에도 핵심 기조로 유지된다는 의견
  • 네트워크 control plane 개념이 에이전트 아키텍처에도 추상화되어 적용되는 점이 신기하다는 반응
  • ADK를 포크해 러스트 엔진으로 최적화하려는 개인 계획 공유(slop 우려도 언급)
