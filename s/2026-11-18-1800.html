6.2 속도와 사용 후기

6.2 Sol의 초당 토큰 생성 속도를 묻자 약 50이라는 전언과 Sol·Astra 모두 Fast 기준 70대라는 사용 경험이 나왔다. 6.2 Sol은 개선됐지만 과검증과 과설계가 여전하다는 의견이 있었고, Astra에도 비슷한 해외 후기가 있다는 말이 나왔다. Astra 6.2 코딩 사용자는 이전보다 효율적이고 결과는 비슷하지만 깊이 생각하는 과정이 짧아진 느낌이며, 6.2 high가 기존 Astra light처럼 느껴진다고 평가했다. 6.1 대비 수학·통계 성능 차이와 6.2의 채팅 모드 지원에 대한 질문과 기대도 있었지만 확인된 답변은 대화에 나오지 않았다.

  • Sol 속도가 초당 약 50토큰이라는 전언과 Sol·Astra의 Fast 속도가 70대라는 체감이 공유됐으며, 측정 조건은 자세히 나오지 않았다.
  • 한 참여자는 6.1 사용 경험에 아쉬움을 표현하며 6.2가 채팅 모드에도 나오기를 기대했다.
  • Sol 6.2는 나아졌지만 과검증·과설계가 남아 있다는 후기와 Astra도 비슷하다는 해외 후기 전언이 나왔다.
  • Astra 6.2는 코딩 결과가 기존과 비슷하면서 효율은 좋아졌지만 추론 과정이 짧아져 사용량을 더 쓰게 된다는 체감이 있었다.
  • 6.1 Sol과 6.2 Sol의 수학·통계 성능이나 지능 차이에 대한 발표가 있는지 질문했으나 답변은 확인되지 않았다.

Whosup 소개

Whosup이 무엇인지 질문이 나왔고, 대화에는 이름이 비슷한 다른 제품과 서비스를 열거한 답변도 등장했다. 확인된 자료에 따르면 Whosup은 열어 둔 터미널 AI 에이전트 세션을 브라우저 상황판에 모아 상태를 표시하는 herdr 플러그인이다. 상황판의 칸을 누르면 해당 세션으로 포커스를 옮기고, 재부팅 뒤 빈 칸에서는 해당 폴더의 최근 Claude Code 대화를 이어 열 수 있다. MIT 오픈소스이며 설치와 실행 환경 요건이 공개돼 있다.

  • 상황판은 세션별 입력 필요, 실패, 답변 도착, 진행 중, 유휴 상태를 표시한다.
  • 상황판에서 칸을 선택하면 herdr가 해당 터미널 칸으로 포커스를 옮긴다.
  • 재부팅 뒤 빈 칸의 ‘이어서 열기’ 기능으로 해당 폴더의 최근 Claude Code 대화를 이어 열 수 있다.
  • 설치 명령은 `herdr plugin install fivetaku/whosup --yes`이며 로컬 상황판 주소는 `http://127.0.0.1:4790`이다.
  • herdr 0.9.0 이상, Node.js 22.13 이상과 macOS 또는 Linux가 필요하며 MIT 라이선스로 공개됐다.
  • https://github.com/fivetaku/whosup

실시간 맥락 연결

실시간 대화에서 화제가 바뀔 때 관련된 과거 맥락을 적절히 이어 붙이기 어렵다는 고민이 나왔다. 시간을 넉넉히 주면 기다림이 길고 빠르게 처리하면 훅이 실패하며, 관련 맥락을 놓친 채 AI가 자체 추론으로 그럴듯하지만 불필요한 내용을 만드는 문제가 있다고 설명했다. 참여자는 각 업무의 고유성을 유지하면서 연관된 맥락은 연결하는 구조를 원했다. 다른 참여자가 큰 일기장 하나를 실시간 편집하는 방법을 제안했고, 질문자는 업무 범위가 넓어 프로젝트별로 나누지 않는 상황에서 비슷한 개념을 실험 중이며 업무 후 분석할 예정이라고 밝혔다.

  • 관련 정보를 직접 읽으러 가는 방식과 관련성이 감지되면 자동으로 밀어주는 방식 모두를 고민했다.
  • 점심 이야기에서 회의로 화제가 전환됐을 때 과거 프로젝트와의 관련성을 자연스럽게 떠올려 주는 상황을 예시로 들었다.
  • 연결이 실패하면 AI 자체 추론이 틀린 말은 아니어도 맥락 없는 슬롭이 될 수 있다는 우려가 나왔다.
  • 개별 업무의 고유성을 유지하면서도 관련 업무를 융합하는 구조가 목표로 제시됐다.
  • 큰 일기장을 실시간 편집하자는 제안에 대해 유사한 방식을 이미 시험 중이며 하루 업무가 끝나면 분석해 보겠다고 답했다.

  • NP-Complete와 나비에-스토크스 문제를 현실 상황 및 고양이에 빗대는 농담이 이어졌다.
