지피탁구 신기함/RAG 구조 화제

방 사람들이 대화를 기억하는 지피탁구(탁구)의 성능에 놀랐다는 반응이 이어졌다. 탁구 운영자가 구조를 공개했는데, 고정 지침이나 메모리 대신 벡터DB 기반 RAG 파이프라인으로 대화를 임베딩해 필요할 때 가져다 쓰는 방식이라고 설명했다. 매번 컨텍스트가 깡통인 상태에서 API 호출로 작동하며, 컨텍스트가 커질수록 메모리는 오염 위험이 있어 관리하지 않는다고 밝혔다. 웹서치 대신 퍼플렉시티(OAuth 방식)와 RAG를 병렬로 붙여 토큰 사용량을 크게 줄였다는 팁도 공유됐다.

  • 고정 지침·누적 메모리 없이 벡터DB+RAG로 운영
  • 요약 시마다 임베딩 재생성
  • 매 호출이 깡통 컨텍스트, 방이 커질수록 메모리 관리 포기
  • 퍼플렉시티(OAuth)와 RAG 병렬 사용으로 토큰 절감
  • 기존 데이터를 그대로 RAG하기보다 데이터 전처리가 핵심이라는 노하우 공유
