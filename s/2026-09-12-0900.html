멀티모델 연결 구조(codex-bridge)

여러 모델을 물려 쓸 때 API 방식인지 세션+OAuth 방식인지 질문이 나왔고, 프론트매터(Md)에 모델을 지정하면 서브에이전트가 해당 모델로 동작한다는 팁이 공유됐다. 이어 실제 구조는 API도 MCP도 아닌 '자식 프로세스 실행' 방식으로, 클로드가 codex.exe를 셸에서 띄우고 파일로 주고받으며 OAuth는 그 바이너리 자체 로그인이라 무관하다는 상세 설명이 나왔다. 소넷 코드브릿지 서브에이전트를 상주시켜 필요시 코덱스에 던지고 결과만 받는 구조가 효율적이라는 비유(고객사 상주 인력 던져놓고 결과만 받기)로 정리됐다.

  • 프론트매터에 모델 지정하면 서브에이전트가 그 모델로 동작
  • 실제 구조는 API/MCP가 아닌 자식 프로세스(codex.exe) 실행 + 파일 입출력
  • OAuth는 codex.exe 자체 ChatGPT 로그인이라 메인 파이프라인과 무관
  • 소넷 코드브릿지를 미리 상주시켜 필요시 결과만 받는 방식이 효율적이라는 비유 제시
  • 2시간짜리 작업을 직접 돌려보면 체감이 크다는 조언
