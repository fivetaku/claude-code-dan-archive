Claude 장애 반복

Claude 웹·API·Code·Cowork 전반에서 여러 차례 높은 오류율과 과부하가 발생했다. 일부 모델 장애는 조사, 원인 확인, 복구 관찰을 거쳐 복구 완료로 공지됐지만 이후 다른 모델에서도 재발했다. 사용자는 temporary overloaded 및 529 오류를 경험했고, API 호출이 서버를 붙잡는 경우 타임아웃·재시도·요청 집중도를 점검하라는 안내가 나왔다.

  • Claude 서비스 전반에서 심각하거나 큰 영향 수준의 오류 공지가 반복됐다.
  • 초기 장애는 일부 모델의 오류율 증가로 시작해 복구 완료 공지까지 이어졌다.
  • 복구 이후에도 Opus 및 기타 모델에서 추가 과부하 공지가 발생했다.
  • 사용자 측에서는 temporary overloaded 및 HTTP 529 과부하 오류가 보고됐다.
  • 연동 서비스 문제를 볼 때 API 응답 지연, 타임아웃, 재시도 정책, 동시 요청량을 우선 확인하라는 조언이 나왔다.

Claude 사용량 절약

Claude 데이터·사용량을 효율적으로 쓰는 방법을 정리했다. 대화가 길어지면 새 세션으로 전환하고, 요청을 구체적으로 작성하며, 관련 파일만 제공하라는 팁이 제시됐다. 단순 작업에는 가벼운 모델을 쓰고 복잡한 설계·디버깅에만 큰 모델을 배정하며, 규칙 파일도 짧게 유지하는 방식이 권장됐다.

  • 긴 세션은 이전 맥락을 반복해서 읽으므로 새 세션 전환이 사용량 절약에 도움이 된다.
  • 요청을 한 번에 구체적으로 작성해 불필요한 왕복을 줄여야 한다.
  • 레포지토리 전체 대신 작업과 직접 관련된 파일·부분만 제공해야 한다.
  • 난도에 따라 경량 모델과 고성능 모델을 분리해 사용해야 한다.
  • 매 세션에 읽히는 규칙 파일은 간결하게 유지해야 한다.

맥미니 서버 램 선택

개인 서버와 개발용 맥미니, 미니PC의 메모리 용량 및 구매 방향을 논의했다. 대체로 예산 안에서 가능한 최대 메모리를 선택하되 CPU보다 RAM 우선이라는 의견이 나왔다. AI 비서·로컬 모델·TTS·RAG 라벨링 등의 구체적 목표를 먼저 정하고, 입문 단계에서는 VPS로 시험한 뒤 장비 구매를 결정하라는 조언도 제시됐다. DDR4 32GB를 보유한 상황에서 8코어 16스레드, SSD 512GB, 50만원 이하 미니PC 후보를 찾는 요청도 이어졌다.

  • 개인 서버·개발·AI 비서 용도라면 메모리를 예산 내 최대치로 확보하라는 의견이 많았다.
  • CPU보다 RAM을 우선시하라는 조언이 나왔다.
  • N100 기반 시스템은 DDR4 중고 부품을 활용하면 비용을 낮출 수 있다는 의견이 제시됐다.
  • 무엇을 자동화하고 로컬에서 어떤 모델을 돌릴지 구체화한 뒤 구매해야 한다는 지적이 있었다.
  • 장비 구매 전 VPS에서 먼저 사용성을 검증하는 대안이 언급됐다.
