로컬 LLM용 맥 사양 논쟁

맥미니 32GB로 로컬 AI에 한계를 느낀 참여자가 M5 Pro 48GB와 M5 Max 36GB 중 무엇이 나은지 물었다. Qwen4가 나오면 27B를 돌릴 계획이었다. 다른 참여자들은 48GB에 27B는 무겁고 헤르메스까지 함께 띄우면 세션이 늘 때 감당이 안 된다고 했다. 4비트 양자화에 KV캐시 8비트 압축으로 256k까지 가능하다는 반론에는 속도가 너무 느려 쓰기 힘들 거라는 반응이 이어졌다. 질문자는 헤르메스가 메인이 아닌 보조용이라고 했고, 반응을 보고 구매를 재고하겠다고 했다.

  • 질문 배경: 맥미니 32GB에서 로컬 AI 한계를 느껴 M5 Pro 48GB와 M5 Max 36GB 가격 비교, Qwen4 27B 구동이 목표.
  • '48GB에 27B는 무겁다', '만족 못 할 것 같다'는 반응이 다수였고, 헤르메스를 같이 띄우면 세션이 늘수록 감당이 어렵다는 지적이 나왔다.
  • 4비트 모델에 KV캐시 8비트 압축으로 256k를 노린다는 계획에는 느려서 스트레스가 늘 거라는 의견이 나왔다. 프론티어 모델도 느려서 답답하다는 말도 있었다.
  • 한 참여자는 모델을 정해놓고 사기보다 예산 내 최고 스펙을 사는 편이 낫다고 했다. 128GB는 1000만원 가까이 든다는 이야기도 나왔다.
  • 일부는 직접 해보고 돈을 날려봐야 다음에 어떻게 할지 안다고 했다. 현재 확인된 Qwen4는 플래그십 Qwen4-Max뿐이라 27B는 아직 나오지 않은 상태다.

500만원 맥 구매 조언

투자 리서치와 엑셀 자동화 같은 텍스트 작업용으로 500만원선 맥 구매 조언을 구했다. 맥북을 예산에 맞게 사고 남은 돈은 OpenRouter와 LLM 구독에 쓰라는 의견이 나왔다. 진짜 무거운 작업이 아니면 RAM 위주로 고르고 500까지는 필요 없다는 얘기도 있었다. 쿠팡에서 M5 Pro 48GB 1TB가 470만원 선이라는 정보가 공유됐다. 맥네오는 가격 대비 비추천이라는 반응이 있었다.

  • 용도는 영상 작업 없는 투자 리서치와 엑셀 업무 자동화 등 텍스트 기반 작업이다.
  • 맥북을 예산에 맞게 사고 남은 돈을 OpenRouter나 LLM 구독에 쓰는 안이 지지를 받았다.
  • 진짜 하드한 작업이 아니면 RAM을 높이는 쪽이 낫고 500만원까지는 굳이 필요 없다는 의견이 나왔다. 쿠팡 M5 Pro 48GB 1TB가 470만원 선이라는 정보도 공유됐다.
  • LLM을 돌리는 컴퓨터는 노트북보다 데스크형이 낫다는 의견과, 에이전트 창구용 하드웨어를 따로 두고 거기로 일을 시키는 구상이 나왔다.
  • 맥네오는 반대 의견이 있었고, 맥스튜디오와 맥에어 조합을 권하는 의견도 있었다. 맥네오는 맥북 네오(99만원대)일 수도, 인디 앱 사이트일 수도 있어 확실하지 않다.

클로드 계정 2개 세션 공유

한 컴퓨터에서 Claude 계정 2개를 쓰면서 세션을 공유하는 방법을 물었다. 계정 분리는 CLAUDE_CONFIG_DIR 환경변수로 하고, 세션 공유는 projects 폴더를 심볼릭 링크로 연결하는 방식이 안내됐다. 환경변수 방식은 공식 지원이지만 심볼릭 링크는 AI 요약 기준이라 근거가 약하다. 자동 전환 프록시 툴은 약관 위반 소지가 있다는 경고도 있었다.

  • 계정마다 설정 폴더를 따로 만든다 (예: ~/.claude-acc1, ~/.claude-acc2).
  • CLAUDE_CONFIG_DIR=해당 폴더 claude 로 실행해 각각 로그인한다.
  • 대화 기록은 폴더 안 projects에 저장되므로 한쪽 projects를 다른 쪽에 심볼릭 링크로 걸면 공유된다는 안내가 있었으나 근거는 약하다.
  • 매번 입력하기 번거로우면 셸 함수로 묶어 쓰고, 환경변수 방식 자체는 공식 지원 기능이라고 했다.
  • 자동 전환 프록시 툴은 약관 위반 소지가 있다고 했다.

그록봇 vs 클로드 듀엣

그록봇을 잘 쓰고 있다는 참여자들이 커서의 요즘 상황을 물었다. 클로드 듀엣이 Opus 5.5 기반이라 들었는데 Grok 4.7이 밀리는 것 아니냐, 듀엣이 그록봇에 어떤 모델을 쓰든 압도하는 것 아니냐는 질문이 이어졌다. 방에서 이에 대한 답은 나오지 않았다. 확인된 정보로 그록봇은 자체 호스팅 AI 에이전트 게이트웨이이고, 클로드 듀엣은 2026년 10월 공개된 선제형 모바일 에이전트 앱이다.

  • 그록봇은 여러 채널에서 AI 코딩 에이전트와 연결해 연구·코딩·배포 업무를 맡기는 자체 호스팅형 게이트웨이다.
  • 클로드 듀엣은 아침 업무 요약, 메일·일정 확인, 답장·자료 준비를 먼저 챙겨 주는 앱이다. 최근 Claude Code 세션을 폰에서 확인·승인하는 연동이 추가됐다.
  • 질문자는 듀엣이 Opus 5.5 기반이라는 점을 근거로 그록봇과의 성능 우열을 물었다.
  • 방 안에서 이 질문에 대한 직접적인 답이나 결론은 나오지 않았다.
  • 별도로 커서의 요즘 평가를 묻는 질문도 있었으나 답은 없었다.

AgentsRoom 링크가 공유되며 대화방에서 나온 사용 후기가 있는지 물었다. 홈페이지 기준으로는 Claude Code, Codex, Cursor 등 여러 AI 코딩 에이전트를 한 화면에서 같이 돌리는 데스크톱 앱이다. 에이전트마다 역할을 주고 서로 메시지나 티켓을 주고받게 하는 구조이며, 이미 결제 중인 요금제를 그대로 쓸 수 있다고 한다. 방 안에서 확인된 사용 후기는 없었다.

  • 여러 코딩 에이전트를 한 화면에서 동시에 운영하는 데스크톱 앱이다.
  • 에이전트별 역할 부여와 에이전트 간 메시지·티켓 교환 구조를 갖췄다.
  • 이미 결제 중인 요금제를 그대로 쓸 수 있다고 소개된다.
  • 대화방에서 나온 사용 후기는 확인되지 않았다.

Sol 버전 차이·Orca 전환

Sol 6.1과 6.2의 성능 차이가 큰지 묻는 질문이 올라왔으나 방에서 답은 없었다. 이어서 orca로 변경했다는 한 줄이 올라왔다. Sol은 Claude Code에서 Claude가 설계·검토하고 OpenAI Codex CLI가 코드를 작성하게 연결하는 멀티모델 플러그인으로 소개된다. Orca는 Claude Code, Codex 등 여러 에이전트를 한 화면에서 병렬로 돌리는 무료 오픈소스 개발 환경이다. 두 도구 모두 확인 내용은 미검수 상태다.

  • Sol 6.1과 6.2의 성능 차이에 대한 질문은 답 없이 지나갔다.
  • Sol은 Claude가 설계·검토를, Codex CLI가 실제 코드 작성을 맡는 플러그인이다 (미검수).
  • Orca는 여러 AI 코딩 에이전트를 병렬 실행·관리하는 무료 오픈소스 ADE다 (미검수).
  • 한 참여자가 orca로 갈아탔다고 밝혔고 이유는 나오지 않았다.

LLM 분석기 네이밍 지적
