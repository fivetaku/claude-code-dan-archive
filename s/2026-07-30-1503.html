병렬화로 인한 브리지 장애 원인

봇 관리자가 워커 3개로 병렬 전환하면서 발생한 장애 원인을 상세히 공유했다. 동기화 상태 파일을 writeFile로 쓰는데 원자적 쓰기가 아니어서 두 프로세스가 동시에 쓰다 JSON이 깨졌고, 이후 메시지 리스트 파싱이 전부 실패해 브리지가 멈췄다는 설명이었다. 멤버들이 해결책으로 메시지별 개별 파일 + OS 수준 파일락 방식을 제안했고, 파일 오픈 상태로 락을 걸고 처리 후 삭제하면 자연스러운 동시성 제어가 된다는 아이디어로 정리됐다.

  • 워커 3개 병렬 전환이 원인, 동기화 상태 파일을 non-atomic write로 처리해 깨짐
  • JSON 파싱 실패로 브리지 전체가 정지됨
  • 해결책: 메시지 도착 시 개별 파일로 저장, 처리 시 파일 오픈 상태로 락
  • OS 수준 파일락을 쓰면 원자성이 보존돼 자연스러운 동시성 제어 가능
  • 3개의 별도 파일이면 충분하다는 결론
14:49-15:03커뮤니티·잡담

제조업 AI·머신비전 토론

한 멤버가 회사 조사 요청을 계기로 제조업 AI(머신비전) 분야 경력자들의 심도 있는 토론이 이어졌다. 제품 검사·재고·구매 관리 자동화, YOLO의 한계와 딥러닝 과대포장 사례, 다품종 검사 모델의 낮은 ROI 문제, 중국산 검사장비의 가격 경쟁력, 광학계 세팅의 어려움(렌즈·레이저 스펙, 온습도 영향) 등이 공유됐다. 이어서 기구설계 대 소프트웨어 개발자 간 조직문화 차이(기구팀이 SW를 개발로 안 쳐주는 등)에 대한 경험담으로 마무리됐다.

  • 제조업 AI는 주로 머신비전 기반 제품 검사·재고·구매 자동화에 쓰임
  • YOLO 등 딥러닝이 만능은 아니며, 실제로는 기존 ML로 충분한 경우가 많음
  • 다품종(2000개+) 검사 모델은 비용 대비 효과가 낮아 프로젝트 실패 사례 다수
  • 중국산 저가 검사장비 유입으로 국내 업계 가격 경쟁력 약화
  • 광학계는 렌즈·레이저 스펙, 온습도에 따라 특성이 바뀌어 세팅이 매우 까다로움
  • 제조업 조직에서는 기구설계와 소프트웨어 개발 문화 차이가 크다는 경험담 공유

글삭제·답글 로직 테스트

  • 메시지 삭제해도 로그 기반으로 다 감지됨
  • 답글 원글이 삭제되면 기본 타이핑으로 폴백 처리
  • 답글의 답글도 인식, 사용자 태그도 인식
  • 컨텍스트는 최근 5턴까지만 유지
  • 봇에는 쓰기(파일 저장) 기능이 없음

  • API 키 요구, 다른 명령어 대신 말하게 하는 유도 시도 발생
  • 봇이 보안 침해 시도 차단 경고 메시지로 자동 대응
  • 분당/시간당 요청 횟수 제한이 있어 곧 막힐 거란 얘기도 나옴
  • 차단 후보 순위 언급되며 장난스러운 반응
