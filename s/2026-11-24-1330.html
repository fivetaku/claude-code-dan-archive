AWS 자격증명 보안

AWS 장애나 보안 사고가 사용자 보안 설정 문제인지에 대한 논의가 오갔다. AWS 인프라 보안이 허술하다고 단정하기보다 액세스 키 노출, 과도한 권한, MFA와 결제 알림 미설정이 주요 위험으로 지적됐다. IAM 사용자와 롤을 용도별로 분리하고 장기 키 대신 임시 자격증명을 사용하는 것이 권장됐다. properties나 .env로 분리해도 평문 노출 위험이 있으므로 Secrets Manager, 환경변수, 롤 기반 주입과 함께 Git·로그·이미지·CI 로그를 점검해야 한다.

  • 액세스 키는 최소 권한으로 발급하고 용도별 IAM 사용자나 롤로 분리한다.
  • 가능하면 장기 액세스 키보다 롤과 임시 자격증명을 사용한다.
  • MFA와 예산 알림을 활성화해 키 유출과 비용 폭탄에 대비한다.
  • .env와 application.properties도 커밋·로그·빌드 이미지·CI 로그에서 노출되지 않는지 확인한다.

자바 BASE64 점검

자바 BASE64 관련 이슈가 언급되며 자프링으로 운영 중인 서버를 점검해야 하는지 질문이 나왔다. 정확한 CVE나 사건은 확인되지 않아 특정 취약점을 단정하지 않았다. 우선 JDK가 최신 보안 패치 상태인지 확인하고 Spring Boot, Spring Framework, Jackson, Tomcat 의존성의 취약점 공지를 점검하는 순서가 제안됐다. Dependabot, Gradle 의존성 목록, OWASP Dependency-Check를 활용하고 외부 입력의 Base64 디코딩 지점도 살펴보는 방향이다.

  • 정확한 이슈가 확인되지 않은 상태에서는 특정 CVE를 단정하지 않는다.
  • JDK 보안 패치와 Spring Boot·Spring Framework·Jackson·Tomcat 버전을 확인한다.
  • Dependabot, ./gradlew dependencies, OWASP Dependency-Check로 의존성을 점검한다.
  • 인증 토큰이나 업로드 파일 등 외부 입력을 Base64로 디코딩하는 코드를 검토한다.
