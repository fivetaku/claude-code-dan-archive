바이브코딩 학습법

코딩 기초가 많지 않은 대학생이 Claude와 Supabase, GitHub, Cron-job 서비스, Vercel 등을 써서 개인 운동 코치·DB를 만들고 있으며 앞으로의 학습 방향을 물었다. 답변은 원하는 것을 계속 만들어 보고, 막히거나 문제가 생긴 지점을 구체적으로 질문하는 방식이 좋다는 것이었다. 손필기 운동 기록 전사 과정의 오타와 정확도 문제도 함께 논의됐다.

  • 개인 운동 코치와 데이터베이스를 바이브 코딩으로 만든 사례가 소개됐다.
  • 기초 학습은 프로젝트를 진행하며 문제를 해결하는 방식으로 권장됐다.
  • 손필기 기록을 사진으로 전사할 때 정확도를 높이는 방법이 추가 질문으로 나왔다.
  • OCR에는 여러 모델을 시험하고 자주 쓰는 단어를 프롬프트에 넣는 방법이 제안됐다.

세션 문맥 유지

새 세션마다 기획안용 MD를 업데이트하고 다시 읽히는 과정이 번거롭다는 고민이 제기됐다. `/resume` 사용 가능성이 제안됐고, 이전 세션 맥락을 새 세션에서도 질의할 수 있게 해 주는 claude-mem 저장소가 공유됐다. agy를 사용하면 일부 자동화가 가능하다는 의견도 나왔다.

  • 수동 MD 갱신과 새 세션 문맥 복구의 번거로움이 문제로 제기됐다.
  • `/resume`으로 이전 작업을 이어갈 수 있다는 제안이 나왔다.
  • claude-mem을 사용하면 새 세션에서 이전 진행 상황을 바로 물을 수 있다고 소개됐다.
  • agy로 일정 수준의 자동화를 할 수 있다는 경험이 공유됐다.
  • https://github.com/thedotmack/claude-mem

손글씨 OCR 개선

손필기 운동 기록을 전사할 때 오타가 많아 정확도를 높이고 싶다는 질문이 나왔다. Gemini 등 성능 좋은 OCR 모델과 OCR 전용 모델을 비교해 보고, 반복적으로 나오는 단어를 프롬프트에 제공하라는 조언이 있었다. 개인 손글씨 특징을 별도로 학습시키는 방법은 본 사례를 보지 못했다는 답변이 나왔으며, PDF 잉크 주석 처리 예시가 담긴 코드 저장소도 공유됐다.

  • 손글씨 OCR은 여러 모델을 직접 비교해 보는 것이 권장됐다.
  • 반복 출현하는 운동 용어 등을 프롬프트에 넣으면 도움이 될 수 있다고 했다.
  • 개인 손글씨 자체를 학습하는 방식은 확인하지 못했다는 의견이 나왔다.
  • PDFBox의 InkAnnotationMarkup 객체와 관련 코드 저장소가 참고 자료로 제시됐다.
  • https://github.com/Seung-zedd/cubrain

PC방 정리매물 판단

  • PC방 점포정리 매물의 가격 적정성이 질문됐다.
  • 부품 제조사·모델명·상세 사양 미기재 매물은 피하라는 조언이 나왔다.
  • CPU와 메모리 구성은 PC방 용도로 아쉽다는 의견이 있었다.
  • 그래픽카드는 합격이라는 평가가 나왔다.

  • 모각코의 의미와 분위기를 처음 접한 참여자에게 설명했다.
  • 모임에서는 각자 작업하거나 자유롭게 대화할 수 있다고 했다.
  • 음료 한 잔을 기본으로 하고 나머지는 실비 부담이라는 안내가 나왔다.
