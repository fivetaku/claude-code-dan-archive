DevDay 발표 반응

OpenAI DevDay 발표를 보며 구독 사용량, 신규 모델, 에이전트 제품군에 대한 실시간 반응이 이어졌다. 발표의 큰 방향은 단순 질의응답형 AI에서 백그라운드로 계속 일하는 에이전트 중심으로 옮겨간다는 것으로 정리됐다. Dots, GPT-6.1 Sol, Space, 초고속 추론, Decisions API, Agents API, Codex Cloud, 고가 Pro 플랜 등이 주요 항목으로 언급됐다. 라이브 데모가 버벅였지만 대부분 기능을 빠르게 열겠다는 발표 내용도 공유됐다.

  • 발표 직후 구독별 사용량과 혜택이 계속 바뀌는 양상이라는 반응이 나왔다.
  • 새 기능 다수가 에이전트의 지속 실행과 클라우드 작업 환경을 중심으로 소개됐다.
  • Pro 500 등 고가 구독제가 실제 가성비를 가질지 지켜봐야 한다는 의견이 있었다.
  • 라이브 데모 지연은 여러 업데이트를 한 번에 적용한 영향이라는 설명이 공유됐다.
  • https://x.com/thsottiaux/status/2104981170685616361

Dots와 Astra 혜택

Dots가 Pro 및 일부 비즈니스·엔터프라이즈 플랜에 포함되고, Astra 관련 사용량이 차감되지 않는다는 발표 내용이 화제가 됐다. Dots는 24시간 작업 후 Astra로 전환되며, 추후 여러 팀 단위 구성도 지원할 예정이라는 요약이 공유됐다. Muse나 다른 봇이 Astra로 구동되면서도 사용량을 쓰지 않는다는 설명이 뒤이어 나왔다. 음성 중심 사용 방식이라 사무실에서 쓰기 어려울 수 있다는 실사용 관점의 우려도 있었다.

  • Dots는 Pro, Business Premium, Enterprise 및 Pro 100에도 포함된다고 언급됐다.
  • 작업을 장시간 수행한 뒤 Astra로 전환되는 구조로 소개됐다.
  • Astra 구동 기능이 별도 사용량을 차감하지 않는다는 설명이 공유됐다.
  • 음성으로 말하며 사용하는 흐름이 핵심처럼 보여 사무실 사용성 우려가 나왔다.

GPT-6.1 Sol 가격

GPT-6.1 Sol은 Astra급 성능을 더 낮은 가격으로 제공하는 모델로 소개됐다. 캐시 읽기 할인과 Ultrafast 결합 시 속도 향상도 함께 언급됐다. 이후 실제 워커 모델로 쓸 때 기존 Sonnet이나 Opus 계열과 비교해 굳이 선택할 이유가 있는지 논의가 이어졌다. 참가자들은 가격은 싸 보이지만 워커 용도에서는 기존 모델이 이미 대안이라는 신중한 반응을 보였다.

  • 캐시 읽기 비용이 크게 할인돼 반복 작업 비용을 낮출 수 있다고 소개됐다.
  • Ultrafast와 결합하면 최대 8배 빠른 속도를 내세웠다.
  • 유료 플랜과 API에 즉시 포함된다는 내용이 공유됐다.
  • 실제 워커 작업에서는 Sonnet·Opus 계열과의 선택 기준이 더 중요하다는 의견이 나왔다.
02:35-05:23워크플로우·방법론

Space 협업 문서

ChatGPT Space가 사람과 Dots가 함께 리치 노트를 편집하는 협업 공간으로 소개됐다. 할 일 위임, 제품 계획, 회의록 작성과 실시간 시각화를 지원하며 최신 상태를 백그라운드에서 맞춘다는 설명이 나왔다. 개발 측면에서는 AGENTS.md 기반 작업 방식을 더 확장한 개념으로 해석됐다. Space를 더 자세히 볼 수 있는 관련 스레드가 언급됐다.

  • 협업 문서에서 사람과 에이전트가 함께 작업하는 용도로 소개됐다.
  • TODO 위임, 제품 기획, 회의록 등 다양한 업무 흐름을 대상으로 한다.
  • 실시간 시각화와 백그라운드 최신 상태 동기화가 특징으로 언급됐다.
  • 개발자용 에이전트 작업 규칙을 더 확장하는 흐름으로 평가됐다.

실시간·에이전트 API

Luna 기반 Decisions API는 제약 조건이 있는 결정을 수백 밀리초 안에 내리는 실시간용 API로 소개됐다. 시각 입력도 받을 수 있으며 처음부터 끝까지 짧은 지연 시간에 맞춘 것으로 설명됐다. Responses API는 전년 대비 트래픽이 100배 증가했고 99.9% 업타임을 내세웠다. Agents API는 Dots와 유사한 기술 기반으로 컴퓨터 사용을 포함해 직접 에이전트를 만들 수 있는 프리뷰로 언급됐다.

  • Decisions API는 빠른 실시간 판단이 필요한 시나리오를 대상으로 소개됐다.
  • 시각 입력을 지원하며 수백 밀리초 수준의 처리 시간을 목표로 한다.
  • Responses API는 트래픽 증가와 안정성 개선 수치를 발표했다.
  • Agents API는 컴퓨터 사용 기능을 갖춘 에이전트 구현 수단으로 언급됐다.

Codex Cloud 변화

로컬 노트북에서 돌리는 Codex보다 클라우드 환경이 중심이 되는 방향이 소개됐다. 사용자가 클라우드 작업 환경을 맞춤 설정해 두면 로컬 중심 작업 방식으로 돌아가기 어렵다는 평가가 나왔다. 엔터프라이즈 Codex에는 GLM-5.3 Flash와 Kimi K3 같은 오픈 모델을 네이티브로 붙이고 기존 OpenAI 커밋에서 비용을 차감하는 방식도 언급됐다. Codex 사용량 초기화 여부에 대한 질문에는 이번에는 초기화가 아니라 쿠폰 제공일 가능성이 있다는 추측이 나왔다.

  • Codex Cloud가 개선돼 클라우드 작업 환경을 중심으로 재소개됐다.
  • 사용자 맞춤형 클라우드 환경을 계속 유지하는 흐름이 강조됐다.
  • 엔터프라이즈에서는 오픈 모델을 Codex 내부에서 바로 쓸 수 있다는 내용이 공유됐다.
  • 사용량 리셋 대신 쿠폰이 제공될 수 있다는 추측이 제기됐다.

ChatGPT 앱 배포

개발자가 네이티브 앱과 플러그인을 ChatGPT 안에서 출시할 수 있게 됐다는 발표가 공유됐다. 대화 맥락에 맞는 플러그인을 사용자에게 노출해 ChatGPT 자체를 배포 채널로 활용하는 구상이다. 플러그인 발견 기능이 사용자 수와 채택을 크게 늘릴 수 있다는 차트 기반 해석도 나왔다. 제품을 만든다면 ChatGPT 플러그인으로 발견되도록 준비하는 것이 중요하다는 의견으로 이어졌다.

  • 플러그인 확장을 갖춘 네이티브 앱을 ChatGPT 안에 출시할 수 있다고 소개됐다.
  • 대화 맥락에서 관련 앱을 띄워 주는 발견 방식이 핵심으로 언급됐다.
  • 플러그인 노출 이후 사용자 수가 크게 증가한 차트가 공유됐다고 전해졌다.
  • 개발자는 제품 배포와 채택 확대를 위해 플러그인 발견성을 고려해야 한다는 의견이 나왔다.

구독 연동 확대

ChatGPT 구독 사용량을 여러 파트너 서비스에서 공통으로 쓰게 하는 연동 확대 소식이 공유됐다. ChatGPT로 로그인하면 별도 복잡한 규칙 없이 파트너 도구를 쓸 수 있다는 설명이었다. 언급된 서비스에는 Devin, OpenCode, Notion이 포함됐다.

  • ChatGPT 구독이 16곳 이상의 파트너와 연동된다고 언급됐다.
  • 구독에 포함된 사용량을 파트너 서비스에서도 활용하는 구조로 소개됐다.
  • Devin, OpenCode, Notion이 예시로 언급됐다.

모델 구독 조합 고민

GPT와 Claude의 구독 단계를 각각 낮춰 둘 다 사용하는 조합이 효율적인지 질문이 나왔다. 현재 높은 단계의 단일 구독을 유지할지, 낮은 단계 두 개로 나눌지 비용 대비 효율을 고민하는 흐름이었다. 답변에서는 상위 단계와 하위 단계의 가격 차이가 크지 않을 수 있으므로 실제 가격을 확인해 보라는 조언이 나왔다.

  • GPT와 Claude를 각각 낮은 구독 단계로 병행하는 방안이 제안됐다.
  • 현재 높은 구독 단계를 유지하는 선택지와 비교가 이뤄졌다.
  • 구독 단계별 실질 가격 차이를 먼저 확인하라는 조언이 나왔다.

Muse 국내 사용 여부

  • Muse의 데스크톱 앱 사용성이 좋다는 반응이 나왔다.
  • 한국에서 즉시 이용 가능한지 질문이 제기됐다.
  • 국내 사용 사례가 언급됐지만 접근 조건은 명확히 정리되지 않았다.
