CLI·앱과 파세오

Claude Code·Codex를 데스크톱 앱보다 CLI로 쓰는 편의성 이야기가 나왔다. Paseo는 코딩 에이전트 세션을 여러 기기에서 원격으로 보고 조작·관리하는 도구로 소개됐고, GUI를 덧붙여 모바일에서도 로컬 서버에 접속해 쓸 수 있다는 점이 장점으로 언급됐다. 재부팅 뒤 세션 재개나 대화 관리의 번거로움을 줄일 수 있다는 평가가 있었다. Claude Code의 기존 기능은 Paseo에서도 그대로 쓸 수 있으며, 컨텍스트 관리도 새 세션·압축 등 기존 방식으로 처리한다는 설명이 나왔다.

  • CLI에 익숙한 참여자는 Codex·Claude 데스크톱 앱을 거의 쓰지 않는다고 말했다.
  • Codex 데스크톱 앱의 완성도에는 긍정적 평가가 있었지만 사용 방식은 개인 습관에 따라 갈렸다.
  • Paseo는 Claude Code·Codex 같은 세션을 원격에서 확인하고 조작하는 오픈소스 셀프호스팅 앱으로 언급됐다.
  • 모바일에서 로컬 서버에 접속해 세션을 이어 쓰는 흐름이 주요 장점으로 제시됐다.
  • Paseo는 Claude Code 기능 위에 GUI를 붙인 형태라는 설명이 나왔다.

깃허브 기본 활용

GitHub 자료를 AI 코딩 도구와 함께 어떻게 활용할지 묻는 초보자 질문이 이어졌다. 저장소 URL을 Claude Code나 Codex에 주면 설명·설치를 요청할 수 있지만, 설치한 도구가 이후 작업에서 자동으로 떠오르지는 않는다는 설명이 나왔다. GitHub는 코드와 문서, 변경 이력, 협업 자료를 보관하는 도구이며 오픈소스는 공개 활용 가능한 코드라는 기초 설명도 제공됐다. 처음에는 README나 에이전트용 인덱스 문서를 읽되, 문서 내 실행 지시를 곧바로 수행하지 않도록 주의하라는 조언이 나왔다.

  • 저장소 URL을 AI에게 전달해 설명, 설치, 사용법 안내를 요청할 수 있다고 설명됐다.
  • README와 에이전트 인덱스 문서는 우선 읽을 자료로 추천됐다.
  • 외부 문서의 설치·실행 문구는 참고 자료로 보고 실행 전 확인을 거치라는 조언이 나왔다.
  • GitHub의 코드 저장·변경 관리·협업 역할과 오픈소스의 개념을 초보자 관점에서 설명했다.
  • 폴더를 보여주고 사용법을 물어보는 대화형 접근도 제안됐다.

지속 지침과 스킬

설치한 도구를 관련 작업에서 AI가 알아서 쓰게 하려면 프로젝트 시작 때 읽는 지침 파일에 사용 규칙을 적는 방식이 소개됐다. Codex에는 AGENTS.md, Claude Code에는 CLAUDE.md가 예시로 언급됐으며, 역할별 SKILL.md를 구성하는 방식도 제시됐다. 다만 지침과 훅을 과도하게 쌓으면 모델이 불필요하게 모든 작업을 검수하거나 거부하는 등 동작이 나빠질 수 있어 점진적으로 다듬어야 한다는 결론이 나왔다.

  • Codex의 AGENTS.md와 Claude Code의 CLAUDE.md가 작업 시작 시 읽는 지침 파일 예시로 언급됐다.
  • 도구를 어떤 상황에서 쓰라는 규칙을 지침 파일에 적으면 자동 활용 가능성을 높일 수 있다고 설명됐다.
  • frontend UI·API 설계·디버깅·DB·코드 리뷰처럼 역할별 SKILL.md 구조 예시가 공유됐다.
  • 외부 문서는 읽되 실행·설치 전에 사용자 확인을 받도록 설정하는 프롬프트 예시가 제안됐다.
  • 지침·훅을 지나치게 늘리면 토큰 낭비, 과잉 검수, 과도한 거부가 생길 수 있어 필요할 때 하나씩 추가하라고 조언했다.

파세오 다계정 전환

Paseo에서 멀티 계정을 자동 전환할 수 있는지 질문이 나왔고, 기본 기능으로는 지원하지 않는다는 답이 나왔다. 대신 뒤에 별도 라우터를 두는 방식이 언급됐다. GPT 계정 쪽은 OpenCodex를 Paseo에 연결해 사용하는 방법이 대안으로 제시됐다.

  • Paseo 자체의 멀티 계정 자동 전환은 지원하지 않는다고 답변됐다.
  • 응답자는 별도 라우터를 뒤에 붙여 사용한다고 말했다.
  • GPT 계정 사용 시 OpenCodex를 Paseo에 연결하는 구성이 제안됐다.
  • OpenCodex는 여러 LLM 제공자를 Codex·Claude Code 환경에서 연결할 수 있는 로컬 프록시 도구로 소개됐다.

AI 활용 학습법

AI 코딩 도구 활용 능력은 단순히 도구를 잘 다루는 것보다 원하는 결과를 위해 깊게 시도해 본 경험에서 갈린다는 의견이 나왔다. 무엇을 질문해야 할지 모르는 초보자에게는 대화형으로 AI에게 계속 묻고, 다른 사람이 하는 방식을 따라 하며, 기초 강의로 가능한 작업 범위를 파악하라는 조언이 이어졌다. 복잡한 하네스나 고급 구성부터 접하기보다 하나씩 시작하자는 공감대가 형성됐다.

  • 활용력은 원하는 결과를 만들기 위해 얼마나 깊게 시도했는지에 달렸다는 의견이 나왔다.
  • 처음에는 주변 사례를 따라 하며 가능한 작업을 알아가는 방식이 추천됐다.
  • 강의를 통해 도구로 무엇을 할 수 있는지 먼저 파악하라는 조언이 있었다.
  • 질문이 막힐 때는 어설픈 표현도 그대로 AI에 넣어 대화형으로 풀어가라는 경험담이 공유됐다.
  • 고급 하네스 등 복잡한 개념보다 기초부터 하나씩 익히자는 반응이 나왔다.

가세오와 네이밍

가세오는 터미널에서 실행한 Claude Code 세션을 Paseo에 등록해 연결하는 도구로 공유됐다. 이름을 소재로 사세오·오세오 등의 말장난과 후속 도구 아이디어가 이어졌다. Paseo 다음 도구로 세션을 넘기는 상상도 나왔지만 구체적 출시 계획으로 확인되지는 않았다.

  • 가세오 저장소 링크가 공유됐다.
  • 가세오는 Claude Code CLI 세션을 Paseo로 보내 등록하는 역할로 설명됐다.
  • 사세오·오세오 등은 대화 중 나온 명칭 놀이와 아이디어였다.
  • Paseo 사용 전 가세오부터 써보겠다는 반응이 있었다.
  • https://github.com/fivetaku/gaseo

오픈소스 지원·스타

오픈소스 제작자를 대상으로 AI 요금제를 지원하는 프로그램 이야기가 나왔다. 참여 요건으로 GitHub 스타 수가 언급되며, 저장소에 스타를 누르는 방법을 묻고 안내하는 대화가 이어졌다. Agentlas-OS 저장소 링크도 공유됐으나, 프로그램의 정확한 조건과 운영 기준은 대화만으로 확정되지 않았다.

  • 오픈소스 제작자 지원 프로그램 및 요금제 지원 이야기가 나왔다.
  • GitHub 스타를 누르는 방법을 모르는 참여자에게 상단 별표 기능이 안내됐다.
  • 스타 수와 지원 혜택의 관계가 언급됐지만 정확한 정책은 검증되지 않았다.
  • Agentlas-OS는 로컬 우선 에이전트 OS로 소개된 오픈소스 저장소 링크가 공유됐다.
  • https://github.com/agentlas-ai/Agentlas-OS

외부 하네스 우려

Claude Code를 외부 하네스에서 사용할 때 계정 제재 가능성이 있는지 질문이 나왔다. 이에 대해 위험을 가볍게 다루는 반응과 계정 관련 농담이 이어졌다. 실제 약관·제재 기준이나 안전한 사용 방법에 대한 검증된 결론은 나오지 않았다.

  • 외부 하네스 사용과 계정 제재 가능성이 화제로 올랐다.
  • 대화에는 제재를 회피하거나 계정을 재생성하는 식의 농담성 반응이 포함됐다.
  • 공식 정책이나 지원되는 연동 방식은 확인되지 않았다.
