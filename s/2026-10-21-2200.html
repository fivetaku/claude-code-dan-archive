Aside와 ego lite 비교

Aside와 ego lite의 차이와 캡처 방식 여부가 질문됐다. Aside는 로그인된 웹사이트에서 직접 작업하는 AI 에이전트 브라우저로, ego lite는 Claude Code·Codex 같은 기존 에이전트가 로그인된 브라우저 세션을 이어받아 자동화하도록 돕는 오픈소스 브라우저로 설명됐다. 둘은 대체재라기보다 브라우저 내장형 사용과 기존 에이전트 연동이라는 층위가 달라, 현재 Aside가 불편하지 않다면 유지하고 필요할 때 ego lite를 추가하는 방식이 제안됐다.

  • Aside는 로그인된 웹사이트에서 조사·메시지·결제·스크린샷 등의 작업을 수행하는 AI 에이전트 브라우저다.
  • Aside는 CLI 명령으로도 작업을 요청할 수 있다고 소개됐다.
  • ego lite는 기존 AI 코딩 에이전트가 로그인된 브라우저 세션을 이어받아 자동화하도록 만든 오픈소스 크로미움 기반 브라우저다.
  • 현재 Aside에 불편이 없다면 바로 교체하기보다 필요할 때 ego lite를 추가하는 접근이 제안됐다.

OpenGCUA와 AppleScript 비교

텍스트 저장과 일정 읽기 작업에서 OpenGCUA와 AppleScript의 실행 시간이 비교됐다. OpenGCUA는 텍스트 저장 약 32초, 일정 읽기 약 29초였고 AppleScript는 각각 약 4초, 7~9초로 같은 결과를 더 빠르게 냈다. 두 방식 모두 결국 AppleScript를 사용하며 차이는 모델 왕복 횟수라는 분석과 함께, 단순 작업은 직접 AppleScript로 작성하는 편이 낫다는 결론이 공유됐다.

  • 텍스트 저장 테스트에서 OpenGCUA는 약 32초, AppleScript는 약 4초가 걸렸다.
  • 일정 읽기 테스트에서 OpenGCUA는 약 29초, AppleScript는 약 7~9초가 걸렸다.
  • 두 방식 모두 결과적으로 AppleScript를 사용했다.
  • 성능 차이는 모델 왕복 횟수에서 발생하는 것으로 분석됐다.
  • 단순하고 정형화된 작업은 직접 스크립트를 작성하는 편이 효율적이라는 결론이 나왔다.

Claude Code 정기 자동화

서버에서 Claude Code로 매주 반복 작업을 실행할 때 cron에 claude -p를 걸지, 다른 방식을 쓸지 질문이 나왔다. 루틴이나 /schedule, 카카오톡·텔레그램·디스코드·슬랙 봇을 활용하는 방법이 제안됐고, 단순 자동화는 일반 스크립트가 더 적합할 수 있다는 의견도 나왔다. 연구 주제와 관련된 논문을 학회 사이트에서 찾아 저장·정리하는 작업이라면 이미 운영 중인 슬랙 봇이나 cron을 활용하면 된다는 방향으로 논의됐다.

  • 정기 실행 방식으로 cron, 루틴, /schedule, 메신저 봇이 후보로 제시됐다.
  • 단순하고 정형화된 작업은 LLM보다 자동화 스크립트가 효율적일 수 있다.
  • 논문 검색·저장·정리처럼 판단이 필요한 작업에는 봇과 Claude Code를 결합하는 방안이 논의됐다.
  • 이미 실행 중인 슬랙 봇이 있다면 별도 시스템을 추가하지 않고 그 봇에 자동화를 맡기는 방법이 제안됐다.
  • cron을 사용할지 봇 기반으로 운영할지는 작업의 복잡도와 운영 환경에 따라 선택할 수 있다.
