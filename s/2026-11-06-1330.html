Claude·Codex 사용량

Claude와 Codex를 여러 계정으로 사용해도 며칠 안에 사용량이 고갈되는 문제와 추가 계정 사용 가능 여부가 논의됐다. Claude 요금제의 사용량 배수가 과거와 달라졌다는 정정이 나왔다. 로컬 프록시로 실제 세션 사용량을 분석해 5배와 20배 요금제의 차이를 비교하고, 주간 사용량을 기준으로 필요한 계정 수를 계산하라는 방법이 공유됐다. Codex에서는 모델 정원 초과 메시지가 반복돼 결제 환불을 진행 중이라는 사례도 있었다.

  • Claude와 Codex를 함께 사용하면 짧은 기간에 한도가 소진될 수 있다는 경험이 공유됐다.
  • Claude 요금제의 사용량 배수와 제공 등급 변경에 대한 정정이 있었다.
  • 로컬 프록시 분석으로 5배와 20배 사용량을 비교한 수치가 공유됐다.
  • 세션 기록과 컨텍스트를 분석해 주간 사용량 및 필요한 계정 수를 계산하라는 팁이 나왔다.
  • Codex 모델 정원 초과 오류로 결제한 서비스를 사용하지 못하고 환불을 진행 중인 사례가 언급됐다.

  • 공유 이후 상세 사용 경험이나 문제점은 논의되지 않았다.

피클 티켓팅 성능

피클이 티켓링크나 쿠팡 같은 사이트에서 예매를 수행할 수 있는지 논의됐다. 로그인 상태에서 작업을 반복시키는 방식이 추정됐지만, 보안문자는 사용자가 직접 입력해야 한다는 경험이 공유됐다. Computer Use 기반이라 빠른 티켓팅에는 느리고, 별도 API 연결 없이는 성능에 한계가 있다는 의견이 우세했다.

  • 피클의 티켓링크 예매 가능 여부가 질문됐다.
  • 로그인 후 반복 작업을 수행하는 방식일 수 있다는 추정이 나왔다.
  • 보안문자는 자동으로 처리하지 못하고 사용자에게 입력을 요청한다는 경험이 있었다.
  • 빠른 예매 작업에는 속도가 부족하며 API 연결 없이는 한계가 있다는 평가가 나왔다.

  • 자동화 과정에서 계정 폭파나 제재 위험을 경고받는다는 경험이 공유됐다.
  • Computer Use 방식은 상대적으로 덜 걸릴 수 있지만 속도가 느리다는 평가가 있었다.
