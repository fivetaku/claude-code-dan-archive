멀티에이전트 분업 구조

여러 세션을 메인 에이전트가 자동으로 나누고 서로 관련된 내용을 공유하게 만드는 멀티에이전트 구조가 논의됐다. 그래프와 실시간 임베딩으로 작업을 쪼개고 등록했지만, 에이전트들이 서로의 영역까지 보면서 세션을 나눈 의미가 약해지는 문제가 생겼다. 큰 작업을 사람이 임의로 분류하면 에이전트 입장에서는 굳이 나눌 필요가 없는 작업이 될 수 있어, 분업 기준과 메인·서브 역할을 더 명확히 설계해야 한다는 결론에 가까웠다.

  • 메인 에이전트가 작업을 여러 세션에 분배하고 관련 세션끼리 정보를 공유하는 구조가 제안됐다.
  • 그래프와 실시간 임베딩을 이용해 작업을 쪼개고 등록하는 방식이 언급됐다.
  • 세션 간 공유 범위가 넓어지면 중복 수행과 역할 중첩이 발생할 수 있다.
  • 작업을 나누는 기준은 사람이 보기 좋은 분류보다 에이전트의 실제 독립성과 책임 범위를 기준으로 잡아야 한다.

세션 허브게이트 설계

세션 목록 조회, 세션 간 메시지 전달, 세션 정보 조회 기능을 바탕으로 세션 허브게이트를 만들고 싶다는 질문이 나왔다. 세션을 에이전시처럼 보고 그 안에서 서브에이전트를 부리되, 발주와 통제를 위한 게이트를 두는 구조가 논의됐다. 공유 작업 목록과 대시보드는 토큰 소비를 늘릴 수 있으므로, 로컬 세션 정보 전체를 복제하기보다 작업 상태와 최종 결과만 요약해 갱신하는 접근이 제안됐다. 준실시간 라우팅과 맥락 관리에 요약 정보를 가공해 적용하는 방향이 검토됐다.

  • 세션 허브게이트의 핵심 기능으로 세션 목록 조회, 메시지 전달, 세션 조회가 제시됐다.
  • 메인 세션과 서브 세션 사이에 발주·통제 게이트를 두는 구조가 논의됐다.
  • 공유 대시보드가 모든 맥락을 중복 기록하면 토큰 소비가 증가할 수 있다.
  • 전체 로그 대신 상태와 최종 결과만 요약해 공유하는 방식이 대안으로 제시됐다.
  • 라우팅용 요약 정보와 세션 맥락용 요약 정보를 함께 활용하는 방향이 검토됐다.

  • 두 도구 모두 병렬 세션 관리가 장점이지만 설정과 충돌 관리가 부담이 될 수 있다.
  • 교체 여부는 기능 목록보다 현재 겪는 불편이 해결되는지를 기준으로 판단하는 것이 좋다.
  • 작은 프로젝트에서 병행 테스트한 뒤 전환 여부를 결정하는 방식이 안전하다.
