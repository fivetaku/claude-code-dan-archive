AI 작업 검증 방식 논의

AI에게 작업을 맡긴 뒤 검증을 어떻게 하는지에 대한 질문에서 여러 방식이 공유됐다. dry run을 todo에 명시하거나 새 세션에서 파일경로만 주고 검토시키는 방법, 코드 직접 안 보고 자연어 요약만 읽는 방식, 에이전트 팀 단위로 작업시켜 모듈간 소통을 늘리는 방법 등이 나왔다. 결론적으로 AI가 부족한 게 아니라 니즈·정보·과거 실수(찐빠)를 종합한 컨텍스트가 부족한 게 문제라는 의견에 다수가 동의했다.

  • dry run을 todo에 명시해두고 문제 생기면 이유를 설명받아 고치는 방식
  • 새 세션에서 파일 경로만 주고 검토 요청하는 팁
  • 에이전트 팀으로 모듈별 스폰 시 서브에이전트간 메시징도 가능
  • claude.md를 작게 유지하고 지침을 lazy loading하면 스폰 비용 절감
  • '찐빠'(계획대로 안 굴러간 실수) 방지엔 니즈·정보품질·과거 시행착오 종합이 핵심
18:45-18:49AI 모델·프롬프트

아스트라 자가검증 루프 문제

아스트라가 갑자기 성능이 떨어져 '똥멍청이'가 됐다는 불만이 나왔다. 검증을 위한 검증, 설계를 위한 검증을 반복하며 골 설정을 지가 중간에 꺼버리는 현상이 보고됐다. 이런 과도한 자가검증 경향은 그동안의 사용자 피드백이 누적된 결과일 수 있다는 추측이 나왔다.

  • 아스트라가 자가루프를 걸며 검증에 검증을 반복
  • 골 설정을 중간에 스스로 꺼버리는 현상 보고
  • 캐시 비대화와 '일을 위한 일' 하는 경향도 함께 지적됨

어사이드·아스트라 토큰 폭탄 후기

어사이드로 루나를 돌리면 서브에이전트를 안 부르고 각개격파하는데, 같은 걸 아스트라로 하면 한번에 에이전트 50개를 불러 토큰 2만엔이 과금됐다는 후기가 공유됐다. 블로그 하나 번역·정리시켰는데 에이전트 다섯 개가 동시에 붙어 10장을 만들어버린 사례도 나왔다. 어사이드 에이전트 한도 설정 위치를 묻자 API 키별 할당량을 공급자 쪽에서 설정하면 된다는 답이 나왔고, 곁들여 젬황(제미나이)을 대안으로 쓰라는 제안도 있었다.

  • 루나+어사이드: 서브에이전트 없이 각개격파 방식
  • 아스트라+어사이드: 한 번에 에이전트 50개 소환, 토큰 2만엔 과금
  • 블로그 번역 작업에 에이전트 5개가 붙어 10장 결과물 생성
  • 에이전트 한도는 API 키별 공급자 할당량 설정으로 조절 가능
