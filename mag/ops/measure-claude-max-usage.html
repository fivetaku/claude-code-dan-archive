Claude Max 5x와 20x, 실제 사용 한도는 어떻게 측정할까

주간 퍼센트와 로컬 토큰 로그를 함께 기록해 100달러·200달러 플랜의 실질 가치를 비교하는 방법

2026-09-24논의 1회 정리

Claude Max 20x는 Max 5x보다 월 100달러 비싸다. 그렇다면 Claude Code로 처리할 수 있는 작업도 두 배 늘어날까. 답을 얻으려면 토큰 수와 주간 한도 퍼센트를 같은 시간축에 놓고 측정해야 한다.

20x라는 이름은 주간 작업량을 보장하지 않는다

Anthropic의 2026년 9월 안내에서 Max 5x는 월 100달러, Max 20x는 월 200달러다. 두 상품은 각각 Pro의 5배와 20배에 해당하는 5시간 세션 한도를 제공한다. Max끼리 비교하면 20x의 세션 용량이 5x보다 네 배 큰 구조다.

하지만 주간 한도에도 네 배 관계가 적용된다고 공식 문서는 밝히지 않는다. Anthropic은 Max에 모든 모델을 아우르는 주간 한도가 있으며 계정마다 정해진 시각에 초기화된다고 설명한다. 필요하면 모델·기능·월간 단위의 제한도 적용할 수 있다고 명시했다.

Claude 웹, 데스크톱, 모바일과 Claude Code의 사용량도 하나의 풀에서 빠진다. 코딩 기록만 비교하더라도 다른 화면에서 쓴 Claude 사용량이 섞이면 결과가 달라진다. 가격표의 배수를 그대로 주간 토큰 배수로 읽을 수 없는 이유다.

토큰과 한도 퍼센트는 서로 다른 장부다

Claude Code의 로컬 기록에는 입력, 출력, 캐시 생성, 캐시 읽기 토큰이 남는다. ccusage는 이 JSONL 기록을 읽어 일별·주별·세션별 사용량과 API 환산 비용을 계산한다. ccusage weekly --json을 실행하면 자동 집계용 JSON을 얻을 수 있다.

반면 실제 사용 중단을 결정하는 값은 Settings > Usage에 표시되는 5시간·주간 한도다. 로컬 토큰 합계는 작업의 크기를 설명하지만 구독 한도의 절대량을 그대로 보여주지는 않는다. API 환산 비용 역시 실제 청구액이 아니라 동일 사용량을 API 가격으로 계산한 비교 단위다.

써본 사람들 사이에서는 로컬 집계량과 계정의 주간 퍼센트가 크게 어긋난다는 반응이 반복된다. 캐시 읽기가 많은 세션이나 서브에이전트 작업에서 차이가 커졌다는 경험도 있다. 개별 사례만으로 한도가 줄었다고 단정할 수는 없다. 다만 퍼센트와 토큰 가운데 하나만 기록해서는 비교가 어렵다는 점은 분명하다.

실시간 상태선도 역할이 다르다. ccstatusline 같은 도구는 현재 모델, 컨텍스트 점유율, 세션 비용과 시간을 확인하는 데 유용하다. 여러 날에 걸친 플랜 비교에는 별도의 누적 저장소가 필요하다.

비교 도구는 두 데이터를 한 행에 저장해야 한다

가장 단순한 측정기는 ccusage 출력과 Usage 화면의 값을 CSV나 SQLite에 합치는 프로그램이다. 한 행에는 timestamp, plan, task_id, model, effort, 입력·출력·캐시 토큰, API 환산 비용, 5시간 퍼센트, 주간 퍼센트, 초기화 시각을 넣는다.

수집 순서는 어렵지 않다. 작업 시작 전에 Usage 값을 기록한다. 종료 직후에는 ccusage weekly --json과 ccusage session --json을 저장한 뒤 같은 시각의 Usage 값을 다시 입력한다. 두 스냅샷의 차이를 작업 ID에 연결하면 어떤 작업이 토큰과 주간 한도를 얼마나 움직였는지 계산할 수 있다.

자동화할 때도 구독 인증정보를 별도 서버에 올리면 안 된다. 공개 도구 가운데 계정의 실시간 한도를 가져오는 프로그램도 있지만 로컬 OAuth 자격증명을 읽는 방식을 쓴다. 코드를 검토하기 어렵다면 한도 퍼센트만 수동으로 입력하고 토큰 집계만 자동화하는 편이 안전하다.

대시보드에는 세 수치가 필요하다. 주간 한도 1%당 토큰, 주간 한도 1%당 API 환산 비용, 완료 작업당 주간 퍼센트다. 마지막 수치에는 테스트 통과나 승인된 PR처럼 명확한 완료 조건을 붙여야 한다. 토큰을 많이 쓴 실행이 더 좋은 결과를 냈다고 볼 근거는 없기 때문이다.

같은 작업을 반복해야 플랜 차이가 드러난다

비교 실험은 각 플랜에서 최소 한 차례의 온전한 주간 주기를 포함해야 한다. 같은 저장소 커밋에서 시작해 버그 수정·테스트 작성·리팩터링처럼 미리 정한 작업 묶음을 사용한다. 모델, effort, MCP 서버, 서브에이전트 수와 CLAUDE.md도 고정한다.

한 번씩 실행한 결과로는 부족하다. 동일한 작업도 실행별 토큰 사용량이 크게 달라질 수 있다. 작업 순서를 바꾼 반복 실험과 중앙값이 필요한 이유다.

컨텍스트 관리도 실험 조건이다. Anthropic은 매 요청마다 이전 대화, 읽은 프로젝트 파일과 새 프롬프트가 함께 처리된다고 설명한다. 작업이 바뀔 때 /clear를 사용하고 같은 작업을 이어갈 때만 /compact를 사용하는 식으로 조건을 통일한다.

Opus와 Sonnet을 섞었다면 모델별 결과도 분리해야 한다. 현재 API 가격은 Opus 5.5가 입력 100만 토큰당 4달러, 출력 20달러이며 Sonnet 5는 각각 2달러와 10달러다. 같은 토큰 수라도 모델 구성에 따라 환산 비용이 달라진다.

두 배 가격의 답은 토큰보다 중단 시간에서 나온다

측정 결과는 단순한 총토큰 표보다 작업 흐름으로 읽어야 한다. Max 5x가 주간 한도는 남지만 5시간 창을 자주 소진한다면 Max 20x의 넓은 세션 용량이 가치가 있다. 긴 리팩터링과 다중 에이전트 작업을 중간에 끊지 않는 효과가 핵심이다.

반대로 두 플랜 모두 주간 한도에 먼저 닿는다면 200달러 상품의 장점은 예상보다 작을 수 있다. 이때는 상위 플랜만 바꾸기보다 Sonnet 중심 실행, 작업별 /clear, CLAUDE.md 관리도 함께 점검할 수 있다. 한도를 넘긴 뒤 사용량 크레딧을 켜고 API 요율로 계속 쓰는 비용과도 비교해야 한다.

그래서 Max 5x와 20x의 가치는 공개되지 않은 ‘실제 토큰 상한’을 추측해서 판단할 문제가 아니다. 같은 작업에서 기록한 주간 퍼센트, API 환산 비용, 중단 시간을 합쳤을 때만 월 100달러의 추가 지출이 흐름을 얼마나 되돌려 주는지 드러난다.

자주 묻는 질문

Q

Claude Max 20x는 Max 5x보다 주간 한도가 네 배인가요?

공식적으로 확인된 네 배 관계는 5시간 세션 용량이다. Anthropic은 두 플랜의 구체적인 주간 용량 비율을 공개하지 않으므로 직접 측정 없이 네 배라고 단정할 수 없다.

Q

Claude Code 주간 토큰 사용량은 어떻게 확인하나요?

ccusage weekly --json으로 로컬 세션의 토큰과 API 환산 비용을 집계할 수 있다. 실제 제한까지 남은 양은 Settings > Usage의 주간 퍼센트를 함께 확인해야 한다.

Q

ccusage 비용이 Claude 구독료와 다른 이유는 무엇인가요?

ccusage의 비용은 로컬 토큰을 API 가격으로 환산한 추정값이다. 구독 한도는 서버 측 정책으로 관리되므로 API 환산 비용과 한도 퍼센트가 일대일로 대응하지 않을 수 있다.
