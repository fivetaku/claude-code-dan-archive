AI 모델·프롬프트

클로드 코드 모델 선택, Opus와 effort를 따로 조절해야 하는 이유

훅과 하네스를 갖춘 환경에서도 최고 설정이 늘 유리하지는 않다. 모델 능력과 작업 강도를 구분하고, 재시도까지 포함해 선택하는 기준을 살펴본다.

2026-11-06논의 1회 정리

클로드 코드에 작업 규칙과 자동 검사를 촘촘히 붙였다면 모델까지 가장 강한 설정으로 돌려야 할까. 클코단에서는 단순한 작업을 정돈할 때 설정을 높이자 기다림과 불필요한 설명이 늘었다는 경험이 공유됐다. 모델 선택과 effort를 분리하면 이 경험을 성능 우열이 아니라 작업에 맞는 설정을 찾는 문제로 해석할 수 있다.

Opus medium은 중간급 모델이 아니다

먼저 두 설정을 구분해야 한다. Anthropic의 모델·effort 안내에서 모델은 기본 능력을, effort는 요청에 투입하는 작업량을 조절한다. effort는 생각하는 시간뿐 아니라 파일 탐색, 도구 사용, 검증에도 영향을 준다. (claude.com)

Opus의 medium과 high를 비교하는 것은 같은 모델의 작업 강도를 비교하는 일이다. Sonnet에서 Opus로 바꾸는 것과는 실험 조건이 다르다. 클코단에서 제시된 Opus의 중간·높음 설정 선호를 곧바로 ‘작은 모델이 더 정확하다’는 결론으로 옮길 수 없는 이유다. (claude.com)

현재 Claude Code 모델 설정 문서는 Opus 5.5, Sonnet 5.5, Haiku 5.5의 기본 effort를 medium으로 명시한다. 반면 Sonnet 5.5의 API 기본값은 high다. 같은 모델이라도 제품별 기본값이 다르므로 비교할 때는 모델명과 실행 환경을 함께 기록해야 한다. (code.claude.com)

방에 공유된 경험에는 정확한 모델 버전과 비교 기록이 없다. 확인할 수 있는 것은 일부 작업에서 높은 설정을 덜 선호했다는 의견이지, 설정을 높이면 오류가 증가한다는 일반 법칙은 아니다.

훅이 많은 환경에서는 지연의 원인도 나눠야 한다

이 기사에서 하네스는 모델 주변의 지침, 도구, 실행 순서, 검증 장치를 묶어 부르는 말이다. Anthropic은 훅을 특정 실행 시점에 작동하는 제어 장치로 설명한다. 파일을 수정하거나 도구를 호출할 때 별도의 검사를 연결할 수 있다. (claude.com)

하지만 모든 훅이 같은 방식으로 작동하지는 않는다. 공식 훅 문서의 command 훅은 명령을 실행하고, prompt 훅은 모델에 판단을 요청한다. agent 훅은 도구를 사용하는 검증 에이전트를 띄워 파일과 코드를 확인한다. (code.claude.com)

이 구조라면 메인 모델의 추론 외에도 시간이 들 수 있다. 도구 호출 뒤 검사가 반복되고 검증 에이전트까지 작동한다면 전체 대기 시간을 메인 모델 탓으로만 돌리기 어렵다. 방에서 언급한 느려짐을 설명할 수 있는 가설이지만 해당 환경의 실행 기록으로 확인된 원인은 아니다. (code.claude.com)

검사를 더 많이 하는 것과 필요한 검사를 하는 것은 다르다.

고정된 형식 검사와 해석이 필요한 검토를 구분하면 비교가 명확해진다. 예컨대 포맷 검사는 명령으로 수행하고, 수정이 요구사항을 충족하는지는 별도로 평가하는 방식이다. 다만 훅이 있다는 이유만으로 판단 능력이 낮은 모델도 충분하다고 보장할 수는 없다. 훅은 실행을 제어하는 장치이지 모델의 능력을 바꾸는 기능이 아니기 때문이다. (claude.com)

확인을 생략했는지, 확인하고도 틀렸는지

설정을 바꾸기 전에 실패를 분류할 필요가 있다. Anthropic의 안내는 필요한 맥락이 제공됐는지부터 점검하도록 권한다. 관련 파일이나 요구사항이 빠졌다면 모델과 effort 어느 쪽을 바꿔도 핵심 정보의 빈칸은 남는다. (claude.com)

파일을 읽지 않았거나 테스트를 생략했다면 effort를 높이는 쪽이 맞을 수 있다. 반대로 자료를 충분히 확인하고도 설계나 오류 원인을 잘못 판단했다면 더 유능한 모델을 시험할 근거가 된다. Anthropic이 제시한 구분은 ‘실패했으니 최고 설정’보다 실패 과정에 초점을 둔다. (claude.com)

반대 방향도 가능하다. Claude Academy는 요청보다 과하게 일하는 경우 역시 effort 문제로 다룬다. 모델을 교체했다면 이전의 높은 설정을 그대로 유지하지 말고 기본값에서 다시 조절하도록 안내한다. 같은 high라도 모델마다 실제 작업량이 같지 않기 때문이다. (academy.claude.com)

클코단에서 나온 단순 작업의 지연 경험은 이 구분으로 다시 살펴볼 수 있다. 불필요한 탐색이었는지, 잘못된 판단이었는지, 검사가 반복됐는지는 서로 다른 문제다. ‘설명을 많이 했다’는 관찰과 ‘사실을 잘못 말했다’는 판정도 분리해야 한다.

같은 작업으로 모델과 effort를 따로 비교하는 방법

개인 개발자나 소규모 팀이라면 대표 작업 하나를 정해 비교할 수 있다. 다음은 성능을 입증한 실험이 아니라 공식 설정 기능을 이용한 비교 절차다. 준비물은 동일한 시작 상태의 코드, 같은 요청문, 합격을 판단할 테스트다.

  1. 입력 범위를 고정한다. 예를 들어 특정 함수의 오류 수정만 요청하고 관련 파일과 실행할 테스트를 명시한다.
  2. /model에서 Sonnet을 선택하고 /effort auto로 모델 기본값을 적용한다. 산출물은 코드 변경분과 테스트 실행 결과로 제한한다.
  3. 원래 코드 상태에서 새 세션을 시작한다. 이번에는 Opus와 기본 effort를 선택하고 같은 요청을 실행한다.
  4. 선택한 모델을 고정한 뒤 medium과 high를 비교한다. 모델과 effort를 동시에 바꾸지 않는다. 해당 명령과 기본값 복원은 공식 문서에 안내돼 있다. (support.claude.com)

평가표에는 완료 시간, 테스트 통과 여부, 요청 밖 수정, 사람의 추가 지시 횟수를 넣을 수 있다. 한 번의 성공보다 여러 작업에서 같은 경향이 반복되는지가 중요하다. 이 비교에서는 훅 구성도 유지해야 모델 설정의 차이를 해석하기 쉽다.

사용량은 /usage로 확인할 수 있다. 공식 비용 문서에 따르면 구독자는 요금제 사용량과 활동 통계를 볼 수 있다. 세션에 표시되는 API 환산 비용은 구독자의 추가 청구액과 같지 않으므로 돈과 사용량을 혼동하지 않아야 한다. (code.claude.com)

저렴한 모델보다 저렴하게 끝내는 조합

공식 권고도 적용 범위에 따라 다르다. Claude Code 도움말은 일반적인 코딩에 Sonnet을, 어려운 디버깅과 구조적 변경에 Opus를 제시한다. 반면 플랫폼의 비용 최적화 문서는 대부분의 에이전트 작업에서 Opus 5.5의 기본 effort를 출발점으로 권한다. (support.claude.com)

두 안내를 가르는 기준은 토큰 단가만이 아니다. Anthropic은 완료한 작업당 비용으로 비교하라고 설명한다. 더 유능한 모델이 적은 시도와 작업량으로 끝낸다면 높은 단가를 상쇄할 수 있기 때문이다. 공식 내부 평가도 공개 순위와 직접 비교할 수 없는 하위 집합이므로 특정 조합의 보편적 우승으로 읽어서는 안 된다. (platform.claude.com)

이 기준을 방의 사례에 적용하면 판단 대상은 명확해진다. 단순 정리 작업에서 medium이 합격 조건을 충족하고 high가 수정 품질을 높이지 못했다면 추가 작업량을 살 이유가 없다. 반대로 낮은 설정에서 재시도와 사람의 수정이 늘었다면 첫 응답이 빨랐다는 장점은 줄어든다.

훅을 촘촘히 갖춘 환경의 기본값은 가장 높은 설정이 아니라 정해진 검증을 통과하며 일을 끝내는 조합이어야 한다. 이 사례가 남기는 질문은 모델이 얼마나 오래 일했느냐가 아니다. 추가로 한 일이 실제 오류를 줄였느냐다.

자주 묻는 질문

Q

클로드 코드의 Opus medium과 high는 다른 모델인가요?

같은 Opus 모델에 적용하는 effort 단계다. effort는 추론뿐 아니라 탐색과 검증 등 작업량에도 영향을 준다. (claude.com)

Q

클로드 코드에서 모델과 effort는 어떻게 변경하나요?

/model로 모델을 선택하고 /effort로 작업 강도를 조절한다. /effort auto를 입력하면 모델 기본값으로 돌아간다. (support.claude.com)

Q

Sonnet보다 Opus가 항상 작업 비용이 많이 드나요?

토큰 단가만으로 작업 전체 비용을 판단할 수 없다. Anthropic은 재시도와 사용량을 포함한 완료 작업당 비용으로 비교하도록 권한다. (platform.claude.com)
