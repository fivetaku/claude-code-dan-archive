Claude Code 주간 한도 리셋 소문, 실제 변경은 따로 있었다

9월 14일 바뀐 것은 사용 기록 초기화가 아니라 프로모션 종료와 영구 한도 조정이었다

2026-09-16논의 1회 정리

Claude Code 이용자들이 기다린 것은 새 모델만이 아니었다. 주간 한도가 곧 초기화되리라는 기대가 퍼졌고, 남은 용량을 미리 써야 할지 고민도 이어졌다. 공식 문서를 보면 9월 14일의 핵심은 ‘리셋’이 아니라 주간 한도의 크기가 바뀐 일이었다.

소문은 서로 다른 세 가지 변화를 하나로 묶었다

Claude Code에서 ‘리셋’은 보통 사용한 할당량이 다시 채워지는 일을 가리킨다. 사용자는 계정별 주기에 따라 한도가 돌아오는 시각을 확인할 수 있다. 한도 자체가 커지는 것과 사용 기록이 지워지는 것은 다르다.

프로모션까지 겹치면서 표현은 더 혼란스러워졌다. Anthropic은 2026년 5월 13일부터 9월 13일까지 Claude Code의 주간 한도를 50% 높였다. 대상은 Pro, Max, Team과 기존 좌석형 Enterprise였고 5시간 한도는 바뀌지 않았다. ([support.claude.com](https://support.claude.com/en/articles/15910845-claude-code-may-august-2026-weekly-limits-promotion))

이용자들이 말한 변화는 세 갈래였다. 계정에 원래 예정된 정기 초기화, 프로모션 종료, 새 영구 한도 적용이다. 새 모델 발표와 함께 별도 초기화가 올 수 있다는 기대도 있었지만 9월 14일 공식 안내에는 그런 약속이 없었다.

공식 발표는 초기화가 아니라 영구 한도 조정이었다

Anthropic 지원 문서는 프로모션이 9월 13일 오후 11시 59분 미국 태평양시간에 끝났다고 명시한다. 다음 날부터 주간 한도는 프로모션 이전보다 25% 높은 수준으로 바뀌었다. 별도 신청은 필요하지 않았으며 변경된 용량은 자동으로 반영됐다. ([support.claude.com](https://support.claude.com/en/articles/15910845-claude-code-may-august-2026-weekly-limits-promotion))

문서에는 기존 사용량을 모두 지운다는 설명이 없다. 5시간 창과 주간 창을 동시에 새로 시작한다는 표현도 나오지 않는다. 프로모션 종료 시각을 모든 계정의 초기화 시각으로 해석할 근거가 부족한 셈이다.

실제 초기화 이벤트는 보통 조건이 훨씬 구체적이다. OpenAI의 Codex 안내는 일회성 리셋이 5시간·주간 창을 갱신하고 다음 주간 초기화 날짜까지 바꾼다고 설명한다. 자동 적용인지 보관형 혜택인지도 구분한다. ([help.openai.com](https://help.openai.com/en/articles/20001498-how-banked-codex-resets-work?utm_source=openai))

공식성이 불분명한 계정에서 ‘선물’이나 ‘리셋’을 암시했더라도 그대로 작업 계획에 반영하기는 어렵다. 제품 회사의 지원 문서나 계정 안의 사용량 화면에서도 같은 내용이 확인돼야 한다.

25% 인상인데 체감 용량은 약 17% 줄었다

이번 발표가 논쟁을 부른 이유는 비교 기준에 있다. 프로모션 이전 한도를 100으로 놓으면 여름 동안 제공된 용량은 150이었다. 9월 14일부터 적용된 영구 한도는 125다.

100에서 125로 보면 25% 증가다. 하지만 사용자가 직전까지 누린 150과 비교하면 25가 줄었다. 25를 150으로 나누면 약 16.7%이므로 체감상 17% 감소라는 설명도 맞다. ([explainx.ai](https://explainx.ai/blog/anthropic-claude-code-limits-17-percent-cut-september-2026-august-2026))

써본 사람들 사이에서는 장기간 이어진 임시 혜택이 사실상 기본 용량처럼 느껴졌다는 반응이 나왔다. 처음부터 기간이 정해진 혜택이었으므로 25%가 남은 것만으로도 개선이라는 의견도 있었다. 두 평가는 계산이 아니라 기준 시점에서 갈린다.

개인 개발자와 소규모 팀에는 후자의 숫자보다 전자의 숫자가 더 직접적이다. 지난 몇 달 동안 150을 전제로 병렬 세션과 자동화 작업을 구성했다면 이제 같은 작업량을 125 안에 넣어야 한다. 구독료가 그대로여도 실제 주간 계획은 다시 계산해야 한다.

한도 소진 전 몰아쓰기는 리셋 시각이 보일 때만 통한다

“곧 초기화된다면 남은 용량을 다 쓰자”는 판단은 정상 초기화 시각을 확인했을 때만 성립한다. 프로모션 종료나 모델 출시가 그 자체로 초기화를 보장하지는 않는다. Claude Code에서는 `/usage`로 프로모션이 반영된 한도를 확인할 수 있다. ([support.claude.com](https://support.claude.com/en/articles/15910845-claude-code-may-august-2026-weekly-limits-promotion))

한도는 단순한 메시지 횟수가 아니다. 대화가 길어질수록 이전 메시지와 읽은 파일이 매번 다시 포함된다. Opus 같은 무거운 모델과 복잡한 작업은 할당량을 더 빠르게 소진할 수 있다. ([support.claude.com](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code))

공식 가이드는 작업이 바뀔 때 `/clear`로 대화를 비우고 같은 작업을 이어갈 때 `/compact`로 맥락을 압축하라고 권한다. 어려운 설계는 Opus로 계획한 뒤 실행을 Sonnet으로 넘기는 방식도 소개한다. 무작정 요청을 늘리기보다는 남은 용량으로 완성할 수 있는 작업을 고르는 편이 안전하다. ([support.claude.com](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code))

리셋 여부는 발표 문구보다 계정의 미터가 답한다

주간 한도 소문을 검증하려면 ‘증가’, ‘연장’, ‘초기화’를 따로 읽어야 한다. 증가나 연장은 할당량의 크기를 바꾼다. 초기화는 이미 소비한 비율과 다음 갱신 시각까지 건드린다.

이번 공식 문서에서 확인된 것은 50% 임시 혜택의 종료와 25% 영구 증액이다. 모든 이용자의 주간 사용 기록을 9월 14일에 지웠다는 발표는 찾을 수 없었다. 새 용량이 적용됐다고 해서 지난 사용량까지 사라졌다고 볼 수는 없다.

자주 묻는 질문

Q

Claude Code 주간 한도는 9월 14일 자동 초기화됐나?

Anthropic의 공식 안내는 자동 초기화를 발표하지 않았다. 50% 프로모션이 끝나고, 프로모션 이전보다 25% 높은 영구 한도가 적용됐다.

Q

Claude Code 한도가 25% 늘었는데 왜 17% 줄었다고 하나?

기존 기준 100에서 새 한도 125로 보면 25% 증가다. 직전 프로모션 용량 150에서 125로 내려왔으므로 실제 체감치는 약 16.7% 감소다.

Q

Claude Code 남은 사용량과 초기화 시각은 어떻게 확인하나?

CLI에서 `/usage`를 실행해 현재 할당량을 확인할 수 있다. 공식 발표보다 계정에 표시되는 사용 비율과 갱신 시각을 작업 계획의 기준으로 삼아야 한다.
