AI 모델·프롬프트

로컬 LLM, 구독 대신 쓸 수 있나: 장비 비용과 성능의 조건

로컬 AI의 경제성은 구독료만으로 결정되지 않는다. 모델 크기와 메모리, 툴 호출, 데이터 전송 경로를 따져 실제로 대체할 업무를 가린다.

2026-10-29논의 1회 정리

AI를 직접 돌리면 구독을 끊어도 될까. 클코단에서는 로컬 모델의 도구 실행에 실망했다는 경험과 자료를 외부에 맡기지 않으려면 필요하다는 의견이 함께 나왔다. 구독 대체 여부를 판단하려면 최고 성능을 재현하는 비용과 특정 업무를 내 컴퓨터로 옮기는 비용부터 나눠야 한다.

구독 대체를 시험하려면 업무 하나를 옮겨야 한다

방에서는 범용 업무를 처리할 때 클라우드의 상위 모델이 수월하다는 의견이 나왔다. 보안 요구가 있거나 실행 환경을 직접 통제해야 하는 작업에는 로컬을 남겨둘 이유가 있다는 시각도 있었다.

두 의견은 서로 다른 구매 목적을 말한다.

시험 경로는 구체적이다. Qwen 공식 저장소는 Ollama 설치 후 ollama run qwen3:8b로 모델을 내려받고 실행하는 방법을 안내한다. 여기서는 최신 모델을 추천하려는 게 아니라 재현 가능한 입문 사례로 Qwen3를 사용한다. 명령을 실행하면 대화창에 텍스트를 넣고 답을 받을 수 있다. (github.com)

가령 개인 사업자는 공개 가능한 회의 메모를 넣고 결정 사항과 미해결 항목을 분리하도록 요청할 수 있다. 같은 입력을 평소 쓰던 서비스에도 넣어 누락, 잘못 추가한 내용, 수정 시간을 비교하는 방식이다. 이 시험의 산출물은 그럴듯한 답변보다 사람이 고치는 데 걸린 시간을 기록한 비교표여야 한다.

평가 질문도 좁아진다. 모든 분야에서 상위 모델을 이기는가가 아니라 반복 업무 하나를 원하는 품질로 끝내는가다.

8GB와 1TB는 서로 다른 모델의 이야기다

Ollama 모델 목록에서 qwen3:8b-q4_K_M 파일은 5.2GB, 같은 모델의 FP16 파일은 16GB다. 같은 이름의 모델도 숫자를 저장하는 정밀도에 따라 크기가 달라진다. 다운로드 용량을 곧바로 실행에 필요한 전체 메모리로 해석해서는 안 된다. (registry.ollama.com)

Ollama 문서는 문맥 길이를 늘리면 메모리 요구량도 증가한다고 설명한다. 실행 중 ollama ps를 입력하면 PROCESSOR에서 CPU·GPU 분담을, CONTEXT에서 배정된 문맥 길이를 확인할 수 있다. (docs.ollama.com)

짧은 질문이 돌아갔다고 긴 문서 처리까지 검증된 것은 아니다.

방에서 제기된 테라바이트급 메모리 질문은 초대형 모델을 상정하면 근거가 있다. DeepSeek-V3 기술보고서의 총 매개변수는 671B다. 이를 모두 16비트로 저장한다고 가정하면 가중치만 약 1.34TB라는 계산이 나온다. 연산 중 쓰는 추가 메모리를 제외한 단순 계산이며 모든 로컬 모델의 최소 사양은 아니다. (arxiv.org)

원본이라는 표현에도 주의가 필요하다. DeepSeek는 V3 공개 가중치를 FP8로 제공하고 BF16이 필요하면 변환하도록 안내한다. 비양자화라는 말 하나로 장비를 산정하기보다 모델 이름과 저장 형식을 함께 지정해야 한다. (huggingface.co)

방에서 거론된 거액의 장비비는 검증된 견적으로 취급할 수 없다. 목표 모델, 정밀도, 문맥 길이도 정하지 않은 금액으로 구독과 비교하면 서로 다른 작업을 계산하게 된다.

Mac Studio의 큰 메모리는 속도 보증이 아니다

2026년 10월 29일 확인한 Apple 지원 사양표에서 M3 Ultra Mac Studio는 최대 256GB 통합 메모리를 제공한다. 메모리 대역폭은 819GB/s다. NVIDIA가 공개한 GeForce RTX 5090의 메모리는 32GB이므로 두 제품의 숫자는 처음부터 같은 용량 구간을 가리키지 않는다. (apple.com)

큰 모델을 담는 문제와 빠르게 답하는 문제는 분리해야 한다.

Ollama도 최적 성능을 내려면 CPU로 모델 일부를 넘기는 상황을 피하도록 안내한다. 공식 사양과 이 지침을 함께 보면 메모리 용량만으로 응답 속도까지 단정할 수 없다. (docs.ollama.com)

방에서는 맥의 공유 메모리를 장점으로, 대역폭을 우려할 요소로 꼽는 의견이 있었다. 다만 세대와 모델을 생략한 채 맥은 느리다고 일반화할 근거는 부족하다. 이 기사에서 확인한 제품 사양 역시 동일 모델을 돌린 비교 실험은 아니다.

소규모 팀이 구매 비용을 계산할 때는 장비값만 넣지 않는 편이 타당하다. 전기 사용, 설치와 업데이트, 실패한 결과를 수정하는 시간을 별도 항목으로 두자는 제안이다. 이미 가진 컴퓨터로 업무를 옮기는 경우와 구독을 없애려고 새 장비를 사는 경우도 구분해야 한다. 구독료가 사라졌다는 사실만으로 투자금을 회수했다고 판단하지 않는 계산법이다.

툴 호출 지원과 업무 완료는 별개의 검증이다

로컬 모델로 도구 실행이 잘되지 않았다는 방의 경험을 기능 자체가 없다는 뜻으로 읽어서는 안 된다. Ollama 공식 문서는 툴 호출을 지원하며 Qwen3를 사용하는 예제를 제공한다. 모델에 함수의 이름과 입력 구조를 전달하고 호출 결과를 후속 대화에 넣는 구조다. (docs.ollama.com)

공식 Python 예제는 도시 이름을 받는 get_temperature 함수를 등록한다. 모델이 반환한 tool_calls를 프로그램이 읽고 함수를 실행한 뒤 결과를 tool 메시지로 다시 보낸다. 최종 답변은 그 결과를 받은 모델이 작성한다. (docs.ollama.com)

모델이 함수 실행을 요청하는 단계와 실제 프로그램이 실행하는 단계가 분리돼 있다.

업무 시험도 그 구분을 따라 설계할 수 있다. 읽기 전용 조회 함수 하나를 연결한다. 입력한 요청이 올바른 함수와 인수로 바뀌는지 기록한 다음 실제 반환값과 최종 답변이 일치하는지 확인하는 방식이다.

파일 생성 같은 작업이라면 완료했다는 문장 대신 실제 파일과 내용을 검사 항목으로 삼아야 한다. 이 기사에서 제안하는 판정 기준은 말의 자연스러움이 아니라 요청과 실행 결과의 일치다. 방에서 제기된 불편도 이 기준으로 재시험해야 모델의 한계와 연결 프로그램의 문제를 구분할 수 있다.

로컬의 실익은 실행 경로를 직접 정하는 데 있다

보안을 이유로 로컬을 택한다면 프로그램 이름보다 요청이 처리되는 위치가 중요하다. Ollama는 다운로드한 모델뿐 아니라 클라우드 모델도 지원한다. 공식 클라우드 문서는 원격 요청의 프롬프트와 응답을 처리한다고 밝힌다. 로컬만 쓰려면 클라우드 기능을 비활성화하도록 안내한다. (github.com)

이미지 생성에서도 같은 구분이 필요하다. 방에서는 서비스의 콘텐츠 제약과 별개로 작업 과정을 자유롭게 조합하려고 ComfyUI를 쓴다는 의견이 나왔다. ComfyUI 공식 입문서는 텍스트 입력부터 이미지 저장까지 로컬에서 재현할 수 있는 예제를 제공한다. (docs.comfy.org)

ComfyUI에서 예제 text-to-image.json을 열고 안내된 v1-5-pruned-emaonly-fp16.safetensors를 models/checkpoints에 둔다. Load Checkpoint에서 모델을 선택하고 프롬프트를 바꾼 뒤 Run을 누르면 Save Image에 결과가 나온다. 워크플로우는 JSON으로 내보내 다시 사용할 수 있다. (docs.comfy.org)

다만 ComfyUI 화면에서 실행했다고 모두 내 장비에서 계산되는 것은 아니다.

Comfy 공식 저장소는 Partner API 노드를 통해 로컬 워크플로우도 외부 모델을 호출할 수 있다고 설명한다. 문서와 이미지를 밖으로 보내지 않는 것이 목적이라면 이런 연결을 제외한 실행 경로를 구성해야 한다. (github.com)

방의 질문으로 돌아가면 판단 기준은 최고급 모델을 집에 들이는 가격이 아니다. 정해진 업무를 외부 전송 없이 끝내고 결과를 고치는 시간까지 감당할 수 있는지가 기준이다.

구독 버튼을 끄는 것만으로 로컬의 경제성이 성립하지는 않는다. 맡긴 업무가 그 조건으로 반복 완료돼야 한다.

자주 묻는 질문

Q

로컬 LLM을 쓰려면 VRAM 1TB가 필요한가요?

모든 모델에 필요한 용량이 아닙니다. DeepSeek-V3의 671B 매개변수를 전부 16비트로 저장한다고 가정할 때 가중치만 약 1.34TB라는 계산이 나옵니다. 실제 요구량은 모델과 저장 형식, 문맥 길이에 따라 달라집니다. (arxiv.org)

Q

Ollama로 실행하면 데이터가 무조건 로컬에 남나요?

Ollama는 로컬 모델과 클라우드 모델을 모두 지원하므로 실행 위치를 구분해야 합니다. 공식 문서는 로컬만 사용하려면 클라우드 기능을 비활성화하도록 안내합니다. (github.com)

Q

로컬 모델도 툴 호출을 할 수 있나요?

Ollama는 툴 호출을 지원하고 Qwen3 예제를 제공합니다. 모델이 요청한 함수를 애플리케이션이 실행하고 결과를 돌려주는 구조이므로, 지원 여부와 실제 업무 성공은 따로 검사해야 합니다. (docs.ollama.com)
