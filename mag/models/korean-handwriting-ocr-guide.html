한글 손글씨 OCR, 이미지 인식에서 검색 가능한 문서까지

한글 손글씨를 OCR로 옮길 때 필요한 모델 선택과 세그멘테이션, 후처리 파이프라인을 정리했다

2026-11-10논의 1회 정리

노트 앱에 연필로 쓴 한글을 사진이나 캡처 이미지로 남기는 사람은 많지만, 이를 검색 가능한 문서로 바꾸는 일은 아직 단순한 OCR 호출로 끝나지 않는다. 핵심 질문은 ‘한글 손글씨를 얼마나 잘 읽느냐’보다 ‘읽은 결과를 업무에 쓸 수 있는 구조로 만들 수 있느냐’에 가깝다. 이 글에서는 이미지 입력부터 영역 분리, 인식, 검증까지 실제 파이프라인을 살펴본다.

한글 손글씨 OCR은 이미 가능하지만, 조건이 붙는다

Microsoft의 Azure Vision Read OCR은 현재 한국어 필기 텍스트를 지원한다. 이미지와 PDF에서 글자·줄·단어의 위치와 신뢰도도 함께 반환한다. Google Cloud Vision 역시 Korean을 지원하는 필기 인식 스크립트로 분류하며, 문서 텍스트 인식 결과에 페이지·문단·단어·문자 계층을 제공한다.

이 기능은 ‘한국어를 읽을 수 있다’는 의미이지, 어떤 필기체도 안정적으로 해석한다는 뜻은 아니다. 글자의 기울기, 획의 생략, 줄 간격, 배경색, 촬영 흔들림에 따라 결과가 크게 달라진다. 한글은 음절 블록 단위로 조합되기 때문에 한 획의 위치가 바뀌면 전혀 다른 글자로 해석될 수 있다.

커뮤니티에서 공유된 노트 앱 손글씨 사례도 비슷했다. 또박또박 쓴 문장은 인식 가능성이 높지만, 필기체가 빠르게 이어지거나 문장이 기울면 제품별 차이가 커진다는 의견이 많았다. 손글씨를 이미지로 저장한 뒤 OCR을 적용하는 방식은 오프라인 필기 인식이고, 펜의 좌표와 시간 정보를 보존한 채 입력하는 방식은 온라인 필기 인식이다.

이미지와 획 데이터는 서로 다른 문제다

노트 앱에서 이미지를 캡처했다면 시스템은 글자가 어떤 순서로 쓰였는지 알 수 없다. 남은 정보는 픽셀뿐이다. 이때 OCR은 먼저 글이 있는 위치를 찾고 줄과 단어를 나눈 뒤 각 영역의 문자를 추정한다.

반대로 태블릿이나 웹 캔버스가 펜의 움직임을 저장하면 입력은 좌표 배열이 된다. Google ML Kit Digital Ink Recognition은 이 방식으로 펜의 획과 시간 정보를 받아 기기에서 글자를 인식한다. 300개가 넘는 언어와 여러 문자 체계를 지원하며, Android와 iOS에서 오프라인 처리가 가능하다.

온라인 방식은 글자의 순서와 획의 시간 정보를 활용할 수 있다는 장점이 있다. 대신 이미 찍힌 사진이나 종이 문서를 처리하지 못한다. 기존 노트 이미지, 스캔 문서, 보험 서류처럼 결과물이 픽셀로만 남아 있다면 Azure Vision, Google Cloud Vision, PaddleOCR, TrOCR 같은 이미지 기반 HTR 도구를 선택해야 한다.

제품 하나보다 세그멘테이션이 먼저다

손글씨 문서에서 자주 발생하는 오류는 글자를 잘못 읽는 문제만이 아니다. 제목, 본문, 표, 체크박스, 낙서, 인쇄 문자가 한 화면에 섞이면 OCR이 읽는 순서 자체를 틀릴 수 있다. 두 개의 문단을 한 줄로 합치거나 표의 열을 왼쪽에서 오른쪽 순서로 재배열하는 식이다.

PaddleOCR의 PP-Structure는 레이아웃 분석 뒤 영역별 OCR을 수행하는 문서 분석 시스템이다. 이미지·텍스트·제목·표를 분리하고, 텍스트 영역에는 탐지와 인식을 적용한다. PaddleOCR 문서에는 Korean 인식 모델도 포함돼 있지만, 최신 범용 모델의 언어 범위와 한국어 모델의 제공 방식은 버전에 따라 다르므로 설치한 버전의 모델 목록을 확인해야 한다.

실제 구현 순서는 다음처럼 잡는 편이 안전하다. 먼저 이미지에서 배경과 기울기를 보정한 다음 텍스트 영역을 분리한다. 영역별로 OCR을 실행하고 좌표를 이용해 읽기 순서를 복원한 뒤, 마지막에 VLM이나 규칙 기반 후처리로 문장과 필드를 정리한다.

필기 이미지가 노트 한 장이라면 원본 전체를 곧바로 VLM에 넣는 방법도 있다. 하지만 금융·보험·의료 문서처럼 숫자와 고정 필드가 중요한 경우에는 영역별 인식과 검증을 분리하는 편이 낫다. 인식 결과가 그럴듯해 보여도 계좌번호, 날짜, 금액, 약품명은 별도 규칙으로 다시 확인해야 한다.

VLM은 문맥을 보완하지만 원문 판정자가 아니다

VLM은 손글씨를 단순한 문자 묶음이 아니라 문장과 문서의 맥락 속에서 해석할 수 있다. 흐릿한 글자 주변의 단어를 보고 후보를 좁히거나, 제목과 본문을 구분하거나, 질문에 맞는 필드를 찾는 데 유리하다. 최근 비교 연구에서도 현대적 손글씨에서는 일부 MLLM이 전용 모델보다 낮은 문자 오류율을 보인 결과가 보고됐다.

그렇다고 VLM 출력을 정답으로 취급하면 안 된다. 문맥을 활용하는 모델은 읽지 못한 글자를 자연스러운 단어로 채울 수 있다. 특히 고유명사, 숫자, 전문 약어, 손으로 수정한 문장은 문장 전체가 자연스러워도 원문과 다를 수 있다.

안전한 방식은 OCR 결과와 VLM 결과를 나란히 보관하는 것이다. OCR은 바운딩 박스와 confidence를 남기고, VLM은 문단 요약이나 필드 매핑을 담당한다. 두 결과가 다르면 원본 이미지의 해당 영역을 다시 보여주거나 사람이 확인해야 할 항목으로 분류한다.

써본 사람들 사이에서도 비슷한 반응이 나온다. 깔끔한 문장과 일반적인 메모는 최신 VLM이 빠르게 읽지만, 표와 수식, 여러 열이 섞인 페이지에서는 레이아웃이 무너진다는 불만이 있다. 전용 OCR은 구조가 단순할 때 안정적이고, VLM은 애매한 문맥을 해석할 때 강하다는 평가가 엇갈린다.

금융·보험·의료 문서는 도메인 모델로 좁혀야 한다

도메인별 처리가 필요한 이유는 단어 목록만의 문제가 아니다. 보험 문서에는 상품명과 보장 항목이 반복되고, 금융 문서에는 금액·날짜·식별번호가 집중된다. 의료 기록은 약품명과 단위, 의학 약어가 섞이며 손글씨의 축약과 기호도 많다.

따라서 ‘한글 손글씨 OCR 모델 하나’를 고르는 접근보다 문서 유형별 평가셋을 만드는 일이 먼저다. 실제 사용자가 쓰는 펜과 종이, 조명, 촬영 거리로 샘플을 모으고, 글자 오류율뿐 아니라 필드 추출 성공률과 숫자 오류율을 따로 측정해야 한다. 한국 국가기록원 연구에서도 한글 필기 기록에 OCR을 적용해 검색성을 높이는 것을 목표로 데이터셋과 테스트베드를 구축했다.

개인 개발자나 소규모 팀이라면 처음부터 모델을 학습할 필요는 없다. 노트 이미지에는 Azure Vision이나 Google Cloud Vision으로 기준선을 만들고, 로컬 처리가 필요하면 PaddleOCR의 한국어 모델과 전처리 파이프라인을 시험하면 된다. 문서 수가 늘고 같은 사람이 반복해서 쓰는 양식이 생겼을 때만 자체 데이터로 미세조정을 검토하는 편이 비용을 통제하기 쉽다.

실제로 만들 때 필요한 입력과 산출물

최소 파이프라인의 입력은 손글씨 이미지 한 장이다. 저장소에는 원본 이미지, 보정 이미지, 영역 좌표 JSON, OCR 원문 JSON, 최종 텍스트를 별도 파일로 남긴다. 이미지 보정 단계에서는 회전·기울기·노이즈를 처리하고, 세그멘테이션 단계에서는 제목·본문·표·필기 영역을 분리한다.

그다음 OCR 엔진에 영역 이미지를 전달한다. Azure Vision과 Google Cloud Vision은 텍스트와 위치 정보를 반환하며, PaddleOCR은 탐지 상자와 인식 문자열, confidence를 제공한다. 결과는 줄 단위로 정렬해 Markdown이나 JSON으로 저장하고, VLM에는 원본 전체보다 필요한 영역과 OCR 후보를 함께 전달한다.

최종 산출물은 텍스트 하나가 아니다. 검색용 본문, 원본 좌표, confidence, 수정 이력, 사람 검수 여부가 함께 있어야 한다. 이 구조를 갖추면 같은 문서를 다시 읽을 때 오류 지점을 찾을 수 있고, 금융·보험·의료처럼 틀린 한 글자의 비용이 큰 영역에서도 자동화 범위를 통제할 수 있다.

한글 손글씨 OCR의 성패는 인식 모델의 이름보다 입력 형태와 문서 구조에 달려 있다. 이미지뿐인 노트라면 세그멘테이션과 검증이 핵심이고, 펜의 획 데이터를 보존할 수 있다면 온라인 인식이 더 직접적인 선택이 된다. 검색 가능한 문서를 만들려는 팀이라면 ‘얼마나 잘 읽는가’에서 멈추지 말고 어떤 영역을 어떤 근거로 확정했는지까지 저장해야 한다.

자주 묻는 질문

Q

한글 손글씨를 무료로 OCR할 수 있나요?

Google ML Kit Digital Ink Recognition은 펜의 획 데이터를 기기에서 처리할 수 있습니다. 이미지 기반이라면 PaddleOCR 같은 로컬 도구를 시험할 수 있지만, 한국어 필기체와 문서 구조는 별도 검증이 필요합니다.

Q

Azure Vision은 한국어 손글씨를 인식하나요?

Azure Vision Read OCR은 한국어 필기 텍스트를 지원합니다. 인식 결과에는 줄과 단어의 위치, confidence가 포함될 수 있지만 필체와 이미지 품질에 따라 정확도가 달라집니다.

Q

VLM과 OCR 중 무엇을 써야 하나요?

OCR은 위치와 원문 후보를 남기는 데 유리하고, VLM은 문서 맥락과 필드 관계를 해석하는 데 유리합니다. 중요한 문서는 두 결과를 결합하고 숫자와 고유명사를 별도로 검증하는 방식이 안전합니다.
