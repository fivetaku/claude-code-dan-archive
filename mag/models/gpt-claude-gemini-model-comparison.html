AI 모델·프롬프트

GPT·Claude·Gemini 비교, 문서와 검수에 맞는 선택법

최신 모델의 성능표보다 중요한 것은 문서 작성, 장기 맥락, 검수 방식에 맞춘 조합이다

2026-11-14논의 1회 정리

생성형 AI를 여러 개 써본 사람에게 남는 질문은 “가장 똑똑한 모델이 무엇인가”보다 “내 작업의 어느 단계에 어떤 모델을 배치해야 하는가”에 가깝다. 최근 GPT-6 Astra, Claude Fable 5.2·Opus 5.5, Gemini 4 Carbon이 잇따라 등장하면서 이 선택은 더 복잡해졌다. 문서 작성과 장기 작업, 결과 검수라는 세 가지 기준으로 실제 선택법을 따져봤다.

최신 모델은 모두 강하지만 잘하는 일은 다르다

OpenAI는 GPT-6 Astra를 복잡한 추론, 코딩, 컴퓨터 사용, 문서 작성에 특화한 모델로 소개한다. 105만 토큰 컨텍스트와 최대 12만8000 토큰 출력을 제공하며, 기존 템플릿을 따르고 문서·프레젠테이션·스프레드시트를 완성하는 능력을 강조한다. OpenAI 자체 평가에서는 Astra가 전문 업무에서 비교 대상 모델보다 적은 출력 토큰으로 결과를 내는 사례도 제시됐다. (openai.com)

Anthropic의 Claude Fable 5.2는 가장 어려운 기술 업무를 겨냥한다. 여러 저장소를 넘나드는 코딩, 과학 연구, 금융 분석처럼 목표가 모호하고 작업 시간이 긴 문제를 주요 용도로 내세운다. 반면 Anthropic은 일상적인 코딩과 지식 업무에는 Claude Opus 5.5부터 시작하라고 안내한다. Fable 5.2의 API 가격은 입력 100만 토큰당 8달러, 출력 100만 토큰당 40달러다. Opus 5.5는 각각 4달러와 20달러다. (anthropic.com)

Google은 Gemini 4 Carbon을 복잡한 다단계 코딩과 개방형 과학 연구를 위한 모델로 설명한다. 사고 토큰 사용량을 조절해 품질·지연시간·비용 사이의 균형을 맞출 수 있다는 점이 특징이다. Google이 공개한 평가 자료는 Carbon을 GPT-6 Astra, Claude Opus 5.5, Claude Fable 5.1과 비교한다. 하지만 벤치마크마다 승자가 달라 단일 순위로 읽기 어렵다. (deepmind.google)

보고서 작성에서는 모델의 ‘완성 습관’이 갈린다

커뮤니티에서 나온 가장 구체적인 불만은 Gemini가 한국어 문장 자체는 자연스럽지만, 보고서나 소개서에서는 내용을 충분히 쓰지 않고 문서 번호나 항목 표시로 넘기는 듯하다는 평가였다. 이 판단은 개인 사용 경험에 기반한 의견이다. Gemini 전체를 설명하는 일반 법칙으로 확대할 수는 없다.

문서 작업에서 모델의 실력은 문장을 매끄럽게 만드는 데서 끝나지 않는다. 요구사항을 빠뜨리지 않고 표와 본문을 연결하며, 독자가 바로 사용할 수 있는 수준까지 마무리해야 한다. GPT-6 Astra는 기존 템플릿과 문체를 유지하면서 문서와 프레젠테이션을 구성하는 기능을 핵심 강점으로 내세운다. 템플릿, 참고 자료, 분량 기준을 함께 제공할수록 강점을 확인하기 쉽다. (openai.com)

Gemini 4 Carbon은 복잡한 사고와 검증 루프를 강조한다. 긴 자료를 읽고 여러 조건을 비교하거나 논리적 결함을 찾는 작업에서 시험하는 편이 합리적이다. 다만 개인 사용자는 모델 자체보다 프롬프트와 입력 자료의 구조에 더 큰 차이를 느낄 수 있다.

속도보다 완성도가 중요할 때는 선택이 달라진다

방 논의에서는 Astra가 세 모델 중 가장 느리지만 결과물의 완성도는 높다는 개인 평가가 나왔다. 반대로 GPT는 장기간 사용하면서 사용자 취향과 작업 패턴이 축적돼 가장 편하다는 의견이 많았다. 두 평가는 충돌하지 않는다. 전자는 한 번의 결과 품질에 관한 판단이고, 후자는 반복 사용에서 생기는 마찰 비용에 관한 판단이기 때문이다.

실사용 반응에서도 Astra는 느리지만 차분하게 끝까지 처리한다는 평가와 작업 시간이 길어 답답하다는 불만이 함께 나온다. 모델 선택에서 속도는 단순한 편의가 아니다. 짧은 답을 하루에 수십 번 받는 업무라면 지연시간이 생산성을 좌우한다. 한 번의 보고서나 설계안을 오래 검토한다면 재작업 횟수가 더 중요해진다.

Claude Fable 5.2는 Anthropic이 장시간 자율 작업과 반복 검증을 강조하는 모델이다. 공식 설명에 따르면 Fable은 자신의 작업을 질문하고 확인하며 여러 하위 작업을 조율하는 방식으로 설계됐다. 반면 Opus 5.5는 Fable 5.1 수준의 성능을 더 낮은 비용으로 제공하는 일상용 고성능 모델로 포지셔닝됐다. (anthropic.com)

가장 현실적인 조합은 ‘생성’과 ‘검수’를 나누는 방식이다

방에서는 Fable과 Opus를 결과 검수에 쓰자는 제안도 나왔다. 모델마다 오류를 만드는 방식이 다르다는 전제에서 출발한 접근이다. 한 모델이 만든 보고서를 다른 모델에 넣고 사실 누락, 논리 비약, 표현의 부자연스러움, 요구사항 미반영 여부를 따로 점검하면 단일 모델에 모든 책임을 맡기는 것보다 실패 지점을 찾기 쉽다.

다만 검수 모델의 판단을 최종 사실로 받아들여서는 안 된다. 외부 사용 경험에서도 한 모델이 다른 모델의 결과를 잘 평가했다는 사례와 검수 모델 자체가 놓치는 문제가 있다는 반응이 함께 나타난다. 검수는 정답 판정이 아니라 추가적인 오류 탐지 단계에 가깝다.

개인 개발자나 소규모 팀이라면 다음과 같은 구성이 현실적이다. 초안과 구조화된 문서는 GPT-6 Astra로 만들고, 복잡한 분석이나 장기 추론은 Claude Fable 5.2 또는 Gemini 4 Carbon으로 별도 요청한다. 비용과 속도가 중요하면 Claude Opus 5.5를 기본 모델로 두고, 중요한 결과만 Fable 5.2나 Astra에 재검토시킬 수 있다.

벤치마크보다 작업 로그가 더 정확한 선택 기준이다

공식 비교표는 모델의 방향성을 보여주지만 사용자의 업무를 그대로 대신하지는 않는다. Anthropic의 비교표에서는 Fable 5.2가 코딩과 과학 영역에서 높은 점수를 보였고, Google의 평가 자료에서는 Carbon이 일부 장기 추론과 에이전트 업무에서 강점을 보였다. OpenAI 역시 Astra의 문서 작성과 컴퓨터 사용, 코딩 성능을 별도 평가로 제시한다. 서로 다른 회사가 서로 다른 조건과 벤치마크를 사용하므로 숫자를 한 줄 순위로 합치면 오해가 생긴다. (anthropic.com)

실전에서는 같은 입력을 세 모델에 넣고 네 항목만 기록하면 된다. 요구사항 누락 수, 사람이 고친 문장 수, 사실 확인이 필요한 주장 수, 첫 결과부터 사용 가능한 데 걸린 시간을 비교한다. 이 기록이 쌓이면 한국어 문서, 코드 리뷰, 조사 보고서처럼 자신의 업무에 맞는 모델 순위가 만들어진다.

세 모델 중 하나를 영구적인 1위로 고르는 전략은 오래가기 어렵다. 2026년 Vercel 자료에서는 새 모델로의 빠른 교체와 여러 모델을 함께 쓰는 양상이 나타난다. (techradar.com) 가장 편한 모델을 기본값으로 두되 중요한 결과에는 다른 모델의 시선을 추가하는 방식이 현재로서는 가장 견고하다.

자주 묻는 질문

Q

GPT, Claude, Gemini 중 문서 작성에 가장 좋은 모델은 무엇인가요?

GPT-6 Astra는 템플릿과 문서 형식을 지키는 작업에 강점을 내세웁니다. 다만 한국어 문서의 자연스러움과 요구사항 준수는 실제 업무 자료로 직접 비교하는 편이 정확합니다.

Q

Claude Fable과 Opus는 어떻게 나눠 써야 하나요?

Claude Fable 5.2는 고난도 기술 업무와 장기 작업에 적합하고, Claude Opus 5.5는 비용과 속도를 고려한 일상 업무용 선택지입니다. 모든 작업에 Fable을 쓰기보다 중요한 문제에 집중하는 편이 효율적입니다.

Q

AI 모델 결과를 다른 모델로 검수해도 되나요?

가능합니다. 다만 검수 모델도 오류를 낼 수 있으므로 사실 확인과 원자료 대조를 함께 해야 합니다.
