Antigravity 2.0, Gemini 성능이 아쉬워도 쓸 이유가 있나

모델 성능 논쟁을 넘어 프로젝트 격리, 병렬 에이전트, 작업 검증까지 실제 선택 기준을 살펴봤다

2026-09-19논의 1회 정리

Google Antigravity 2.0을 두고 반응이 엇갈린다. 여러 작업을 맡기는 화면은 매력적이지만 Gemini가 답답해 다시 쓸 이유가 없다는 의견도 적지 않다. 그렇다면 Antigravity의 가치는 모델 성능과 함께 사라지는가? 아니면 실행 환경 자체에 남아 있는가?

Antigravity 2.0은 IDE보다 에이전트 관제 도구에 가깝다

Google은 2026년 5월 Antigravity 2.0을 독립 데스크톱 앱으로 개편했다. 기존 Antigravity IDE에 있던 Agent Manager를 떼어내 여러 로컬 에이전트를 관리하는 중심 화면으로 확장했다. macOS와 Windows, Linux에서 실행되며 CLI와 SDK, IDE 확장도 별도 제품군으로 제공한다. ([antigravity.google](https://antigravity.google/))

핵심 단위는 파일 하나가 아니라 Project다. 프로젝트에 로컬 폴더나 Git 저장소를 연결하면 여러 대화를 같은 작업 경계 안에서 운영할 수 있다. 여러 저장소를 한 프로젝트에 넣는 교차 저장소 작업도 지원한다.

작업을 시작할 때는 현재 폴더를 직접 수정하는 Local Mode와 별도 Git worktree를 만드는 New Worktree Mode 중 하나를 고른다. 실험 기능이나 병렬 작업에는 worktree가 안전하다. 한 에이전트가 기능을 만들고 다른 에이전트가 테스트를 수정하더라도 파일 충돌을 줄일 수 있기 때문이다. ([antigravity.google](https://antigravity.google/docs/getting-started))

여기에 예약 실행, 하위 에이전트, MCP, Skills, Hooks, 브라우저 조작과 변경사항 검토가 붙는다. Antigravity를 단순한 ‘Gemini 코딩 앱’으로 보면 놓치게 되는 부분이다.

Gemini가 마음에 들지 않으면 모델을 바꿀 수 있다

실사용 의견에서 가장 자주 나온 불만은 Gemini가 복잡한 코드 수정에서 맥락을 놓치거나 쉬운 명령을 반복하며 시간을 소비한다는 점이었다. 특히 Windows와 PowerShell 환경에서 셸 문법을 혼동하거나 지정한 폴더와 다른 문맥을 여는 일을 겪었다는 반응도 있다. 반면 짧은 프로토타입과 단순 파일 작업에는 충분히 빠르다는 평가도 나온다.

모델 품질과 Antigravity의 실행 환경은 나눠서 볼 필요가 있다. 무료 개인 플랜의 공식 모델 목록에는 Gemini 3.8 Flash와 3.1 Pro뿐 아니라 Claude Sonnet·Opus 4.6, gpt-oss-120b도 들어 있다. Gemini 결과가 불만스럽다면 같은 프로젝트 구조와 검토 화면을 유지하면서 모델만 바꿀 수 있다. ([antigravity.google](https://antigravity.google/pricing))

Google의 공식 실습 문서도 Antigravity에서 Gemini와 Claude를 선택할 수 있다고 설명한다. 계획을 먼저 검토하고 실행 도중 피드백을 주는 방식, 에디터·터미널·브라우저를 오가는 과정은 어느 모델을 고르더라도 플랫폼이 제공하는 기능이다. ([codelabs.developers.google.com](https://codelabs.developers.google.com/codelabs/getting-started-with-spec-driven-development-in-antigravity))

성능을 비교할 때도 한 번의 생성 결과만 봐서는 부족하다. 저장소를 정확히 읽는지, 잘못된 명령을 스스로 고치는지, 테스트를 실제로 실행했는지까지 살펴야 한다. Antigravity 안에서 같은 요청을 Gemini와 Claude에 각각 맡겨보는 것이 가장 현실적인 평가법이다.

CSV 관리 도구를 만들면 장단점이 빠르게 드러난다

Antigravity를 시험한다고 거대한 서비스를 만들 필요는 없다. 개인 개발자와 소규모 팀이라면 CSV를 읽고 수정하는 내부 도구가 적당하다. 입력과 산출물이 명확해 에이전트의 실수를 바로 찾을 수 있다.

먼저 영문과 숫자로 `student-record-helper` 같은 빈 폴더를 만든다. Antigravity 왼쪽의 새 프로젝트 메뉴에서 해당 폴더를 추가한 뒤 Project를 생성한다. 원본 보호가 중요하다면 Git을 초기화하고 New Worktree Mode로 대화를 연다.

폴더에는 열 이름과 가상 데이터만 담은 `sample.csv`를 넣는다. 첫 요청에는 “CSV 열 구조를 먼저 설명하고 구현 계획을 작성하라. Python Flask로 로컬 웹 앱을 만들고, 검색·수정·CSV 내보내기 기능을 넣어라. 원본 파일은 덮어쓰지 말고 테스트용 복사본만 사용하라”처럼 재료와 금지 조건을 함께 적는다.

에이전트가 제시한 계획에서 파일명, 저장 경로, 개인정보 처리, 테스트 항목을 확인하고 실행을 허용한다. 산출물은 Flask 코드와 HTML 화면, 의존성 파일, 실행 안내, 수정된 CSV 복사본이어야 한다. 마지막에는 잘못된 열 이름, 빈 셀, 한글 인코딩을 넣어 테스트하도록 요청한다.

이 과정에서는 구현보다 Artifacts와 diff 검토가 더 중요하다. 계획서와 코드 변경, 실행 결과를 사람이 확인할 수 있어야 업무 파일을 다루는 도구로 넘어갈 수 있다. 공식 문서 역시 에이전트가 작업 계획을 제시하고 승인을 받은 후 실행하는 방식을 기본으로 둔다. ([codelabs.developers.google.com](https://codelabs.developers.google.com/codelabs/getting-started-with-spec-driven-development-in-antigravity))

최신 버전도 완성품이라기보다 빠르게 고치는 제품이다

2026년 9월 18일 공개된 2.15.0은 대화 전환 속도와 사용자 지정 에이전트 제어를 개선했다. 프로젝트 밖에서 시작한 대화가 관계없는 파일을 불러오던 문제와 설정 및 프로젝트 목록이 덮어써지는 문제 등도 함께 수정했다. 사흘 앞선 2.14.0에서는 긴 대화의 메모리 사용량, 멈춘 하위 에이전트 표시, 일시적 서비스 오류 처리 등을 손봤다. ([antigravity.google](https://antigravity.google/changelog))

업데이트 내용에서 두 가지를 확인할 수 있다. Google은 빠른 속도로 불편을 고치고 있다. 그러나 프로젝트 문맥과 세션 상태처럼 개발 도구의 기본 요소도 아직 흔들릴 수 있다. 써본 사람들 사이에서 작업 완료 후 화면이 멈추거나 선택한 프로젝트와 다른 폴더를 참조한다는 불만이 나오는 배경이다.

무료 플랜은 모델 접근과 무제한 탭 완성·명령 요청을 제공하지만 에이전트 모델에는 주간 한도가 적용된다. Pro와 Ultra는 더 넉넉한 한도와 AI 크레딧 풀을 제공한다. 공식 페이지가 작업별 소비량을 단순한 고정 숫자로 제시하지 않으므로 유료 전환 전 `/usage`와 `/credits`로 자신의 실제 소모를 확인해야 한다. ([antigravity.google](https://antigravity.google/pricing))

Claude Code·Codex 대신 선택할 조건은 분명하다

Claude Code는 터미널과 기존 저장소를 중심으로 일하는 개발자에게 자연스럽다. Codex 역시 병렬 에이전트와 장시간 작업을 데스크톱 환경에서 관리하는 방향으로 발전했다. 이제 병렬 실행만으로 Antigravity를 고를 이유는 약하다. ([docs.anthropic.com](https://docs.anthropic.com/?utm_source=openai))

Antigravity의 차이는 여러 모델과 로컬 폴더, 대화, 예약 작업을 하나의 시각적 Project에 묶는 데 있다. 터미널 사용이 익숙하지 않거나 CSV 업무 도구처럼 화면을 확인하며 만드는 작업에는 이 구성이 유리하다. 반면 단일 저장소에서 정교한 리팩터링을 오래 수행한다면 익숙한 Claude Code나 Codex의 작업 방식이 더 단순할 수 있다.

Gemini 결과가 만족스럽지 않다는 이유만으로 Antigravity 전체를 버릴 필요는 없다. 다만 모델을 바꿔도 프로젝트 문맥 오류와 앱 안정성 문제가 반복된다면 남는 장점도 없다. Antigravity 2.0을 선택하는 기준은 Gemini에 대한 신뢰가 아니다. 여러 에이전트의 작업을 눈으로 나누고 검토하는 과정이 실제로 시간을 줄여주는지가 기준이다.

자주 묻는 질문

Q

Google Antigravity 2.0은 무료인가요?

개인용 무료 플랜이 있으며 여러 Gemini 모델과 Claude, gpt-oss-120b에 접근할 수 있습니다. 다만 에이전트 모델에는 주간 사용 한도가 적용됩니다.

Q

Antigravity에서 Claude 모델도 사용할 수 있나요?

공식 가격 페이지는 Claude Sonnet과 Opus 4.6을 지원 모델로 안내합니다. 계정과 플랜, 시점에 따라 제공 모델과 한도는 달라질 수 있습니다.

Q

Antigravity 2.0과 Antigravity IDE는 무엇이 다른가요?

2.0은 여러 프로젝트와 에이전트를 관리하는 독립 데스크톱 앱입니다. Antigravity IDE는 코드 편집기와 Agent Manager를 함께 제공하는 통합 개발 환경입니다.
