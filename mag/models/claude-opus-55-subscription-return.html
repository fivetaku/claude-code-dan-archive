Claude Opus 5.5, 느린데도 다시 구독할 만큼 좋아졌나

성능 향상과 넉넉해진 한도 뒤에 남은 속도·환불·리셋 문제를 실제 작업 기준으로 따져봤다

2026-09-28논의 1회 정리

Claude Opus 5.5 출시 뒤 Claude로 돌아갔다는 개발자도 있다. 반면 느린 응답과 불투명하게 느껴지는 사용량, 늦어진 환불 때문에 복귀를 망설이는 목소리도 나온다. 성능 향상만으로 다시 주력 도구가 될 수 있을지 따져봤다.

Opus 5.5는 무엇이 달라졌나

Anthropic은 2026년 9월 22일 Opus 5.5를 공개했다. 회사 발표에 따르면 Opus 5보다 출력이 30% 이상 빨라졌으며 일반적인 작업 비용은 약 40% 낮아졌다. API 가격도 입력 100만 토큰당 4달러, 출력 20달러로 내려갔다. (anthropic.com)

여기서 ‘Claude x5’는 모델명이 아니라 월 100달러인 Max 5x 요금제를 가리킨다. Pro보다 세션당 사용량이 다섯 배 많다. Opus 5.5 자체는 Pro·Max·Team·Enterprise에서 쓸 수 있다. 개인용 요금제는 Pro 20달러, Max 5x 100달러, Max 20x 200달러로 구분된다. (support.claude.com)

체감 향상은 단순히 답이 맞는가보다 작업을 끝까지 붙드는 능력에서 크게 나타났다. 복잡한 코드 수정에서 지시를 반복할 일이 줄었고 기획과 구현 사이의 빈틈도 먼저 채운다는 의견이 많았다. 글쓰기 방식이 간결해졌다는 반응 역시 공식 발표의 개선 방향과 겹친다.

다만 모든 평가가 압도적이지는 않다. SonarSource가 실행 가능한 HumanEval·MBPP 문제 544개를 시험한 결과 Opus 5.5의 통과율은 87.7%로, Opus 5의 88.6%보다 낮았다. Endor Labs의 보안 코드 생성 평가에서도 Fable 5.1에 뒤졌다. 작업 종류에 따라 이전 모델이나 GPT-6 Astra가 나을 수 있다는 경고다. (sonarsource.com)

공식 속도 향상과 느리다는 체감은 함께 성립한다

출력 속도가 빨라졌다는 발표와 작업이 답답하다는 평가는 모순이 아니다. 모델이 글자를 생성하는 속도와 Claude Code가 도구 실행을 기다리는 시간은 다르다. 테스트 실행이나 서버 응답 대기, 하위 에이전트 호출이 길어지면 화면에서는 모델이 멈춘 듯 보인다.

노력 수준도 큰 변수다. Anthropic은 긴 추론이 필요 없는 작업에서 effort를 낮추면 토큰과 한도를 아낄 수 있다고 안내한다. 써본 사람들 사이에서도 Medium은 빠르면서 수정 횟수가 적지만 High나 Max를 기본값으로 두면 간단한 변경까지 오래 걸린다는 반응이 갈렸다. (support.claude.com)

빠른 결과가 필요하면 Claude Code와 API의 Fast mode를 선택할 수 있다. 최대 2.5배 빠르지만 API 기준 입력 8달러, 출력 40달러로 기본 모드의 두 배다. 구독 한도 안에서 무조건 빨라지는 기능이 아니라 추가 비용과 맞바꾸는 선택지다. (anthropic.com)

실전에서는 Medium으로 탐색과 일반 구현을 진행하되 재현하기 어려운 버그나 대규모 리팩터링만 High로 올리는 방식이 맞는다. 느린 작업은 테스트나 외부 서비스가 끝나기를 기다리는지부터 확인해야 한다. 모델의 추론 지연과 도구 대기를 구분하지 않으면 요금제를 바꿔도 같은 문제가 반복된다.

사용량 리셋은 세 가지 시간을 구분해야 한다

Claude의 사용량은 Claude 채팅, Desktop, Claude Code가 한 계정에서 공유한다. 세션 한도는 소진한 뒤 5시간 단위로 돌아오며 Pro에는 별도의 주간 한도도 있다. 주간 한도는 사용을 시작한 시각이 아니라 계정에 지정된 고정 시각에 갱신된다. (support.claude.com)

Opus 5.5 출시와 함께 제공된 무료 limit reset은 정기 갱신과 다른 일회성 권리다. 웹이나 Claude Desktop의 Settings > Usage에서 직접 사용하면 세션 또는 주간 한도가 즉시 채워진다. 저장할 수 있지만 표시된 만료일이 있으며, 사용 전에 구독을 취소하거나 낮추면 사라진다. 터미널의 Claude Code에서는 버튼을 누를 수 없다. (support.claude.com)

그래서 “리셋이 늦다”는 현상을 하나의 장애로 단정하기는 어렵다. 5시간 세션과 고정된 주간 갱신, 직접 눌러야 하는 무료 리셋을 혼동했을 수 있다. 표시된 시각이 지났는데도 한도가 돌아오지 않았다면 계정과 시간대를 적어 지원팀에 조사를 요청해야 한다.

환불 요청과 구독 취소는 같은 절차가 아니다

Anthropic의 원칙은 법이나 약관에서 정한 경우를 제외하면 결제가 환불되지 않는다는 것이다. 웹 결제는 로그인 후 지원 메신저의 환불 절차에서 자격을 확인한다. iOS 결제는 Apple이 심사하며 환불 요청만으로 Claude 구독이 취소되지는 않는다. (support.claude.com)

지원은 실시간 채팅이 아니라 메신저와 이메일을 통한 비동기 방식이다. 답변 시간도 요금제와 문제의 심각도에 따라 달라진다. 환불이 처리되지 않았다는 경험만으로 일반적인 처리 기한을 정할 수 없는 이유다. (support.claude.com)

구독을 끊을 계획이라면 다음 결제 24시간 전에는 취소해야 한다. 취소 후에도 현재 결제 기간까지 유료 기능을 쓸 수 있다. 환불을 기다리는 동안 결제 갱신까지 막고 싶다면 환불 요청과 자동 갱신 취소를 각각 확인해야 한다.

GPT는 채팅, Opus는 긴 작업이라는 분업이 가능한가

GPT Pro를 대화와 빠른 조사에 남겨 두고 Claude Max 5x를 Claude Code 중심으로 쓰는 조합은 제품 충성도보다 작업 흐름에 가깝다. OpenAI에서도 일반 Chat의 모델 한도와 Work·Codex의 공유 사용량은 분리된다. 같은 Pro 구독이어도 채팅 사용과 에이전트 작업은 서로 다른 한도 체계를 따른다. (help.openai.com)

개인 개발자에게 Max 5x의 가치는 메시지 수가 아니라 중단 비용으로 계산해야 한다. 하루에 여러 저장소를 오가거나 하위 에이전트를 병렬로 돌린다면 넓어진 한도가 작업을 이어가게 해준다. 반대로 짧은 채팅과 간헐적인 수정이 대부분이라면 Pro에서도 Opus 5.5를 시험할 수 있다.

복귀 여부는 같은 실제 작업을 두 도구에 맡겨 확인하는 편이 정확하다. 완료 시간과 사람이 고친 횟수, 한도 소모량을 한 주 동안 기록하면 체감 성능을 비용으로 환산할 수 있다. Opus 5.5의 복귀 조건은 벤치마크 1위가 아니라 어려운 작업의 재시도 횟수를 실제로 줄이는지다.

자주 묻는 질문

Q

Claude Opus 5.5는 Pro 요금제에서도 사용할 수 있나요?

사용할 수 있다. 다만 Pro는 Max 5x보다 세션 사용량이 적고 별도의 주간 한도가 있어, 긴 Claude Code 작업에서는 먼저 한도에 도달할 수 있다.

Q

Claude Max 5x 사용량은 언제 리셋되나요?

세션 한도는 소진 후 5시간 단위로 갱신된다. 정기 리셋과 별도로 지급된 무료 limit reset은 Settings의 Usage 화면에서 직접 사용해야 한다.

Q

Opus 5.5가 느릴 때 Fast mode를 쓰면 되나요?

Fast mode는 최대 2.5배 빠르지만 API와 사용량 크레딧 비용이 높다. 먼저 effort를 Medium으로 낮추고 테스트나 외부 도구 대기 때문에 지연되는지 확인하는 편이 낫다.
