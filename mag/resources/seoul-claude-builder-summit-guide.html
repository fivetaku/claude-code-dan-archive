서울 Claude Fable 5.1 Build Day, 5시간 빌드의 실제 구조

발표 행사가 아닌 2시간 40분짜리 집중 제작전, 준비 순서와 100달러 크레딧의 실제 범위를 짚었다

2026-09-24논의 1회 정리

서울에서 열린 Claude Fable 5.1 Build Day를 두고 가장 많이 나온 질문은 단순했다. 다섯 시간 안에 무엇을 만들 수 있으며 제공되는 100달러 API 크레딧은 얼마나 버틸까. 공개 일정과 공식 문서를 맞춰 보면 핵심은 긴 개발보다 하나의 작동 경로를 빠르게 증명하는 데 있었다.

2025년 Builder Summit과 2026년 Build Day는 다른 행사다

검색 결과에는 이름이 비슷한 두 행사가 함께 나타난다. Anthropic의 Seoul Builder Summit은 2025년 3월 19일 시그니엘 서울에서 열린 공식 행사였다. Anthropic 발표와 한국 스타트업 사례, 프로덕션 활용법, 교류가 중심이었다.

Claude Fable 5.1 Build Day는 2026년 9월 23일 성수에서 열린 커뮤니티 주도 행사다. Anthropic이 후원했지만 무대 발표를 오래 듣는 콘퍼런스는 아니었다. 참가자가 Fable 5.1로 직접 결과물을 만들고 시연하는 형식이었다.

두 행사를 혼동하면 준비물부터 달라진다. Builder Summit이 정보와 관계 형성에 무게를 뒀다면 Build Day에는 노트북과 Claude Console Organization이 필요했다. 등록도 자동 확정이 아니라 신청 내용을 검토한 뒤 승인하는 방식이었다.

커뮤니티에서는 신청자가 많아 참가가 쉽지 않았다는 경험담도 나왔다. 다만 공개 페이지에는 정원이나 경쟁률이 표시되지 않아 수치로 확인할 수는 없다.

다섯 시간 가운데 실제 빌드 시간은 2시간 40분이다

행사는 오후 3시부터 8시까지 진행됐다. 오프닝과 모델 소개, 라이브 데모, 트랙 안내와 팀 편성에 먼저 50분이 배정됐다. 실제 빌드 시간은 오후 3시 50분부터 6시 30분까지였다.

참가자는 Delight, Breakthrough, Everyday 가운데 하나를 골랐다. 혼자 작업하거나 현장에서 2~4인 팀을 꾸릴 수 있었다. 제작 뒤에는 팀별 2분 데모와 제출, 시상, 단체 촬영이 이어졌다.

마지막 45분은 별도의 네트워킹 시간이었다. 팀을 구하는 과정에서도 자연스럽게 대화가 생기지만 제작 중 교류와 공식 네트워킹은 일정상 구분돼 있었다.

2시간 40분은 새 서비스를 설계하고 완성하기에는 짧다. 대신 입력 하나가 모델을 거쳐 눈에 보이는 결과로 나오는 수직 경로는 만들 수 있다. 로그인, 결제, 복잡한 권한 체계보다 핵심 효용 한 가지를 택해야 하는 구조다.

100달러 크레딧은 사용 시간이 아니라 토큰으로 계산된다

행사 페이지는 승인된 참가자의 Claude Console Organization에 100달러 상당 크레딧을 연결한다고 안내했다. Fable 5.1의 공식 API 가격은 입력 100만 토큰당 10달러, 출력 100만 토큰당 50달러다. 입력만 계산하면 1,000만 토큰이고 출력만 계산하면 200만 토큰이다.

실제 앱은 입력과 출력을 함께 쓴다. 입력 500만 토큰과 출력 100만 토큰을 사용하면 정가 기준 100달러다. 도구 호출을 반복하거나 큰 저장소를 계속 읽히면 같은 제작 시간에도 비용이 훨씬 빨리 늘어난다.

프롬프트 캐싱을 적용하면 반복해서 읽는 문맥의 비용을 낮출 수 있다. Fable 5.1의 캐시 읽기는 100만 토큰당 0.25달러다. 반대로 시스템 프롬프트나 앞선 대화를 중간에 고치면 캐시가 깨져 긴 문맥을 다시 써야 할 수 있다.

써본 사람들 사이에서는 낮은 effort로도 어려운 코딩이 잘 풀린다는 평가가 있었다. 높은 effort와 긴 에이전트 작업이 크레딧을 예상보다 빠르게 쓴다는 불만도 함께 나왔다. Anthropic 역시 일반 작업에는 Opus 5.5부터 검토하고 Fable 5.1은 고난도 추론과 장시간 에이전트 작업에 쓰도록 권한다.

행사 크레딧의 만료일은 공개 페이지에 적혀 있지 않다. 일반 구매 크레딧의 1년 만료 정책을 행사 지급분에 그대로 적용해서는 안 된다. 승인 메일과 Console의 Billing 화면에서 별도 조건을 확인해야 한다.

현장용 결과물은 입력과 출력 한 쌍부터 만든다

가장 안전한 준비 방식은 빈 폴더보다 실행되는 작은 저장소를 가져가는 것이다. 웹 앱이라면 화면 한 장과 서버 엔드포인트 하나, .env 파일을 준비한다. API 키는 환경변수에만 넣고 저장소에는 커밋하지 않는다.

그다음 Messages API에 claude-fable-5-1 모델을 지정한다. 사용자가 텍스트나 이미지를 넣으면 서버가 Claude API를 호출한다. 응답은 화면에 표시하거나 파일로 저장한다. 여기까지 작동해야 다음 기능을 붙일 수 있다.

현장에서는 세 단계면 충분하다. 먼저 예제 데이터 하나로 끝까지 실행한다. 이어 실패 사례를 한 번 고친다. 마지막으로 데모용 입력을 고정한다. 에이전트, MCP, 외부 검색은 핵심 경로가 안정된 뒤 추가해야 한다.

2분 시연도 제작 범위를 결정한다. 해결하려는 문제를 짧게 보여주고 실제 입력을 넣은 뒤 결과와 전후 차이를 제시하면 된다. 설명하지 못하는 기능은 시연에도 들어가기 어렵다.

Build Day의 성패는 모델보다 준비된 문제에서 갈린다

Fable 5.1은 100만 토큰 컨텍스트와 최대 12만8,000 토큰 출력을 지원한다. 그러나 넓은 컨텍스트가 모호한 아이디어를 제품으로 바꿔 주지는 않는다. 긴 자료를 가져오더라도 성공 조건과 샘플 입력이 없으면 작업 시간만 줄어든다.

개인 개발자와 소규모 팀에는 이 지점이 중요하다. 행사장에서 처음 문제를 정하면 팀 편성 뒤 남은 시간을 대부분 설계에 쓰게 된다. 실제 사용자 데이터의 익명 샘플과 원하는 출력 형식, 실패 기준을 미리 준비한 팀이 모델 성능을 더 정확히 시험할 수 있다.

서울 Build Day가 보여준 형식은 거대한 해커톤보다 압축된 모델 검증에 가깝다. 두 시간대의 빌드에서 남겨야 할 산출물은 기능 목록이 아니다. 다음 날 다시 실행해도 같은 문제를 푸는 한 개의 완성된 흐름이다.

자주 묻는 질문

Q

Claude Fable 5.1 Build Day에서는 실제로 몇 시간 개발하나요?

전체 일정은 5시간이지만 공개 시간표상 순수 빌드 시간은 2시간 40분입니다. 나머지는 모델 소개, 팀 구성, 데모와 네트워킹에 배정됐습니다.

Q

100달러 Claude API 크레딧으로 얼마나 사용할 수 있나요?

Fable 5.1 정가 기준으로 입력만 쓰면 1,000만 토큰, 출력만 쓰면 200만 토큰입니다. 실제 소진량은 출력 길이, 반복 호출, effort, 캐싱 여부에 따라 크게 달라집니다.

Q

Build Day 참가 전에 무엇을 준비해야 하나요?

Claude Console 계정과 Organization, 실행되는 작은 저장소, 환경변수 방식의 API 키 설정이 필요합니다. 샘플 입력과 성공 조건, 2분 데모 흐름까지 준비하면 현장 시간을 제작에 집중할 수 있습니다.
