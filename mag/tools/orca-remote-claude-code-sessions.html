Orca 원격 서버로 Claude Code 세션을 여러 기기에서 이어 쓰는 법

한 대의 컴퓨터에서 에이전트를 실행하고 노트북과 휴대전화에서 접속하려면, 어떤 설정이 필요하고 어디서 복잡해질까

2026-10-06논의 1회 정리

한 대의 컴퓨터에 Claude Code를 띄워 두고 다른 기기에서 같은 작업으로 돌아올 수 있을까? 멀티에이전트 IDE인 Orca를 써본 커뮤니티에선 이 방식의 편리함과 초기 설정의 부담이 함께 거론됐다. 핵심은 에이전트를 어디서 실행하고 어느 기기가 그 세션을 소유하는지다.

세션을 보존할 컴퓨터가 Orca 서버가 된다

Orca는 Claude Code 같은 CLI 에이전트를 프로젝트별 git worktree에서 실행하는 데스크톱 IDE다. 작업마다 별도 브랜치와 터미널을 두고 변경 사항은 diff 화면에서 검토한다. 자체 코딩 모델이나 호스팅 서버를 제공하는 제품은 아니다. (onorca.dev)

여러 기기에서 같은 실행 환경에 접속하려면 Remote Orca Server 구성을 쓴다. 서버 컴퓨터가 저장소, worktree, 터미널, 에이전트 프로세스와 세션 상태를 보유하고 노트북은 그 환경을 조작하는 클라이언트가 된다. 클라이언트를 닫아도 서버가 켜져 있으면 에이전트는 계속 실행된다. (onorca.dev)

방에서 여러 기기를 오가는 사람에게 잘 맞겠다는 의견이 나온 이유도 여기에 있다. 다만 ‘어느 기기에서나 접속’은 서버가 잠들어도 된다는 말이 아니다. Orca 공식 문서는 서버의 전원과 네트워크 연결이 유지돼야 한다고 명시한다. (onorca.dev)

Claude Code를 실행하기까지 필요한 설정

가장 단순한 공식 경로는 서버와 노트북에 Orca와 Tailscale을 각각 설치하는 것이다. 두 컴퓨터를 같은 사설 네트워크에 연결한 뒤 서버 Orca의 Settings → Remote Orca Servers에서 서버 공유를 켠다. New Link를 눌러 Tailscale 주소를 선택하고 접속 링크를 만든다. 노트북의 같은 설정 화면에서 Add Server를 선택해 그 링크를 등록한다. (onorca.dev)

이어서 서버 컴퓨터에 저장소와 Claude Code CLI를 준비하고 로그인한다. 노트북에서 인증한 계정이 서버로 자동 복사되지는 않는다. 연결된 서버의 프로젝트를 Orca에서 열고 작업공간을 만들면 Claude Code는 노트북이 아닌 서버에서 실행된다. 서버에 CLI가 없으면 클라이언트 화면만 연결해도 에이전트를 시작할 수 없다. (onorca.dev)

작업 입력과 산출물의 흐름도 구체적이다. 저장소를 추가하고 작업 이름을 붙여 worktree를 만든 다음 에이전트 선택 메뉴에서 Claude Code를 고른다. 예를 들어 로그인 오류의 재현 조건과 수정 범위를 프롬프트로 주면 에이전트가 해당 브랜치의 파일을 수정한다. 사용자는 Orca의 diff에서 바뀐 코드를 확인하고 피드백할 수 있다. 세 에이전트를 비교하려면 같은 기준 브랜치에서 worktree 세 개를 만들어 동일한 과제를 각각 입력한다. (onorca.dev)

화면 없는 컴퓨터에서는 데스크톱 앱 대신 orca serve로 서버를 실행할 수도 있다. 평소 쓰는 컴퓨터를 서버로 둘 계획이라면 앱에서 공유하는 경로가 더 간단하다. 공식 문서는 같은 호스트에서 앱 공유와 orca serve를 동시에 실행하지 말라고 안내한다. (onorca.dev)

진입장벽은 설치보다 프로젝트 위치에 있다

커뮤니티에서는 Orca의 프로젝트별 설정이 처음 접할 때 복잡하다는 의견이 나왔다. 실제로 원격 작업공간을 만들 때는 에이전트 이름만 고르는 것으로 끝나지 않는다. 서버에 그 프로젝트의 저장소가 어디 있는지 지정하고 새 worktree의 시작 브랜치도 확인해야 한다. 다른 기기에서 기존 폴더가 그대로 보일 것이라고 예상하면 여기서 막히기 쉽다. (onorca.dev)

Orca에는 비슷해 보이는 원격 방식이 하나 더 있다. SSH worktree는 노트북의 Orca가 실행 환경을 관리하면서 특정 작업만 원격 컴퓨터에서 돌린다. 반면 Remote Orca Server에서는 서버가 전체 세션 상태를 소유하고 여러 클라이언트가 다시 접속한다. 한 대의 메인 컴퓨터에 세션을 모으려는 이번 경우에는 후자가 질문에 더 직접적으로 답한다. (onorca.dev)

써본 사람들 사이에선 여러 호스트의 작업을 한곳에서 보는 점을 반기는 반응도 있다. 모바일 입력과 원격 화면의 사용감이 기대만큼 매끄럽지 않다는 의견도 나온다. 어느 쪽이든 접속 가능 여부와 작은 화면에서의 작업 편의는 다른 문제다.

휴대전화는 작업 상태를 보는 창에 가깝다

Orca의 iOS·Android 모바일 앱은 데스크톱 세션에 연결되는 동반 앱이다. 공식 문서는 이를 에이전트 상태 확인, 입력 요청에 대한 답변, 파일 탐색 등에 쓰는 읽기 중심 화면으로 설명한다. 휴대전화 안에서 별도의 클라우드 에이전트가 실행되는 구조는 아니다. 모바일 앱과 Remote Orca Server 기능은 모두 베타로 안내돼 있다. (onorca.dev)

서버 접근 링크는 세션을 조작할 권한과 연결된다. Orca는 클라이언트마다 취소 가능한 접근 권한을 만들며 공개 인터넷에 서버 포트를 직접 노출하지 말라고 권고한다. 에이전트를 시작하기 전에는 권한 설정도 확인할 필요가 있다. Orca 공식 문서에 따르면 새 에이전트 실행에는 승인 절차를 건너뛰는 옵션이 기본으로 채워질 수 있고 Settings → Agents → Agent Permissions에서 Manual로 바꿀 수 있다. (onorca.dev)

작은 팀이라면 편의 기능보다 이 운영 조건이 먼저 비용으로 돌아온다. 서버에 저장소와 도구를 유지하고 접속 권한을 관리해야 한다. 에이전트가 만든 diff를 검토할 사람도 필요하다. worktree가 분리돼 있어도 승인 없이 실행되는 명령까지 안전해지는 것은 아니다. (onorca.dev)

원격 접속만 필요하다면 Orca가 필수는 아니다

Claude Code 자체에도 Remote Control이 있다. Anthropic 문서에 따르면 로컬 세션을 휴대전화나 브라우저에서 이어 사용할 수 있으며 코드 실행과 파일 접근은 원래 컴퓨터에서 계속된다. 컴퓨터와 claude 프로세스가 실행 중이어야 한다는 점은 같다. 다만 Orca처럼 여러 종류의 에이전트와 worktree의 diff를 한 화면에서 관리하려는 목적과는 다르다. (code.claude.com)

VS Code Remote Tunnels도 원격 컴퓨터의 개발 환경에 브라우저나 다른 VS Code 클라이언트로 접속하는 방법이다. 기존 편집기를 유지하며 원격 파일을 다루는 일이 주목적이라면 비교할 만하다. 반대로 Claude Code와 다른 에이전트의 작업 브랜치를 나눠 실행하고 검토하려면 Orca의 구조가 더 맞는다. (code.visualstudio.com)

따라서 판단을 가르는 질문은 ‘휴대전화에서도 열리나’가 아니다. 한 세션을 이어 쓰고 싶은가, 아니면 여러 에이전트가 만든 서로 다른 변경 사항까지 한곳에서 운영하고 싶은가? 전자만 필요하면 Claude Code의 기능으로도 시작할 수 있다. Orca의 설정 부담은 후자를 선택할 때 비로소 대가를 치를 이유가 생긴다. (code.claude.com)

자주 묻는 질문

Q

Orca Remote Orca Server를 쓰려면 Claude Code를 어느 컴퓨터에 설치해야 하나요?

에이전트가 실제 실행되는 서버 컴퓨터에 Claude Code CLI를 설치하고 인증해야 합니다. 클라이언트 노트북의 로그인 상태는 서버로 자동 이전되지 않습니다.

Q

Orca의 SSH worktree와 Remote Orca Server는 무엇이 다른가요?

SSH worktree는 클라이언트 Orca가 실행 환경을 관리하면서 원격 컴퓨터에서 선택한 작업을 실행합니다. Remote Orca Server는 원격 컴퓨터가 프로젝트와 세션 상태 전체를 보유하므로 여러 클라이언트의 재접속에 적합합니다.

Q

Claude Code Remote Control만으로도 휴대전화에서 작업을 이어갈 수 있나요?

가능합니다. Anthropic 문서에 따르면 로컬 Claude Code 세션에 휴대전화나 브라우저로 접속할 수 있지만, 원래 컴퓨터와 Claude Code 프로세스는 계속 실행 중이어야 합니다.
