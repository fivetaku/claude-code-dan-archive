sprite-gen 사용법, 이미지 한 장을 게임 스프라이트로

이미지 생성과 게임 에셋 완성은 다르다. sprite-gen의 프레임 추출·검수·아틀라스 출력 과정을 따라 실제 적용 조건을 살핀다.

2026-11-11논의 1회 정리

사진이나 그림 하나로 게임 캐릭터의 동작까지 만들 수 있을까. 클코단에서는 이 질문을 계기로 sprite-gen의 출력 형식과 사용 방식에 관심이 모였다. 공식 프로젝트는 이미지 생성부터 프레임 추출까지 연결한다. 그렇다면 한 장을 움직이게 만드는 과정에서 무엇이 자동화되고 무엇을 사람이 확인해야 할까. (github.com)

sprite-gen은 그림보다 게임에 전달할 파일을 만든다

방에서는 sprite-gen을 코드를 대신 작성하는 제품보다 에셋 제작용 스킬과 Python CLI로 이해하는 설명이 나왔다. 공식 README도 기준 이미지에서 동작별 이미지를 생성하고 배경을 제거한 뒤 프레임을 추출하는 도구로 소개한다.

다만 사진을 넣으면 원하는 화풍과 정확한 동작까지 반드시 완성된다는 보장은 확인되지 않는다. (github.com)

스프라이트 시트는 여러 애니메이션 프레임을 모은 이미지다. sprite-gen의 주요 산출물은 투명 배경의 sprite-sheet-alpha.png와 manifest.json이다. 후자의 frame_layout에는 프레임 영역과 상태별 FPS, 반복 여부가 들어간다. 그림만 전달하는 대신 게임이 어디를 잘라 어떻게 재생할지 함께 넘기는 구조다. (github.com)

두 파일은 역할이 다르다. PNG는 캐릭터의 모습을 담고 manifest는 재생에 필요한 좌표와 규칙을 담는다. 방에서 관심을 보인 아틀라스 출력의 실익도 이 구분에 있다. 격자처럼 보이는 이미지와 프로그램이 읽을 수 있는 에셋 묶음은 같지 않다. (github.com)

기준 이미지에서 아틀라스까지 네 단계

공식 빠른 시작에서는 저장소를 내려받은 디렉터리에서 Python 가상환경을 만들고 pip install -e .로 설치한다. 현재 README가 명시한 최소 버전은 CPython 3.11이다. 설치 후 sprite-gen --help로 명령 구성을 확인할 수 있다. (github.com)

예를 들어 기준 그림을 base.png, 결과 폴더를 run으로 정한다. sprite-gen prepare --out-dir run --character-id hero --base-image base.png는 요청 파일과 상태별 배치 가이드, 생성 프롬프트를 준비한다. 이어 sprite-gen gen-set --run-dir run --provider codex가 상태별 원본 이미지를 생성한다. 여기서 hero와 run은 예시 이름이다. (github.com)

그다음 sprite-gen extract --run-dir run으로 배경을 제거하고 프레임을 분리한다. sprite-gen compose-atlas --run-dir run을 실행하면 최종 시트와 manifest를 조합한다. 공식 실행 계약은 준비·생성·추출·조합을 별도 단계로 구분한다. 추출 실패 시에는 실패 보고서를 남기도록 정의한다. (github.com)

이 구조라면 작은 팀도 어느 단계에서 결과가 틀어졌는지 나눠 살펴볼 수 있다. 포즈 자체가 잘못됐는지, 배경 제거가 실패했는지, 선택한 프레임이 잘못됐는지를 같은 문제로 취급하지 않아도 된다. 단계별 입력과 출력을 분리한 설계의 실무적 이점이다. (github.com)

영상에서 동작을 추출하는 경로는 별개다

방에서 함께 언급된 투명 GIF와 WebP는 영상 기반 경로의 산출물이다. 공식 문서는 정지 이미지에 여백을 마련하고 영상을 생성한 뒤 프레임과 반복 구간을 추출하는 순서를 설명한다. 아틀라스용 상태 이미지를 만드는 과정과 혼동하면 안 된다. (raw.githubusercontent.com)

공식 예시는 sprite-gen video-set --base side=still.png --states idle,walk,run,jump,attack --out-dir set/이다. 측면 그림 still.png를 받아 대기·걷기·달리기·점프·공격을 처리한다. 결과 위치는 set/table.md에 정리된다. 영상 생성에는 Grok Imagine을 사용하고 관련 실행에는 ffmpeg와 img2webp 등이 필요하다. (github.com)

오픈소스 도구라는 사실과 생성 비용은 구분해야 한다.

sprite-gen 생성 문서는 외부 제공자를 선택하는 구조를 설명하며 API 키를 통한 호출은 과금될 수 있다고 명시한다. 로컬에서 CLI를 실행한다고 생성 모델까지 로컬에서 무료로 돌아가는 것은 아니다. (github.com)

영상 경로도 단순히 일정 간격으로 화면을 잘라 붙이는 데 그치지 않는다. 문서는 반복 동작의 주기 탐색과 일회성 동작 구간 추출을 구분한다. 점프나 공격을 걷기처럼 무조건 반복시키지 않는 이유를 이해해야 출력물을 게임 상태에 맞게 선택할 수 있다. (raw.githubusercontent.com)

프레임 선택과 동작 검수는 여전히 필요하다

자동 생성이 끝났다고 채택할 프레임까지 결정된 것은 아니다. sprite-gen curation --run-dir run은 프레임을 고르고 순서를 바꾸거나 위치를 조정하는 검수 화면을 연다. 공식 큐레이션 문서에 따르면 선택과 변환은 curation.json에 저장되며 원본 프레임 PNG는 그대로 남는다. (github.com)

파일을 게임 프로젝트로 옮길 때는 이 차이에 유의해야 한다. 실행 계약은 frames/를 직접 복사하면 사람이 수정한 내용이 빠질 수 있다고 경고한다. 애니메이션에는 큐레이션을 반영해 다시 조합한 시트와 manifest를 사용해야 한다. 개별 이미지가 필요하면 별도의 큐레이션 반영 내보내기를 거쳐야 한다. (github.com)

걷는 모습은 정지 화면만으로 판정할 수 없다.

README는 걷기와 달리기를 동작 QA 통과 전까지 실험적으로 취급한다고 명시한다. 방향을 요청하는 프롬프트도 결과를 보장하지 않는다. 방향 감지 역시 틀릴 수 있다고 설명한다. 방에서 출력 기능을 확인했다고 해서 모든 캐릭터의 동작 품질이 검증됐다고 평가할 근거는 없다. (github.com)

최근 개선도 이러한 후처리에 집중돼 있다. 공개 릴리스 목록의 v3.15.0은 중간 프레임 생성에 쓰는 RIFE 기본 모델 변경을 안내한다. 해당 보간이 적용되는 작업은 결과 프레임이 달라질 수 있다는 설명도 붙었다. 이미 채택한 에셋을 재생성할 때는 도구 버전 변화도 비교 조건에 포함해야 한다. (github.com)

엔진에 넣기 전 확인할 출력 형식

Aseprite 공식 문서는 스프라이트 시트와 JSON 메타데이터 내보내기를 안내한다. sprite-gen도 sprite-gen export-aseprite --run-dir run으로 Aseprite 로더가 읽는 JSON을 만들 수 있다. 다만 프로젝트 문서는 편집 가능한 .aseprite 원본 파일을 만드는 기능이 아니라고 명확히 구분한다. (aseprite.org)

Phaser나 Flame용 연동 경로가 있다고 모든 엔진이 sprite-gen manifest를 그대로 읽는 것은 아니다. Godot 공식 튜토리얼은 AnimatedSprite2D에 SpriteFrames를 만들고 개별 이미지나 시트에서 프레임을 추가하는 절차를 안내한다. 규칙적인 시트는 행과 열을 지정할 수 있지만 sprite-gen의 좌표 정보를 자동으로 가져오는 별도 기능까지 확인된 것은 아니다. (raw.githubusercontent.com)

이번 사례에서 확인한 sprite-gen의 강점은 단 한 번의 생성으로 제작을 끝내는 데 있지 않다. 기준 그림을 생성 입력으로 쓰고 검수한 프레임을 좌표·속도·반복 정보와 함께 전달하는 연결 과정에 있다.

한 장의 이미지가 게임 에셋이 되는 시점은 그림이 움직일 때가 아니라, 선택한 동작을 엔진에서 의도대로 재생할 때다. (github.com)

자주 묻는 질문

Q

sprite-gen은 어떤 파일을 출력하나요?

아틀라스 경로는 투명 PNG 시트와 프레임 좌표·FPS·반복 정보를 포함한 manifest를 출력합니다. 영상 경로에서는 투명 GIF·WebP와 프레임 스트립을 만들 수 있습니다. (github.com)

Q

sprite-gen 결과를 Aseprite에서 바로 편집할 수 있나요?

export-aseprite는 Aseprite 호환 로더를 위한 JSON을 출력합니다. 편집 가능한 .aseprite 원본을 생성하는 기능은 아닙니다. (raw.githubusercontent.com)

Q

sprite-gen으로 만든 걷기 애니메이션은 검수 없이 써도 되나요?

공식 README는 걷기와 달리기를 동작 QA 통과 전까지 실험적으로 취급합니다. 프레임을 연속 재생하면서 캐릭터 형태와 동작 연결을 확인하는 과정이 필요합니다. (github.com)
