insane-search로 네이버 쇼핑 커넥트 상품을 찾을 때 확인할 것

크롤링이 성공해도 제휴 가능한 상품과 발행할 콘텐츠는 따로 확인해야 한다. 플러그인 변경 이력부터 공식 상품 탐색 절차까지 짚었다.

2026-10-06논의 1회 정리

insane-search로 상품 정보를 모으면 네이버 쇼핑 커넥트의 블로그 소싱까지 자동화할 수 있을까? 크롤링에 성공했다는 경험담 뒤에는 플러그인 기능 변경과 제휴 상품 확인이라는 별개의 문제가 남는다. 공개 페이지를 읽는 일부터 발행할 상품을 고르는 일까지 어디를 자동화할 수 있는지 살펴봤다.

크롤링 성공과 제휴 상품 확보는 다른 단계다

커뮤니티에서는 insane-search로 쇼핑 블로그용 상품 자료를 모았다는 경험이 공유됐다. 수집이 어려워진 사이트가 늘었다는 의견도 있었다. 자료를 쌓고 정리하는 작업은 Comet보다 Claude Code가 낫다는 선호도 나왔다. 어느 사이트에서 어떤 항목을 얼마나 수집했는지는 확인되지 않았다.

네이버 브랜드 커넥트 고객센터에 따르면 쇼핑 커넥트의 ‘상품 찾기’에는 판매자가 제휴 대상으로 등록한 상품이 표시된다. 네이버 쇼핑에서 검색되는 모든 상품이 여기에 들어오는 것은 아니다. 공개 상품 페이지에서 이름과 가격을 읽더라도 해당 상품의 제휴 링크를 발급할 수 있다는 보장은 없다. (help.naver.com)

쇼핑 커넥트는 크리에이터가 상품 전용 링크를 발급하고 그 링크를 통한 판매 실적에 따라 수수료를 받는 구조다. 수수료는 상품마다 달라질 수 있다. 소싱 목록에는 검색 결과의 인기 순위뿐 아니라 실제 링크 발급 가능 여부와 제휴 조건도 중요하다. (brandconnect.naver.com)

insane-search에서 없어진 기능은 무엇인가

insane-search는 Claude Code가 공개 웹페이지를 읽지 못할 때 다른 접근 경로를 시도하는 플러그인이다. 저장소의 현재 안내에 따르면 공개 엔드포인트와 피드, 브라우저 방식 등을 단계적으로 시도한다. 로그인이나 유료 접근이 필요한 페이지에서는 멈추도록 설계됐다고도 밝힌다. (github.com)

변경 이력에는 중요한 경계가 있다. 개발자는 2026년 8월 6일 공개한 0.14.0에서 내부·비공개 API 발굴 기능과 사이트별 레시피를 제거했다. 변경 이력에는 범위를 공식 공개 API, 피드, 메타데이터와 범용 접근 방식으로 좁혔다고 적혀 있다. ‘예전에는 되던 수집이 이제 안 된다’는 이야기를 모든 사이트의 차단 강화로만 해석할 수 없는 이유다. (github.com)

다만 저장소의 한국어 소개에는 내부 JSON API를 찾는다는 이전 설명도 남아 있다. 현재 기능을 판단할 때는 이 문구보다 삭제 항목을 구체적으로 적은 변경 이력을 기준으로 읽는 편이 정확하다. 구버전을 보관하자는 커뮤니티 의견은 작업 환경을 기록하자는 취지로 이해할 수 있지만, 구버전으로 제거된 수집 방식을 계속 써도 된다는 근거는 아니다. (github.com)

써본 사람들 사이에서는 막힌 페이지에 재시도 경로가 생기는 점을 반기면서도 수집 도구를 완전한 브라우저 작업이나 대량 수집의 대체재로 여기지 않는 반응이 있다. 플러그인 개발자 역시 자동 접근의 허용 여부와 사이트 약관 준수는 사용자 책임이라고 명시한다. 공개 페이지라고 해서 자동 수집까지 허용된다고 단정할 수는 없다. (github.com)

후보 목록은 어떻게 만들고 검증하나

작업은 두 갈래로 나누는 게 명확하다. 먼저 Claude Code에서 개발자가 안내한 마켓플레이스를 추가하고 insane-search@gptaku-plugins를 설치한다. 관심 상품군의 공개 페이지를 읽어 상품명, 확인한 페이지 주소, 표시 가격, 확인 시각을 후보 목록으로 정리하도록 요청한다. 플러그인은 접근과 읽기를 돕지만 쇼핑 커넥트의 제휴 자격을 판정하지는 않는다. (github.com)

다음에는 브랜드 커넥트의 ‘쇼핑 커넥트 > 상품 찾기’에서 후보를 직접 검색한다. 목록에 있는 상품만 링크 발급 가능 여부와 표시된 조건을 확인해 남긴다. 네이버 고객센터가 안내하는 링크 발급 장소도 이 메뉴다. 공개 검색 결과의 상품명과 제휴 상품의 이름이 비슷하다면 같은 상품인지 판매 정보까지 대조해야 한다. (help.naver.com)

이때 Claude Code에 넣을 입력은 검증을 마친 후보 목록이다. 예를 들어 상품명·공개 페이지 주소·확인 날짜·커넥트 등록 확인 여부·발급한 링크 열을 가진 CSV를 준비한다. Claude Code에는 중복 상품을 묶고 등록 여부가 비어 있는 행을 따로 표시하며 블로그 글감 후보표를 만들도록 요청할 수 있다. 빈칸을 추정으로 채우지 말고 ‘미확인’으로 남기게 하는 것이 핵심이다.

Comet보다 Claude Code가 낫다는 의견도 이 지점에서 의미가 있다. 어느 도구가 데이터를 더 정확하게 수집한다는 검증 결과는 아니다. 다만 CSV처럼 검토 가능한 산출물을 남기면 후보를 고른 근거와 이후 수정 내역을 확인하기 쉽다. 수집 결과를 곧바로 발행 원고로 취급하지 않을 수 있다.

수집한 가격과 제휴 링크는 어떻게 다뤄야 하나

상품 자료는 빨리 낡는다. 후보를 모은 시점의 가격과 판매 상태를 발행 시점의 사실처럼 쓰면 오류가 생길 수 있다. 블로그 글에는 확인한 상품 정보만 반영하고 링크는 쇼핑 커넥트에서 발급한 것을 사용해야 한다. 네이버는 링크 변조, 게시물과 무관한 상품 연결, 과장되거나 잘못된 상품 설명을 제재 대상 행위로 안내한다. (help.naver.com)

제휴 사실도 빠뜨릴 수 없다. 네이버의 링크 삽입 가이드는 판매에 따른 수수료를 받을 수 있다는 경제적 이해관계를 콘텐츠에 표시하도록 안내한다. 공정거래위원회 역시 판매 실적에 따라 대가를 받는 추천글을 경제적 이해관계 공개가 필요한 사례로 설명했다. 상품 후보표의 마지막 검토 항목에 링크와 광고 표시를 함께 두어야 하는 이유다. (help.naver.com)

공식 데이터 경로를 대안으로 생각했다면 날짜도 확인해야 한다. 네이버 개발자센터는 기존 검색 ‘쇼핑’ API의 종료 적용일을 2026년 7월 31일로 공지했다. 반면 쇼핑인사이트 API 문서는 분야별·키워드별 검색 클릭 추이를 제공한다고 설명한다. 클릭 추이와 쇼핑 커넥트 제휴 가능 상품 목록은 서로 다른 데이터다. (developers.naver.com)

insane-search가 맡을 수 있는 일은 공개 자료에서 후보를 찾는 데까지다. 실제 발행 가능한 목록은 쇼핑 커넥트의 등록 상품, 발급 링크, 최신 상품 정보가 결정한다. 크롤링이 한 번 성공했다는 경험보다 중요한 기록은 후보가 그 검증 단계를 통과했는지 여부다.

자주 묻는 질문

Q

insane-search가 쇼핑 커넥트 제휴 상품을 자동으로 찾아주나요?

공개 상품 페이지를 읽어 후보를 조사하는 데 쓸 수 있습니다. 제휴 등록과 링크 발급 가능 여부는 브랜드 커넥트의 ‘상품 찾기’에서 별도로 확인해야 합니다.

Q

insane-search 구버전에는 어떤 기능이 있었나요?

프로젝트 변경 이력에 따르면 내부·비공개 API 발굴 기능과 사이트별 레시피가 0.14.0에서 제거됐습니다. 구버전 보관이 제거된 수집 방식의 사용 허가를 뜻하지는 않습니다.

Q

쇼핑 커넥트 링크를 블로그에 넣을 때 무엇을 표시해야 하나요?

네이버 가이드는 링크를 통한 판매로 수수료를 받을 수 있다는 경제적 이해관계를 표시하도록 안내합니다. 상품 설명과 링크도 발행 전에 다시 확인해야 합니다.
