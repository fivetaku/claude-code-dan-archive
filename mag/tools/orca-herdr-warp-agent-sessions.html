Orca·herdr·Warp 비교: 병렬 에이전트와 세션 관리

터미널을 바꾸면 에이전트 관리도 쉬워질까. Ghostty 조합부터 독립 앱까지, 가독성과 세션 유지 방식으로 선택 기준을 나눈다.

2026-11-21논의 2회 정리

여러 코딩 에이전트를 함께 쓰는 환경에서 어떤 터미널이 작업을 놓치지 않고 읽기 편하게 해줄까. 클코단에서는 Orca의 기능, Warp의 편의성, Ghostty와 herdr 조합을 놓고 경험이 갈렸다.

공식 문서를 대조하면 화면 취향뿐 아니라 작업·대화·실행 상태를 어떻게 분리하느냐가 선택을 가른다.

같은 후보 목록에 있지만 맡는 역할은 다르다

Ghostty 공식 문서는 제품을 창·탭·분할 화면과 GPU 렌더링을 제공하는 터미널로 설명한다. herdr TUI는 그 터미널 안에서 작업 공간과 에이전트를 관리한다. Ghostty와 herdr를 함께 쓴다는 말은 같은 기능을 중복 설치한다는 의미가 아니다. 화면을 표시하는 앱과 그 안의 작업 관리 도구를 조합하는 방식이다. (ghostty.org)

Orca는 저장소와 Git worktree, 에이전트, 변경 사항 검토를 묶는다. Warp도 터미널에 자체 에이전트와 외부 CLI 에이전트 지원을 결합한다. 세 제품을 단순히 터미널 속도 순으로 줄 세우면 실제로 필요한 기능의 차이가 사라진다. (orca.dev)

클코단에서는 Orca의 기능을 높이 평가하면서도 문자 중심 화면을 읽기 어렵다는 의견이 나왔다. 다른 참여자는 Warp를 더 편하고 안정적으로 느꼈다. 다만 대화에는 동일한 장비와 작업으로 측정한 결과가 없다. 이를 안정성 순위로 확대할 근거는 없다.

Ghostty와 herdr는 작업 상태를 모아 보여준다

방에서 언급한 조합을 재현하려면 herdr의 TUI 문서를 기준으로 삼아야 한다. 공식 빠른 시작에 따르면 설치 후 Ghostty에서 프로젝트 디렉터리로 이동해 herdr를 실행한다. 작업 공간이 없으면 하나가 자동으로 생긴다. 프로젝트마다 별도 공간을 두도록 안내한다. (herdr.dev)

패널에서 opencode 같은 지원 에이전트를 실행하고 작업 요청을 입력한다. 다른 작업은 새 탭이나 분할 패널에서 실행한다. 기본 키 설정에서는 Ctrl+B 다음 C로 탭을 만들고 V로 오른쪽을 분할한다. 사이드바에는 작업 중·입력 대기·완료 등의 상태가 표시된다. (herdr.dev)

이 구성의 산출물은 새로운 AI 모델이 아니라 여러 실행 상태를 모아 놓은 작업 화면이다.

개인 개발자에게 중요한 비교 항목도 패널 개수보다는 개입할 작업을 얼마나 쉽게 찾는지다. 입력을 기다리는 작업과 실행 중인 작업을 구분하는 기능이 그 판단을 돕는다. (github.com)

현재 herdr에는 별도의 네이티브 앱도 있다. 공식 홈페이지는 기존 Herdr TUI와 새 앱이 서로 다른 프로그램이며 실행 중인 에이전트를 공유하지 않는다고 명시한다. 새 앱을 설치했는데 기존 작업이 나타나지 않는 현상을 곧바로 세션 유실로 판단하면 안 된다. (herdr.dev)

clear는 새 작업 공간을 만드는 명령이 아니다

클코단에서 답이 남지 않은 질문은 herdr를 계속 비우면서 사용하는지, 새 세션을 만드는지였다. 여기에는 서로 다른 세 가지 동작이 겹쳐 있다. 화면 지우기, 에이전트 대화 초기화, herdr 실행 공간 분리는 같은 작업이 아니다.

ncurses의 clear 매뉴얼은 이 명령을 터미널 화면과 지원되는 스크롤 기록을 지우는 기능으로 설명한다. 새 herdr 세션을 만들거나 에이전트 대화를 초기화하는 기능은 아니다.

반면 Orca의 구조화된 Chat UI에서 /clear는 같은 패널에 새 대화를 시작하고 이전 대화를 이력에 남긴다. 실행하는 위치까지 확인해야 의미가 정해진다. (invisible-island.net)

herdr 공식 에이전트 가이드에서 세션은 백그라운드 서버의 독립 실행 영역이다. herdr session attach work처럼 이름을 지정하면 기본 세션과 분리된 영역을 사용한다. 문서는 대부분 기본 세션이면 충분하다고 설명한다. 저장소·작업·조사별 구분에는 워크스페이스를 쓰도록 안내한다. (github.com)

화면이 복잡해졌다는 이유만으로 실행 영역 전체를 새로 만들 필요는 없다.

공식 구조에서 프로젝트를 구분할 때는 워크스페이스를 쓴다. 이전 대화의 영향을 없애려면 사용하는 에이전트의 대화 기능을 쓴다. 방의 질문만으로 실제 어떤 의미의 clear였는지는 확인할 수 없다. 특정 사용 습관도 단정할 수 없다. (github.com)

Orca의 비교 기준은 작업 분리와 검토

Orca를 TUI 전용 제품으로 설명하는 것은 현재 공식 문서와 다르다. Orca는 xterm.js 기반 터미널뿐 아니라 지원 에이전트용 Chat UI도 제공한다. 설정에서 에이전트별 Chat 또는 CLI를 선택하고 채팅 글자 크기와 폭도 조정할 수 있다. 문자 화면이 부담스럽다는 경험과 제품 전체의 화면 선택지는 구분해야 한다. (orca.dev)

실제 사용 순서는 저장소 추가, worktree 생성, 에이전트 선택, 작업 입력, diff 검토다.

Orca의 첫 세션 안내는 같은 요청을 별도 worktree의 에이전트들에게 주는 비교 방법을 제시한다. 입력은 동일한 작업 요청이고 산출물은 각 브랜치의 변경 사항이다. 별도 파일 경로에서 작업하므로 같은 체크아웃을 동시에 수정하는 문제를 줄인다. (orca.dev)

소규모 팀이라면 이 차이는 화면 배치보다 검토 과정에서 드러난다. 수정안별 브랜치와 diff를 유지하면 결과를 단위별로 비교할 수 있다. 다만 worktree를 나눈 사실만으로 변경 사항의 정확성까지 검증되지는 않는다. Orca의 안내 역시 실행 다음 단계에 diff 검토를 둔다. (orca.dev)

Warp와의 차이는 표시 위치와 복원 조건에서 드러난다

Warp 공식 문서는 외부 CLI 에이전트에 입력 편집기, 알림, 코드 리뷰 등을 제공한다고 설명한다. 다만 외부 에이전트는 Warp 자체 대화 목록이나 Agent Management Panel에 나타나지 않는다. 실행 중인 패널과 세로 탭에서 상태를 확인한다. 관리 패널이 있다는 이유만으로 모든 에이전트가 한 목록에 모인다고 기대하면 실제 사용과 어긋난다. (docs.warp.dev)

화면을 닫은 뒤 무엇이 남는지도 비교해야 한다.

herdr TUI 공식 문서에서는 Ctrl+B 다음 Q로 연결을 끊어도 서버와 프로세스가 계속 실행된다. 다시 herdr를 실행하면 돌아온다. 하지만 서버 자체를 재시작하면 원래 프로세스는 종료된다. 레이아웃 복원과 에이전트 대화 재개는 각각 별도 조건을 따른다. (herdr.dev)

새 herdr 앱도 창 종료와 컴퓨터 재부팅을 구분한다. 앱을 닫아도 herdr-core에서 실행은 이어지지만 재부팅이나 core 종료 후에는 프로그램이 멈춘다. 패널이 돌아온다고 에이전트의 진행 중 작업까지 자동 재개되는 것은 아니다. (herdr.dev)

클코단에는 데스크톱 앱의 표현 방식이 더 읽기 편하고 피로가 덜하다는 의견도 있었다. 이 경험을 모든 사용자에게 적용할 수는 없지만 이번 비교의 질문에는 분명한 답을 준다. 선택할 대상은 터미널 이름 하나가 아니라 읽을 화면과 작업을 나눌 단위, 중단 뒤 되살릴 상태의 조합이다.

자주 묻는 질문

Q

Ghostty와 herdr는 함께 사용하는 도구인가?

Ghostty는 터미널 앱이고, herdr TUI는 그 안에서 작업 공간과 에이전트를 관리한다. 따라서 함께 사용할 수 있으며, 별도로 제공되는 herdr 네이티브 앱과는 구분해야 한다. (ghostty.org)

Q

herdr에서 clear를 실행하면 새 세션이 생기나?

셸의 clear는 화면을 지우는 명령이지 herdr 세션 생성 명령이 아니다. herdr의 독립 세션과 워크스페이스, 에이전트의 대화 초기화는 서로 다른 기능이다. (invisible-island.net)

Q

Orca는 터미널 화면으로만 사용해야 하나?

현재 Orca는 터미널과 지원 에이전트용 Chat UI를 제공한다. 에이전트별로 Chat 또는 CLI를 선택할 수 있지만, 세션 유형에 따라 지원 범위가 다르다. (orca.dev)
