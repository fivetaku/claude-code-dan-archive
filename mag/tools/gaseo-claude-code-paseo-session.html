가세오는 왜 Claude Code 세션을 Paseo로 옮기는가

터미널에서 시작한 작업을 모바일로 이어가는 플러그인, 가세오의 설치법과 쓰임새·한계를 살펴봤다

2026-09-20논의 1회 정리

터미널에서 Claude Code와 한참 작업하다 자리를 떠나야 한다면 같은 대화를 휴대전화에서 이어갈 수 있을까. Anthropic이 이 문제를 다루는 가운데 가세오는 이미 실행 중인 세션을 Paseo에 등록하는 좁고 구체적인 해법을 제시한다. 새 에이전트를 띄우는 도구가 아니라 터미널과 원격 관제 화면 사이의 빠진 연결고리를 메우는 플러그인이다.

가세오는 새 세션을 만들지 않고 기존 대화를 연결한다

Paseo는 로컬 컴퓨터나 서버에서 Claude Code, Codex 등 여러 코딩 에이전트를 실행하고 관리하는 오픈소스 관제 도구다. 데스크톱과 모바일, 웹, CLI에서 작업을 확인하고 메시지를 보내며 변경 사항을 검토할 수 있다. 에이전트가 실제로 코드를 읽고 명령을 실행하는 장소는 사용자의 호스트다.

문제는 Paseo 밖에서 먼저 시작한 대화다. 평소처럼 프로젝트 폴더에서 `claude`를 실행한 세션은 Paseo가 직접 생성한 에이전트 목록에 자동으로 나타나지 않는다. 가세오는 현재 Claude Code 세션의 식별자를 찾아 `paseo import`에 넘긴다. 그러면 Paseo에서 같은 대화를 계속 열 수 있다.

저장소 설명에 따르면 대화 기록을 복사하거나 옮기지는 않는다. Paseo 쪽 레코드가 Claude Code 세션 ID를 가리키도록 연결한다. 등록 이후 Paseo에서 보관 처리해도 Claude Code가 만든 원본 대화 파일은 그대로 남는다.

커뮤니티에서는 Paseo를 본격적으로 설정하기 전에 가세오부터 시험해 보겠다는 반응이 나왔다. 기능 범위가 작아 사용 목적을 바로 이해할 수 있다는 점이 관심을 끈 셈이다. 이름에서 파생된 사세오·오세오 같은 표현도 나왔지만 확인된 제품이나 출시 계획은 아니다.

설치 후 `/gaseo`를 실행하면 현재 세션이 등록된다

가세오는 Claude Code 플러그인으로 배포된다. 먼저 Claude Code 안에서 플러그인 마켓플레이스를 추가한다.

/plugin marketplace add https://github.com/fivetaku/gptaku_plugins.git

이어서 플러그인을 설치하고 Claude Code를 재시작한다.

/plugin install gaseo

새 명령은 재시작 뒤 등록된다. Paseo 데몬이 실행 중이고 `paseo` CLI가 PATH에 잡혀 있다면 작업하던 대화에서 아래 명령을 입력한다.

/gaseo

가세오는 현재 폴더에 대응하는 Claude Code 세션 디렉터리를 찾는다. 우선 `$CLAUDE_CODE_SESSION_ID`와 일치하는 기록을 확인한다. 찾지 못하면 가장 최근에 수정된 `.jsonl` 파일을 후보로 삼는다. 선택한 세션의 첫 메시지도 보여주므로 사용자는 엉뚱한 대화가 잡히지 않았는지 확인할 수 있다.

과거 대화를 가져오려면 `/gaseo past`를 쓴다. 현재 폴더에서 발견한 이전 세션의 시작 메시지와 시간, 등록 여부를 목록으로 제시한다. 다른 프로젝트 폴더를 인수로 넘기는 방식도 지원한다.

자동 탐색의 편리함에는 오탐 가능성이 붙는다

환경변수에서 현재 세션 ID를 읽은 경우 출력에 `via=env`가 표시된다. 이 경로가 실패하면 파일 수정 시각을 기준으로 추측하며 `via=mtime`으로 구분한다. 후자의 결과는 반드시 첫 메시지를 확인하는 편이 안전하다.

백그라운드 서브에이전트나 hook이 별도 세션 파일을 만들면 해당 파일이 실제 대화보다 나중에 갱신될 수 있다. 가세오 문서도 이런 상황에서 최신 파일 탐색이 잘못된 세션을 고를 수 있다고 밝힌다. 확실하게 지정하려면 `/gaseo past`에서 직접 선택해야 한다.

현재 지원 대상은 Claude Code 세션이다. 저장소는 Codex가 세션을 날짜 중심 구조로 보관해 프로젝트 폴더와 세션을 연결하는 같은 방식이 아직 적용되지 않는다고 설명한다. Paseo 자체가 여러 공급자를 지원한다는 사실과 가세오의 가져오기 범위는 구분해야 한다.

Paseo 데몬이 꺼져 있을 때 가세오가 임의로 재시작하지 않는 점도 중요하다. 데몬 재시작은 실행 중인 다른 에이전트에 영향을 줄 수 있다. 그래서 오류만 알리고 판단을 사용자에게 남긴다. 개인 개발자에게는 불편함보다 예측 가능한 동작에 가깝다.

Claude Code Remote Control과 목적이 겹치지만 범위는 다르다

Anthropic은 공식 Remote Control을 통해 로컬 Claude Code 세션을 모바일 앱이나 브라우저에서 이어가는 기능을 제공한다. 로컬 환경에서 명령이 실행되고 원격 화면은 세션을 조작한다는 기본 구조는 가세오와 Paseo 조합과 비슷하다.

차이는 관리 범위다. 공식 Remote Control은 Claude Code를 다른 기기에서 계속 사용하는 직접 경로다. Paseo는 여러 공급자의 에이전트, 워크스페이스, 터미널, Git worktree와 실행 상태를 하나의 인터페이스에서 다룬다. 가세오는 그 관제 화면에 이미 진행 중인 Claude Code 작업을 합류시킨다.

Claude Code 하나만 쓰고 단일 세션을 잠깐 원격 제어하려는 사용자라면 공식 기능이 더 단순하다. 반대로 Claude Code와 Codex 등을 함께 운영하거나 여러 작업의 상태와 변경분을 한 화면에서 검토한다면 Paseo 쪽의 관리 모델이 맞는다. 써본 사람들 사이에서도 이동 중 승인과 진행 확인이 편하다는 평가가 나온다. 동기화 지연이나 세션 표시가 불안정할 때 답답하다는 반응도 함께 나온다.

작은 연결 도구가 작업 흐름을 바꾸는 조건

가세오가 유용한 순간은 분명하다. 작업은 습관대로 터미널에서 시작했지만 이후에는 휴대전화에서 질문에 답하거나 다른 컴퓨터에서 진행 상황을 확인해야 할 때다. 세션 내용을 다시 설명하거나 Paseo에서 새 대화를 만드는 대신 `/gaseo` 한 번으로 기존 문맥을 이어간다.

설치 전에는 세 가지를 확인해야 한다. Claude Code CLI가 정상 작동해야 하고 Paseo 데몬이 떠 있어야 하며 사용 중인 터미널에서 `paseo status`가 성공해야 한다. 원격 연결에는 Paseo의 종단간 암호화 릴레이나 로컬 네트워크, 별도 VPN 같은 경로를 선택할 수 있다.

가세오는 대형 오케스트레이터가 아니다. 모델을 바꾸거나 작업을 병렬화하는 대신 사용자가 이미 만든 대화를 올바른 관리 화면에 등록한다. 공식 원격 기능이 생긴 뒤에도 가세오가 남기는 질문은 선명하다. 개발 도구의 경쟁력은 더 많은 에이전트를 띄우는 데만 있지 않다. 지금 작업 중인 세션을 다음 화면으로 얼마나 손실 없이 넘기느냐에도 달려 있다.

자주 묻는 질문

Q

가세오로 Claude Code 세션을 Paseo에 등록하는 방법은?

Claude Code에서 가세오가 포함된 플러그인 마켓플레이스를 추가하고 `/plugin install gaseo`를 실행한 뒤 재시작한다. Paseo 데몬이 실행 중인 상태에서 작업 세션에 `/gaseo`를 입력하면 된다.

Q

가세오는 Claude Code 대화 기록을 복사하나?

저장소 설명상 대화 파일을 복사하지 않는다. Paseo에 Claude Code 세션 ID를 가리키는 레코드를 만들어 기존 기록을 이어서 사용한다.

Q

가세오와 Claude Code Remote Control의 차이는 무엇인가?

Remote Control은 Claude Code 세션을 공식 모바일·웹 화면에서 잇는 기능이다. 가세오는 기존 세션을 여러 코딩 에이전트를 관리하는 Paseo 워크플로에 편입하는 데 초점을 둔다.
