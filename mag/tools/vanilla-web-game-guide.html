바닐라 HTML·CSS·JavaScript로 웹게임 만드는 법

프레임워크 없이 자동화 도구를 활용해 취미용 브라우저 게임을 만드는 구조와 한계를 살펴봤다.

2026-11-26논의 1회 정리

웹게임을 만들려면 반드시 게임 엔진이나 프레임워크가 필요할까. 클코단에서는 자동화 도구의 도움을 받아 바닐라 HTML·CSS·JavaScript만으로 취미용 게임을 구현한 사례가 공유됐다. 이 글은 프레임워크 없이 어디까지 만들 수 있는지, 어떤 순서로 작업해야 하는지, 어느 시점부터 다른 도구가 필요해지는지를 살펴본다.

작은 게임은 브라우저 기능만으로 시작할 수 있다

MDN은 웹게임의 핵심 요소로 HTML·CSS·JavaScript, Canvas, Web Audio API, 입력 이벤트, 저장소를 제시한다. 브라우저가 제공하는 기능만으로 화면 표시, 사용자 입력, 애니메이션, 점수 관리까지 연결할 수 있다는 뜻이다. 실제로 MDN에는 외부 라이브러리 없이 순수 JavaScript로 벽돌깨기 게임을 만드는 튜토리얼이 있다.

취미 프로젝트라면 구성이 특히 단순하다. 별도의 패키지 설치나 빌드 설정 없이 폴더 하나를 만들고 브라우저에서 index.html을 열면 기본 화면을 확인할 수 있다. Visual Studio Code의 공식 입문서도 추가 확장, 빌드 도구, 런타임 없이 HTML·CSS·JavaScript 앱을 만드는 흐름을 안내한다.

방 논의에서도 프레임워크와 패키지를 덜어낸 구성이 장점으로 언급됐다. 서비스 운영이 목적이 아니라면 초기 설정에 시간을 쓰기보다 게임 규칙을 빠르게 시험하는 편이 낫다는 의견이 많았다.

파일 세 개로 게임의 뼈대를 만든다

가장 작은 프로젝트는 다음처럼 시작할 수 있다.

my-game/
├─ index.html
├─ style.css
└─ game.js

index.html에는 게임 영역과 버튼, 점수 표시를 둔다. style.css는 화면 배치와 색상, 버튼 상태를 맡는다. game.js는 게임 상태를 만들고 입력을 받아 화면을 바꾼다. 타이핑 게임이라면 HTML에 제시할 단어, 입력창, 남은 시간, 현재 점수를 배치한다.

작업 순서는 화면보다 규칙을 먼저 정하는 방식이 안정적이다. 예를 들어 시작 버튼을 누르면 3초 뒤 게임을 시작하고, 제한 시간 안에 목표 단어를 입력하면 점수를 올린다. 단어가 맞으면 다음 단어를 보여준다. 시간이 0이 되면 게임을 멈춘다. 자동화 도구를 쓸 때도 이 흐름을 먼저 문장으로 적어야 결과 코드가 한꺼번에 뒤섞이지 않는다.

입력은 DOM 이벤트로 받는다. 키보드 게임은 keydown 이벤트와 KeyboardEvent.key를 이용할 수 있다. 화면을 누르는 게임은 Pointer Events로 마우스·터치·펜 입력을 하나의 모델로 처리할 수 있다. 버튼을 실제 <button> 요소로 만들면 키보드 조작과 포커스 표시도 함께 관리하기 쉽다.

움직이는 게임에는 게임 루프가 필요하다

정적인 퀴즈나 타이핑 게임은 버튼 클릭과 타이머만으로 충분할 수 있다. 캐릭터가 움직이고 충돌하는 게임부터는 매 프레임 상태를 갱신한 뒤 다시 그리는 구조가 필요하다. 이때 브라우저의 requestAnimationFrame()이 기본 선택지다.

MDN에 따르면 requestAnimationFrame()은 다음 화면을 다시 그리기 전에 콜백을 실행한다. 일반적인 디스플레이 주기에 맞춰 호출되며, 보이지 않는 탭에서는 대부분 일시 정지된다. 콜백 안에서 다시 requestAnimationFrame()을 호출해야 다음 프레임이 이어진다.

구현 순서는 세 단계로 나누면 된다. 먼저 키보드나 포인터 입력을 읽는다. 다음으로 캐릭터 위치와 점수 같은 상태를 갱신한다. 마지막으로 DOM 또는 Canvas에 현재 상태를 그린다. 이동량을 프레임 횟수에만 연결하면 고주사율 화면에서 속도가 달라질 수 있다. 따라서 콜백이 전달하는 시간값으로 경과 시간을 계산해야 한다.

Canvas를 선택하면 JavaScript가 도형과 이미지를 직접 그린다. MDN의 Canvas 튜토리얼은 도형, 이미지, 변환, 애니메이션, 최적화 순서로 기능을 확장한다. 반대로 카드 뒤집기, 단어 맞히기, 보드형 퍼즐처럼 화면 요소가 적은 게임은 DOM과 CSS만으로도 충분하다.

자동화 도구는 첫 코드보다 검증 과정에서 차이가 난다

방에서는 자동화 도구를 활용해 게임을 만들고 있다는 경험이 공유됐다. 이 방식의 실용성은 한 번에 완성품을 받는 데 있지 않다. 게임 규칙을 작은 단위로 나누고, 각 단계의 입력과 출력을 확인하는 데 있다.

예를 들어 첫 요청은 index.html에 시작 버튼과 점수 영역을 만들라는 수준으로 제한한다. 다음 요청에서 버튼 클릭 시 게임 상태를 ready에서 playing으로 바꾸고, 그 뒤에 타이머를 붙인다. 마지막으로 정답 처리와 게임 종료 화면을 추가하면 오류가 발생했을 때 어느 단계에서 문제가 생겼는지 추적하기 쉽다.

자동화 도구가 만든 코드는 브라우저 개발자 도구로 확인해야 한다. 콘솔의 오류 메시지와 요소의 실제 상태를 살펴보고, 이벤트가 중복 등록됐는지도 확인한다. 특히 타이머가 게임 재시작 때 여러 개 남아 있거나 게임 종료 후에도 키 입력이 처리되는 문제는 작은 프로젝트에서 자주 드러나는 구조적 결함이다.

코드가 커지면 JavaScript 파일을 나눌 수 있다. 브라우저는 type="module"을 지정한 스크립트에서 import와 export를 직접 지원한다. 다만 모듈은 file://로 바로 여는 환경에서 제한될 수 있으므로 로컬 서버를 사용하는 편이 안전하다. 이 단계에서도 패키지 매니저나 번들러를 반드시 도입해야 하는 것은 아니다.

취미용에서 실제 서비스로 넘어갈 때 달라지는 것

게임을 혼자 실행하는 것과 다른 사람이 반복해서 사용하는 서비스는 요구사항이 다르다. 점수 기록만 필요하면 localStorage로 브라우저별 최고 점수를 저장할 수 있다. Web Storage는 출처별 키·값 저장소이며, localStorage의 값은 브라우저를 닫았다가 다시 열어도 남는다. 다만 저장과 조회가 동기식이므로 큰 데이터를 다루는 용도에는 적합하지 않다.

게임 파일을 온라인에서 불러오거나 사용자 기록을 서버와 동기화하려면 Fetch API와 백엔드가 필요하다. 오프라인 실행을 원한다면 서비스 워커가 HTML·CSS·JavaScript·이미지를 캐시에 저장하도록 구성해야 한다. 설치 가능한 PWA로 확장하려면 웹 앱 매니페스트도 추가해야 한다.

사운드를 넣을 때는 자동 재생 정책도 확인해야 한다. Web Audio API는 정교한 효과음 제어에 쓸 수 있지만, 브라우저는 사용자의 명시적 동작 전 자동 재생을 막을 수 있다. 사운드 버튼을 제공하고 음량을 조절하게 만드는 이유다.

작은 팀이나 개인 개발자에게 바닐라 방식의 장점은 선택지가 적다는 데 있다. 파일을 열고 규칙을 바꾼 뒤 브라우저에서 결과를 바로 확인한다. 반면 장면 관리, 물리 계산, 에셋 관리, 멀티플레이어, 여러 화면의 상태 공유가 필요해지면 프레임워크나 게임 엔진이 반복 작업을 줄여준다.

프레임워크 없이 만든 게임은 완성도가 낮은 게임이 아니다. 다만 프로젝트의 범위를 브라우저가 제공하는 기능 안에서 관리해야 한다. 클코단의 사례처럼 서비스가 아닌 취미용 결과물을 목표로 한다면, 바닐라 HTML·CSS·JavaScript는 규칙을 배우고 빠르게 실험하기에 충분한 출발점이다. 다음 질문은 기술 선택보다 명확하다. 지금 만들려는 게임에 정말 엔진이 필요한가. 아니면 파일 세 개와 브라우저만으로 첫 판을 실행할 수 있는가.

자주 묻는 질문

Q

바닐라 HTML·CSS·JavaScript만으로 웹게임을 만들 수 있나요?

가능합니다. DOM 기반 게임은 버튼과 이벤트만으로 시작할 수 있고, 움직임이 필요하면 Canvas와 requestAnimationFrame을 추가하면 됩니다.

Q

바닐라 웹게임은 어떤 파일로 시작하나요?

기본 구성은 index.html, style.css, game.js 세 파일입니다. HTML은 화면, CSS는 스타일, JavaScript는 게임 상태와 규칙을 담당합니다.

Q

웹게임에 프레임워크가 필요한 시점은 언제인가요?

장면 관리, 물리 계산, 에셋 처리, 멀티플레이어처럼 반복 구조가 커질 때 검토할 수 있습니다. 단순한 취미용 게임은 브라우저 API만으로도 충분합니다.
