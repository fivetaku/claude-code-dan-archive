Cursor Ultra와 SuperGrok Heavy, 사용량은 정말 따로일까

같은 Grok 이름 아래 숨은 별도 구독과 Cursor의 두 사용량 풀, Fable·Grok·Composer 배분법을 짚었다.

2026-08-30논의 1회 정리

Cursor Ultra와 SuperGrok Heavy를 함께 구독하면 한도가 합쳐질까. Fable·Grok·Composer 가운데 무엇을 먼저 써야 오래 버틸까. 비슷한 이름이 한 화면에 모이면서 생긴 혼선을 최신 가격 체계와 실제 작업 흐름으로 풀었다.

Cursor와 SuperGrok은 서로 다른 구독이다

Cursor Ultra는 Anysphere가 판매하는 월 200달러 개인 요금제다. Cursor 가격 페이지는 Ultra에 Pro의 20배 Agent 한도와 Grok Bot 접근도 표시한다. Cursor 안의 모델 사용량은 월별 결제 주기에 맞춰 갱신된다. SuperGrok Heavy는 SpaceXAI가 운영하는 Grok 유료 요금제다. SpaceXAI FAQ에 따르면 유료 사용자는 Chat·Build·Imagine·Voice 등을 아우르는 주간 사용량 풀을 받으며, 설정의 Usage 화면에서 소진율과 다음 초기화 시점을 확인한다.

두 구독은 청구 주체와 초기화 주기, 잔량 화면이 모두 다르다. Cursor는 월간 결제 주기를, Grok은 주간 사용량 주기를 따른다. 따라서 Cursor Ultra와 SuperGrok Heavy의 기본 사용량은 별개로 관리해야 한다.

Cursor Ultra 안에는 사용량 풀이 두 개 있다

Cursor 문서는 Pro·Pro+·Ultra에 월간 사용량 풀 두 개가 들어간다고 설명한다. Cursor Models에는 Cursor Grok 4.6·4.5와 Composer 2.5가 묶인다. Other Models에는 Anthropic과 OpenAI 같은 외부 모델이 들어간다.

한도 계산은 여기서 한 번 더 갈린다. Grok과 Composer는 같은 Cursor Models 잔량을 나눠 쓴다. Claude Fable 5는 Other Models에서 차감된다.

Ultra를 하나의 거대한 토큰 통장으로 이해하면 실제 소진 경로를 놓치기 쉽다.

Cursor의 Spending 화면은 두 풀의 잔량과 요청별 비용을 보여준다. 포함량을 넘기면 사용자는 온디맨드 결제를 켜거나 상위 요금제로 바꿀 수 있다. 자동 결제를 원치 않으면 온디맨드 설정부터 확인해야 한다.

Grok은 판단에, Composer는 반복 작업에 맞는다

Cursor는 Composer 2.5를 빠르고 저렴한 자체 에이전트 모델로 설명한다. 파일 편집과 터미널 작업에 맞춰 조정됐다. 표준 단가는 입력 100만 토큰당 0.5달러다. 출력은 2.5달러이며 Fast는 각각 3달러와 15달러다. Cursor Grok 4.5는 복잡하고 오래 걸리는 작업용 모델이다. 표준 단가는 입력 2달러, 출력 6달러이며 Fast는 4달러와 18달러다. 최신 문서는 지시 준수와 장기 작업에는 Grok 4.6을 우선 권한다.

써본 사람들 사이에서는 평가가 한쪽으로 모이지 않았다. Composer가 예측 가능하고 막다른 길이 적다는 반응이 있었다. 반대로 깊은 디버깅과 계획에서는 Grok이 더 낫다는 의견도 나왔다.

반복해서 등장한 사용법은 Grok이 계획하고 Composer가 구현하는 조합이다. 먼저 Grok에 요구사항과 실패 조건, 검증 명령을 담은 계획을 맡긴다. 이어 Composer에 계획과 대상 파일을 넘겨 수정·테스트를 시킨다. 짧은 작업은 처음부터 Composer로 끝내면 같은 풀을 더 오래 쓸 수 있다.

Fast는 시간이 중요한 경우에만 켜는 편이 합리적이다. 공식 단가상 두 모델 모두 Fast 출력 비용이 크게 오른다. 기다림보다 예산이 중요하면 표준 속도가 출발점이다.

Fable은 상시 모델보다 해결사에 가깝다

Claude Fable 5는 Cursor가 최고 난도 장기 작업에 배치한 Anthropic 모델이다. 컨텍스트는 기본 30만 토큰이며 Max는 100만 토큰까지 지원한다. CursorBench에서는 Opus 5와 함께 최상위권으로 소개된다.

가격 차이는 크다. Fable은 입력 100만 토큰당 10달러, 출력 50달러다. 같은 토큰 양만 비교하면 표준 Composer 2.5의 20배다. Fable을 계속 쓰면 한도가 빨리 줄었다는 사용자 경험은 단가 구조와 방향이 맞는다.

사용 순서는 좁게 잡을수록 좋다. Composer로 재현 절차와 관련 파일을 모으고 Grok으로 원인 후보를 줄인다. 그래도 막힌 문제만 Fable에 실패 테스트, 변경 범위, 종료 조건과 함께 넘긴다. Fable의 긴 추론을 모든 탐색 단계에 쓰지 않는 방식이다.

Fable에는 별도 개인정보 조건도 붙는다. Cursor Privacy Mode를 쓰는 계정과 조직은 Anthropic의 데이터 보존 정책을 승인해야 한다. 비용뿐 아니라 팀의 코드 처리 규칙도 선택 기준에 들어간다.

Cursor의 Claude 모델은 Claude Code가 아니다

Cursor 모델 선택기에서 Fable이나 Claude를 고르면 Cursor의 Agent가 해당 모델을 호출한다. 사용량은 Cursor의 Other Models 풀에 기록된다. 모델이 Anthropic 제품이라는 사실만으로 Claude Code 세션이 되지는 않는다. Claude Code는 Anthropic의 코딩 도구다. 터미널에서 실행하거나 지원 IDE 확장으로 설치하며 Cursor도 지원 IDE에 포함된다. Claude 계정으로 로그인한 Claude Code 사용량은 Claude Pro·Max 한도와 공유된다.

같은 Cursor 창에서도 청구 경로는 달라질 수 있다. Cursor Agent 패널의 Fable은 Cursor Spending에서 확인한다. Claude Code 확장이나 터미널 세션은 `/status`로 Claude 한도를 확인한다. `ANTHROPIC_API_KEY`가 잡혀 있으면 구독 대신 API 요금이 나갈 수 있다는 경고도 공식 도움말에 있다.

세 개의 잔량판을 따로 보면 배분이 선명해진다

개인 개발자와 소규모 팀은 작업을 난도별로 나눌 수 있다. 일상 수정과 파일 탐색은 Composer 2.5, 구조 설계와 깊은 디버깅은 Cursor Grok, 막힌 장기 과제는 Fable에 맡긴다. SuperGrok Heavy는 IDE 밖의 조사와 문서 작업에 쓰며 자체 주간 풀을 관리한다.

Claude Code까지 Cursor에서 쓴다면 예산판은 하나 더 생긴다. Cursor Spending의 두 풀, Grok Settings의 주간 풀, Claude Code의 `/status`를 각각 확인해야 한다. 같은 모델 이름보다 어느 제품의 에이전트와 계정으로 호출했는지가 한도를 결정한다.

자주 묻는 질문

Q

Cursor Ultra와 SuperGrok Heavy 사용량은 공유되나요?

공유되지 않는다. Cursor는 자체 월간 사용량 풀을 관리하고, SuperGrok Heavy는 Grok 제품 전반에서 쓰는 별도 주간 풀을 제공한다.

Q

Cursor에서 Fable 5를 쓰면 Claude Code 한도가 줄어드나요?

Cursor Agent의 모델 선택기에서 Fable 5를 쓰면 Cursor의 Other Models 풀에서 차감된다. Claude Code 확장이나 터미널에 Claude 계정으로 로그인한 사용량은 Claude 구독 한도에 잡힌다.

Q

Grok과 Composer 2.5는 어떻게 나눠 쓰는 게 좋나요?

복잡한 계획과 깊은 디버깅은 Grok에, 반복 구현과 파일 편집은 Composer 2.5에 맡기는 방식이 실용적이다. 짧고 명확한 작업은 저렴한 Composer 표준 모드부터 시작하면 된다.
