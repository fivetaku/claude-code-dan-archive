Claude Code 원격 작업, CLI 사용자에게 Pase오가 필요한 순간

공식 원격 제어도 생긴 지금, Paseo의 가치는 모바일 화면보다 여러 에이전트와 작업공간을 한곳에서 다루는 데 있다

2026-09-17논의 1회 정리

Claude Code를 터미널에서 잘 쓰는 사람에게 별도 GUI가 필요할까. Claude와 Codex 모두 자체 원격 기능을 갖춘 지금, Paseo를 설치할 이유는 단순한 ‘모바일 터미널’만으로 설명되지 않는다. 핵심은 여러 CLI 에이전트와 작업 디렉터리를 어떤 단위로 관리할지에 있다.

Paseo는 에이전트를 교체하지 않고 실행 환경을 관리한다

Paseo는 Claude Code나 Codex를 대체하는 모델이 아니다. 개발자 컴퓨터에서 daemon을 실행하고 설치된 에이전트 CLI를 대신 시작하고 감시하는 오픈소스 제어면이다. 데스크톱·웹·모바일·CLI 클라이언트가 이 daemon에 연결된다.

Claude Code는 공식 `claude` CLI와 Claude Agent SDK로 구동한다. Codex도 공식 `codex` CLI와 app-server 인터페이스를 사용한다. 기존 로그인, MCP, 설정, 스킬과 사용 한도는 각 제공자의 규칙을 그대로 따른다. Paseo가 별도 추론 요금을 붙이지도 않는다.

v0.8은 베타로 제공되며, 사용자 정의 provider와 플러그인 관련 기능을 포함한다. 저장소는 Apache-2.0 라이선스로 공개돼 있다.

따라서 같은 모델과 같은 지시를 쓴다면 코드 품질을 바꾸는 주체는 주로 에이전트다. Paseo가 바꾸는 부분은 실행 시작점, 상태 확인, 승인 처리와 작업 간 격리다.

한 개의 Claude 세션만 원격으로 볼 때는 공식 기능도 충분하다

Anthropic의 Remote Control은 로컬 Claude Code 세션을 브라우저와 Claude 모바일 앱에서 이어 간다. 로컬 파일, MCP 서버와 프로젝트 설정을 유지하며 대화와 권한 요청도 동기화한다. 네트워크가 끊겼다가 돌아오면 메시지와 상태를 다시 전달한다.

Claude Code만 사용한다면 `claude --remote-control`이나 세션 내부의 `/remote-control`로 목적을 달성할 수 있다. 다만 Claude 요금제 로그인이 필요하며 API 키, Bedrock, 일부 프록시 환경에서는 사용할 수 없다. 로컬 프로세스도 계속 실행돼야 한다.

Codex 역시 데스크톱 작업을 모바일에서 확인하는 Remote 흐름을 제공한다. 각 회사의 공식 앱이 빠르게 개선되면서 “휴대전화에서 한 세션을 확인한다”는 이유만으로 제3자 도구를 선택할 필요는 줄었다.

Paseo의 차이는 provider 경계를 넘을 때 드러난다. Claude Code로 구현하고 Codex로 검토하거나 OpenCode와 Copilot을 섞어 쓰는 흐름을 하나의 프로젝트 목록에서 다룰 수 있다. 여러 구독과 모델을 오가는 개발자에게는 화면 하나보다 통합된 작업 단위가 더 큰 이점이다.

프로젝트가 아니라 workspace를 만들면 병렬 작업이 분리된다

Paseo는 채팅보다 workspace를 중심에 둔다. 하나의 workspace에는 작업 디렉터리, 여러 에이전트 세션, 터미널, 브라우저와 diff가 함께 들어간다. 기능 구현과 검토를 같은 폴더 맥락에 묶되 다른 기능과는 분리할 수 있다.

설치 순서는 단순하다. 먼저 사용할 컴퓨터에 Claude Code나 Codex CLI를 설치하고 로그인한다. 이어 데스크톱 앱을 받거나 서버에서 다음 명령으로 daemon을 시작한다.

`npm install -g @getpaseo/cli`

`paseo`

프로젝트 폴더에서 `paseo project create`를 실행한 뒤 작업을 보낸다. 예를 들어 `paseo run --provider codex "현재 diff를 검토해 위험한 변경을 찾아라"`라고 입력하면 새 workspace와 세션이 만들어진다. `paseo ls`로 상태를 보고 `paseo attach <id>`로 출력을 따라가며 `paseo send <id> "테스트도 추가해라"`로 후속 지시를 보낸다.

동시에 여러 기능을 맡길 때는 Git worktree가 중요하다. `paseo workspace create --isolation worktree --mode branch-off --new-branch feature/auth --base origin/main`처럼 별도 디렉터리와 브랜치를 만든다. 각 에이전트가 같은 파일을 덮어쓰는 충돌을 줄이고 결과를 diff 단위로 검토할 수 있다.

저장소 루트의 `paseo.json`에는 `npm ci` 같은 준비 명령과 `npm test`, `npm run dev` 같은 스크립트를 넣는다. 새 worktree가 만들어지면 의존성을 설치한다. 작업이 끝나면 테스트나 개발 서버를 같은 workspace에서 실행하는 구조다. 개인 개발자도 기능 구현과 코드 리뷰를 서로 다른 모델에 나눠 맡길 수 있다.

모바일 연결은 편의 기능이면서 원격 실행 권한이다

휴대전화 연결은 데스크톱 설정에서 Pair Device를 선택하거나 `paseo daemon pair`를 실행해 시작한다. QR 코드를 스캔하면 모바일 앱이 로컬 daemon과 연결된다. 공식 relay를 쓰지 않으려면 Tailscale이나 SSH, 직접 연결을 선택할 수 있다.

Paseo 문서에 따르면 relay 트래픽은 종단간 암호화된다. relay 운영자는 메시지와 코드를 읽을 수 없지만 IP 주소, 전송 시점과 크기 같은 메타데이터는 보게 된다. 에이전트가 Anthropic이나 OpenAI API로 보내는 데이터는 각 provider의 기존 경로를 따른다.

daemon을 외부 네트워크에 직접 노출할 때는 비밀번호를 설정하고 방화벽 규칙을 검토해야 한다. 공식 문서는 인증 없이 `0.0.0.0`에 바인딩하지 말라고 경고한다. Docker를 쓴다면 에이전트가 접근할 저장소만 마운트해야 한다.

모바일 승인은 속도와 안전의 교환이다. 권한 질문을 최소화하면 병렬 작업은 빨라지지만 잘못된 셸 명령도 즉시 실행될 수 있다. 모델과 추론 강도뿐 아니라 provider별 권한 모드를 작업 성격에 맞춰 확인해야 한다.

Paseo가 필요한 기준은 화면이 아니라 작업 수다

실사용자들은 외출 중 진행 상황을 보고 승인할 수 있다는 점을 높게 평가한다. 반면 업데이트가 잦은 도구답게 간헐적인 UI 문제와 provider별 기능 차이가 불편하다는 반응도 있다. 하위 에이전트가 막혔을 때 세부 상태를 파악하기 어렵다는 경험도 나온다.

터미널 한두 개로 충분하고 Claude Code만 쓴다면 공식 Remote Control이 더 짧은 경로다. 기존 CLI 습관을 버릴 필요도 없다. Paseo 안에서도 터미널을 열고 `claude`나 `codex`를 그대로 실행할 수 있다.

선택이 달라지는 지점은 세션이 아니라 작업을 관리하기 시작할 때다. 세 기능을 별도 worktree에서 돌리고 Claude와 Codex를 역할별로 나누며 이동 중 권한 요청과 diff를 확인한다면 Paseo는 GUI 장식이 아니다. 그때부터 관리해야 할 대상은 대화창이 아니라 여러 작업의 생명주기다.

자주 묻는 질문

Q

Paseo를 쓰면 Claude Code를 다시 설치해야 하나요?

Paseo가 실행될 컴퓨터에 Claude Code CLI가 설치되고 로그인돼 있어야 합니다. Paseo는 기존 CLI와 인증을 사용하며 Claude Code 자체를 포함하지 않습니다.

Q

Paseo와 Claude Code Remote Control의 차이는 무엇인가요?

Remote Control은 실행 중인 Claude Code 세션을 다른 기기에서 이어 쓰는 공식 기능입니다. Paseo는 Claude Code뿐 아니라 Codex 등 여러 provider와 workspace, worktree를 한 인터페이스에서 관리합니다.

Q

Paseo로 여러 코딩 에이전트를 안전하게 병렬 실행하려면 어떻게 하나요?

작업마다 Git worktree 기반 workspace를 만들고 provider 권한을 제한하는 편이 좋습니다. 원격 daemon에는 비밀번호를 설정하고 relay, VPN 또는 SSH처럼 암호화된 연결을 사용해야 합니다.
