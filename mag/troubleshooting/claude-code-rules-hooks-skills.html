Claude Code가 규칙을 잊는 이유와 고치는 설정법

CLAUDE.md만으로 부족한 이유를 컨텍스트 구조와 Hooks·Skills·Subagents 활용법으로 풀어봤다.

2026-11-13논의 1회 정리

Claude Code를 오래 쓰면 비슷한 장면을 만난다. 초반에는 프로젝트 규칙을 잘 따르다가 어느 순간 테스트 순서나 파일 수정 범위를 놓친다. 이 기사는 규칙이 왜 흐려지는지, CLAUDE.md만으로 부족할 때 무엇을 어디에 배치해야 하는지에 답한다.

규칙이 사라진 게 아니라 컨텍스트에서 밀린다

Anthropic 공식 문서는 Claude Code의 각 세션이 새로운 컨텍스트 윈도우에서 시작한다고 설명한다. 이전 대화의 기억이 자동으로 영구 보존되는 구조는 아니다. 세션 사이에 남는 것은 사용자가 작성한 CLAUDE.md와 Claude가 저장하는 자동 메모리다.

CLAUDE.md는 프로젝트 루트, 사용자 설정, 하위 디렉터리별로 둘 수 있다. 작업 디렉터리와 상위 경로의 파일은 시작할 때 읽히고 하위 디렉터리의 파일은 필요할 때 읽히지만 문서 자체가 강제 설정으로 작동하지는 않는다. 공식 문서도 CLAUDE.md와 자동 메모리를 “컨텍스트”로 설명하며 더 구체적이고 짧은 지시일수록 잘 따른다고 안내한다.

방 논의에서도 비슷한 경험이 많았다. 세션에서 정한 규칙이 한 시간 안에 약해지거나 전역 규칙과 프로젝트 규칙을 함께 둬도 다음 날에는 품질이 달라졌다는 의견이 나왔다. 일부 사용자는 모델을 바꾼 뒤 응답 태도가 크게 달라졌다고 느꼈지만 특정 모델 하나의 문제로만 단정하기는 어렵다.

컨텍스트가 길어지면 규칙이 삭제되지 않아도 작업과 직접 관련된 정보에 비해 주목도가 낮아진다. 긴 로그, 검색 결과, 파일 내용이 이어지면 모델이 현재 목표를 우선 처리하는 과정에서 오래된 지시를 덜 활용할 수 있다. 공식 문서가 장기 작업에서 진행 상태를 파일에 남기고 새 컨텍스트에서 다시 읽게 하라고 권하는 이유도 여기에 있다.

CLAUDE.md에는 항상 필요한 사실만 남겨야 한다

CLAUDE.md에 넣을 내용은 프로젝트 전반에 늘 필요한 정보가 적합하다. 예를 들면 패키지 설치 명령, 테스트 실행법, 디렉터리 구조, 반드시 지켜야 할 코드 스타일처럼 매 작업마다 참고할 사실이다. 한 번만 수행하는 배포 절차나 긴 체크리스트까지 모두 넣으면 매번 컨텍스트 비용이 발생한다.

공식 문서의 현재 권장 구조는 파일을 여러 범위로 나누는 방식이다. 루트 CLAUDE.md에는 공통 규칙을 두고 특정 디렉터리의 규칙은 해당 위치의 파일이나 .claude/rules/에 둔다. 자동 메모리는 사용자의 선호나 반복해서 수정한 부분을 기록하는 용도다. 두 장치를 하나의 강제 정책처럼 다루면 기대와 실제 동작 사이에 틈이 생긴다.

긴 문서를 줄이는 작업도 단순히 문장 수를 줄이는 데서 끝나지 않는다. “항상 지켜야 하는 원칙”과 “필요할 때 찾아볼 절차”를 분리해야 한다. 반복 절차가 CLAUDE.md의 상당 부분을 차지한다면 Skills로 옮기는 편이 맞다.

써본 사람들 사이에서는 규칙을 여러 파일에 반복하면 오히려 컨텍스트만 늘어난다는 반응도 있다. 반대로 짧은 규칙을 상단에 배치하고 작업 시작 때 핵심 조건을 다시 확인시키면 체감이 좋아졌다는 의견도 있다. 공통점은 규칙을 많이 쓰는 것보다 현재 작업에 필요한 규칙을 좁히는 편이 낫다는 점이다.

반복 절차는 Skills로, 위험한 행동은 Hooks로 옮긴다

Skills는 필요할 때 불러오는 작업 설명서다. Claude Code 공식 문서에 따르면 .claude/skills/이름/SKILL.md를 만들고 반복되는 지침·체크리스트·다단계 절차를 담을 수 있다. Skill의 본문은 매번 전부 컨텍스트에 들어가는 것이 아니라 사용될 때 로드된다.

예를 들어 release-check Skill을 만든다면 문서에 버전 확인, 테스트, 변경 로그 생성, 빌드 검증 순서를 적는다. 사용자가 /release-check를 호출하거나 현재 작업이 설명과 맞을 때 Claude가 해당 절차를 읽는다. 입력은 저장소 상태와 릴리스 버전이고 산출물은 검사 결과와 누락된 단계다.

Hooks는 성격이 다르다. Hooks reference에 따르면 특정 이벤트에서 셸 명령이나 검증 로직을 실행할 수 있다. PreToolUse는 도구 실행 전에 검사하고 조건에 맞으면 작업을 막을 수 있다. 비밀 키가 파일에 들어가는지, 보호된 경로를 지우려는지, 위험한 명령이 실행되는지를 검사하는 데 적합하다.

구성 순서는 간단하다. 먼저 .claude/settings.json에 어떤 이벤트를 감시할지 적고 검사 스크립트가 도구 입력을 받아 허용 또는 차단 결과를 반환하게 만든다. 파일 수정 뒤 테스트를 돌리고 싶다면 PostToolUse를 활용할 수 있다. 규칙을 “잊지 말라”고 부탁하는 대신 실패하면 다시 수정하도록 피드백을 돌려주는 구조다.

다만 Hooks는 임의의 셸 명령을 실행하므로 출처와 내용을 검토해야 한다. 공식 자료도 Hooks가 사용자 권한으로 파일을 읽거나 변경할 수 있다고 경고한다. 강제성이 필요한 만큼 잘못 만든 Hook의 영향도 크다.

검색과 로그는 Subagents의 별도 컨텍스트에서 처리한다

Subagents는 메인 세션과 다른 컨텍스트 윈도우에서 작업한다. Claude Code 문서는 검색 결과, 로그, 대량의 파일 내용처럼 메인 대화에 다시 가져올 필요가 적은 작업을 Subagent에 맡기면 컨텍스트를 보존할 수 있다고 설명한다.

구성 파일은 보통 .claude/agents/이름.md에 둔다. 파일에는 역할, 사용할 도구, 권한, 결과 형식을 적는다. 예를 들어 security-reviewer는 읽기 전용으로 저장소를 검사하고 발견한 위험과 파일 위치만 요약하게 만들 수 있다. 메인 세션은 전체 로그 대신 요약만 받는다.

방에서 공유된 경험처럼 한 작업 안에서 모델이나 담당 에이전트를 바꾸는 경우에도 이 구분이 중요하다. 메인 대화에 모든 탐색 기록을 쌓으면 다음 단계의 구현이 느려질 수 있다. 반면 Subagent의 결과가 지나치게 짧으면 판단 근거가 사라지므로 “위험도·근거 파일·재현 명령”처럼 반환 형식을 정해야 한다.

Anthropic의 공식 가이드도 복잡한 문제를 탐색·계획·구현으로 나누고 초기에 Subagents를 활용하면 메인 컨텍스트를 보존할 수 있다고 설명한다. 단순한 한 파일 수정까지 무조건 분리할 필요는 없다. 병렬 처리, 독립적인 조사, 대량 출력처럼 분리 효과가 뚜렷한 경우가 기준이다.

개인 개발자에게 필요한 최소 구성은 네 층이다

작은 프로젝트라면 처음부터 복잡한 에이전트 팀을 만들 필요가 없다. 루트 CLAUDE.md에는 실행 명령과 핵심 금지사항만 둔다. 반복 작업은 .claude/skills/ 아래에 절차별로 나누고 삭제·비밀정보·보호 경로 같은 위험 행동은 PreToolUse Hook으로 차단한다.

검색이나 테스트 로그가 커질 때만 읽기 전용 Subagent를 추가한다. 작업이 길어지면 progress.md나 테스트 목록을 저장해 다음 세션이 현재 상태를 다시 발견하게 한다. 새 세션이 이전 대화를 기억하지 못해도 저장소 안의 상태와 검증 명령은 남는다.

이 구성은 규칙을 더 많이 주입하는 방법이 아니다. 모델이 참고할 내용은 짧게 유지하고 필요한 절차는 호출 시점에 불러오며 반드시 막아야 할 행동은 프로그램이 검사한다. Claude Code가 규칙을 잊는 문제에 대한 현실적인 해법은 기억력을 기대하는 대신 규칙의 역할을 컨텍스트·절차·검증으로 나누는 데 있다.

자주 묻는 질문

Q

Claude Code는 CLAUDE.md를 매번 읽나요?

프로젝트와 사용자 범위에 맞는 CLAUDE.md는 세션 시작 시 로드됩니다. 다만 컨텍스트로 취급되므로 모든 지시가 강제로 집행되는 것은 아닙니다.

Q

CLAUDE.md와 Skills는 어떻게 나누나요?

매 작업에 필요한 프로젝트 사실과 공통 규칙은 CLAUDE.md에 둡니다. 반복되는 체크리스트와 긴 절차는 .claude/skills/의 SKILL.md로 분리하는 편이 적합합니다.

Q

규칙을 반드시 지키게 하려면 무엇을 써야 하나요?

위험한 파일 수정이나 명령 차단에는 PreToolUse Hook과 권한 설정을 사용해야 합니다. CLAUDE.md는 행동을 안내하지만, Hook은 조건에 따라 실행 자체를 막을 수 있습니다.
