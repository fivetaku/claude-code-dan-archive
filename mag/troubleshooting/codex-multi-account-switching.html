코덱스 다중 계정 전환, 토큰 제한까지 분리될까

CODEX_HOME으로 인증 환경을 나누는 방법과 사용량 제한, 자동 전환의 경계를 짚었다

2026-09-17논의 1회 정리

코덱스 계정을 바꾸면 남은 사용량도 새 계정 기준으로 바뀔까. 여러 유료 계정을 오가는 개발자에게 이는 단순한 로그인 편의의 문제가 아니다. 2026년 9월 17일 기준 공식 문서와 공개 이슈를 살펴보면 인증 환경은 분리할 수 있다. 하지만 사용량까지 확실히 분리된다고 장담하기는 어렵다.

코덱스는 계정보다 인증 환경을 기준으로 움직인다

OpenAI 문서에 따르면 Codex CLI는 ChatGPT 로그인과 API 키 로그인을 지원한다. 전자는 구독에 포함된 사용량을 쓰고 후자는 OpenAI Platform에서 사용량만큼 별도로 결제한다. 같은 CLI라도 인증 방식에 따라 한도와 관리 정책이 달라진다.

로그인을 마치면 CLI와 IDE 확장은 인증 정보를 공유한다. 자격 증명은 기본적으로 `~/.codex/auth.json`이나 운영체제의 보안 저장소에 남는다. 한쪽에서 로그아웃하면 다른 쪽도 다시 로그인해야 할 수 있다. ([developers.openai.com](https://developers.openai.com/codex/auth))

계정 전환 문제는 여기서 시작된다. 기본 경로 하나에 인증과 설정이 모이기 때문에 새 계정으로 로그인하면 기존 작업 환경까지 함께 바뀐다. 개인 프로젝트와 회사 저장소를 오가는 사람에게는 사용량보다 설정 혼선이 더 큰 위험이다.

공식 빠른 전환 기능은 아직 문서화되지 않았다

현재 공식 CLI 명령에는 `codex login`, `codex login status`, `codex logout`이 있다. `codex switch`나 인증용 `--account` 같은 명령은 공식 명령표에서 확인되지 않는다. `--profile` 옵션은 설정 파일을 겹쳐 읽는 기능일 뿐, 로그인 계정을 고르는 인증 프로필과는 다르다. ([developers.openai.com](https://developers.openai.com/codex/cli/reference))

OpenAI의 Codex 저장소에도 빠른 계정·워크스페이스 전환을 요구하는 이슈가 열려 있다. 요청자는 현재 우회법을 로그아웃 후 재로그인으로 설명했다. 개인용과 회사용 인증을 동시에 유지하려는 수요가 제품 기능보다 앞선 상황이다. ([github.com](https://github.com/openai/codex/issues/30684))

써본 사람들 사이에서는 반복 로그인을 없애는 별칭이 편하다는 반응이 많다. 반면 어느 계정으로 실행 중인지 놓치거나 세션과 설정이 서로 다른 폴더에 흩어진다는 불만도 나온다. 자동 전환만 붙인다고 해결될 문제는 아니라는 얘기다.

CODEX_HOME으로 개인용과 업무용을 분리한다

파일 방식의 자격 증명 저장을 설정한 경우 활용할 수 있는 방법은 계정별 `CODEX_HOME`을 만드는 것이다. OpenAI 문서는 파일 방식의 인증 정보가 `CODEX_HOME` 아래 `auth.json`에 저장된다고 설명한다. 파일 방식의 자격 증명 저장을 쓸 때, 각 터미널이 서로 다른 홈 디렉터리를 가리키면 인증 파일과 설정을 나눌 수 있다. ([developers.openai.com](https://developers.openai.com/codex/auth))

파일 방식의 자격 증명 저장을 설정했다면 다음처럼 구성할 수 있다.

mkdir -p "$HOME/.codex-personal" "$HOME/.codex-work"

CODEX_HOME="$HOME/.codex-personal" codex login
CODEX_HOME="$HOME/.codex-work" codex login

alias codex-personal='CODEX_HOME="$HOME/.codex-personal" codex'
alias codex-work='CODEX_HOME="$HOME/.codex-work" codex'

별칭은 `.zshrc`나 `.bashrc`에 넣는다. 새 터미널에서 `codex-personal login status`와 `codex-work login status`를 각각 실행해 인증 방식을 확인한다. 두 창을 나란히 열어두면 개인 작업과 회사 작업을 동시에 유지할 수 있다.

인증 파일을 직접 복사하는 방식은 피하는 편이 낫다. OpenAI는 `auth.json`을 비밀번호처럼 다루고 저장소나 채팅에 공유하지 말라고 경고한다. 여러 환경을 만들 때마다 해당 경로에서 정상적으로 로그인해야 토큰 갱신 충돌도 줄어든다.

`CODEX_HOME`은 코덱스의 로컬 상태만 분리한다. 같은 운영체제 사용자가 가진 SSH 키나 GitHub CLI 인증, 브라우저 쿠키까지 나누지는 않는다. 고객사 코드나 회사 정책을 엄격히 구분해야 한다면 별도 OS 사용자나 기기를 쓰는 편이 더 확실하다. ([github.com](https://github.com/openai/codex/discussions/30852))

계정을 바꿨는데 제한이 남는 현상은 확정된 정책이 아니다

커뮤니티에서는 한 계정이 사용량 한도에 도달한 뒤 다른 계정으로 바꿔도 제한 표시가 남았다는 경험과 별도 터미널에서는 정상 작동했다는 경험이 엇갈렸다. OpenAI 저장소에도 Plus 계정의 제한이 Team 계정에 나타났다는 공개 신고가 있다. 해당 이슈에는 브라우저 캐시나 공유 인증 상태 등이 원인 후보로 적혔지만 공식 원인이나 해결책은 제시되지 않았다. ([github.com](https://github.com/openai/codex/issues/23706))

제한이 따라왔다고 곧바로 기기나 IP 단위 정책으로 단정해서는 안 된다. 우선 `codex login status`로 인증 방식을 확인한 뒤 실행 중인 세션에서 `/status`를 사용해야 한다. 공식 가격 문서는 사용량 대시보드와 `/status`를 현재 한도 확인 수단으로 안내한다. ([developers.openai.com](https://developers.openai.com/codex/pricing))

계정별 `CODEX_HOME`에서도 같은 현상이 재현된다면 진단 보고서와 로그인 로그를 확보할 수 있다. 다만 토큰 원문이나 `auth.json`은 첨부하지 않아야 한다. 다른 계정에서 우연히 풀렸다는 경험은 해결책이 아니라 재현 조건 하나에 불과하다.

자동 전환의 목적이 사용량 우회라면 경계가 달라진다

업무 계정과 개인 계정을 구분하려는 전환은 합리적인 운영 방식이다. 하지만 한 계정의 제한이 끝날 때마다 다음 유료 계정으로 자동 이동하는 설계는 성격이 다르다. OpenAI 이용약관은 자격 증명 공유와 사용량 제한 우회를 금지한다. 자동 계정 순환이 제한 회피를 목적으로 작동한다면 약관 위반으로 해석될 위험이 있다. ([openai.com](https://openai.com/policies/row-terms-of-use/))

공식 대안은 이미 마련돼 있다. Plus와 Pro 사용자는 포함량을 소진한 뒤 추가 크레딧을 살 수 있으며 더 작은 모델로 사용량을 늘릴 수도 있다. 로컬 작업은 API 키로 이어갈 수 있지만 표준 API 요금이 별도로 청구된다. ([developers.openai.com](https://developers.openai.com/codex/pricing))

개인 개발자와 소규모 팀에게 필요한 자동화는 ‘한도가 끝나면 다음 계정’이 아니다. 저장소마다 올바른 인증 환경을 선택하고 실행 전에 현재 계정과 사용량을 보여주는 런처가 더 안전하다. 코덱스 다중 계정 운영의 핵심은 토큰을 이어 붙이는 기술이 아니라 프로젝트·결제·정책의 경계를 섞지 않는 데 있다.

자주 묻는 질문

Q

Codex CLI에서 여러 계정을 동시에 로그인할 수 있나요?

공식 빠른 전환 명령은 확인되지 않는다. 계정별 CODEX_HOME을 만들고 각 경로에서 로그인하면 여러 인증 환경을 나란히 유지할 수 있다.

Q

CODEX_HOME을 바꾸면 사용량 제한도 분리되나요?

CODEX_HOME은 로컬 인증과 설정을 분리하지만 서버의 사용량 계산 방식까지 보장하지 않는다. 각 환경에서 login status와 /status를 확인해야 한다.

Q

코덱스 한도에 도달하면 API 키로 계속 쓸 수 있나요?

로컬 Codex CLI는 API 키 로그인을 지원한다. 구독 포함량 대신 OpenAI Platform의 표준 API 요금이 별도로 적용된다.

Q

auth.json을 복사해 계정을 전환해도 되나요?

인증 파일에는 접근 토큰이 들어 있어 직접 복사하거나 공유하지 않는 편이 안전하다. 각 CODEX_HOME에서 로그인 절차를 따르는 방식이 낫다.
