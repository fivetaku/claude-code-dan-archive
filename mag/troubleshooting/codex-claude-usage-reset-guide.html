AI 구독 리셋권, 코덱스와 클로드에서 다르게 쓰는 법

신규 구독 보너스처럼 보이는 리셋권의 실제 작동 방식과 사용 시점을 공식 문서로 구분했다

2026-09-23논의 1회 정리

AI 구독을 새로 시작하거나 상위 플랜으로 바꾸면 사용량 리셋권을 받을 수 있다는 경험담이 번지고 있다. 문제는 화면에 같은 ‘reset’이라는 말이 떠도 Codex와 Claude의 작동 방식이 다르다는 점이다. 리셋권은 추가 사용량일까, 아니면 다음 주 몫을 앞당겨 쓰는 기능일까?

2026년 9월 Codex 리셋은 실제 프로모션이었다

OpenAI는 GPT-6 Astra 출시 과정에서 Codex banked reset을 지급했다고 공식 도움말에 명시했다. 기존 Plus·Pro·Business 이용자는 2026년 9월 3일과 4일 각각 지급 대상에 포함됐다. 당시 새로 만든 계정도 정해진 시각 전에 구독을 시작했다면 대상이 될 수 있었다. (help.openai.com)

신규 가입자는 9월 3일 오후 10시, 9월 4일 오후 8시까지 계정을 만들고 구독해야 했다. 두 시각은 미국 태평양 시간 기준이다. 플랜과 지역, 계정 상태, 공급 상황에 따라 실제 지급 여부는 달라질 수 있었다.

9월 7일에는 별도의 global reset도 시행됐다. 이 리셋은 즉시 적용됐기 때문에 계정에 저장되지 않았다. 반면 banked reset은 만료 전까지 보관한 뒤 이용자가 직접 실행하는 방식이었다. (help.openai.com)

신규 가입이나 플랜 업그레이드 자체가 리셋권을 보장하지는 않는다. 당시 지급 사례는 근거 없는 소문이 아니었지만 특정 기간의 프로모션을 상시 혜택으로 받아들이면 안 된다. OpenAI도 향후 리셋 지급을 보장하지 않는다고 설명한다.

Codex banked reset은 주간 갱신일도 다시 잡는다

Codex의 full banked reset을 적용하면 5시간 사용 창과 주간 사용량이 함께 복구된다. 동시에 다음 주간 갱신일도 바뀐다. 기존 갱신일까지 며칠 남았더라도 새 주간 창이 시작된다. 단순히 한 주 분량을 덧붙이는 쿠폰과는 다르다. (help.openai.com)

예를 들어 월요일이 원래 갱신일인데 일요일에 banked reset을 쓰면 다음 날 기존 일정에 맞춰 다시 채워지지 않는다. 공식 문서상 새 갱신일은 리셋을 사용한 흐름에 맞춰 이동한다. 사용 직전에는 남은 비율과 기존 갱신 시각을 함께 확인해야 한다.

써본 사람들 사이에서는 이 구조를 뒤늦게 알아 손해처럼 느꼈다는 반응이 적지 않았다. 갱신을 몇 시간 앞두고 리셋을 실행했거나 화면의 사용량이 늦게 반영돼 적용 여부를 판단하기 어려웠다는 경험도 나왔다. 다만 개별 계정의 급격한 소진을 리셋 기능의 결함으로 단정할 공식 근거는 없다.

업무가 급하지 않다면 갱신 직전 사용은 효율이 낮다. 반대로 주간 한도를 많이 썼고 며칠 동안 집중 개발해야 한다면 저장된 리셋의 가치가 커진다. 만료가 더 빠른 리셋부터 확인하되 실행 뒤 갱신일이 어떻게 바뀌는지도 기록해야 한다.

Claude 리셋은 기존 주간 일정을 유지한다

Claude의 limit reset은 Codex와 이름은 비슷하지만 주간 일정 처리 방식이 다르다. Anthropic 도움말에 따르면 제공된 리셋은 5시간 세션 한도나 주간 한도 가운데 표시된 항목을 즉시 채운다. 주간 리셋을 사용해도 원래 정해진 정기 갱신 시각은 유지된다. (support.claude.com)

Claude Max에는 기본적으로 5시간 단위 사용 한도와 주간 한도가 있다. claude.ai, Claude Desktop, Claude Code에서 쓴 양은 같은 계정 한도에 합산된다. 모델, 대화 길이, 첨부 파일, 도구, effort 수준에 따라 소모량도 달라진다. (support.claude.com)

Claude 리셋은 웹이나 Claude Desktop의 Settings > Usage에서 Reset for free를 눌러 사용한다. 터미널의 Claude Code와 모바일 앱에는 현재 실행 버튼이 없다. 웹에서 적용하면 같은 계정의 Claude Code 한도도 복구된다.

Codex와의 차이는 선명하다. Claude의 주간 리셋은 기존 정기 갱신일을 보존하지만 Codex full banked reset은 주간 날짜를 변경한다. 두 제품의 리셋권을 같은 기준으로 계산하면 사용 시점을 잘못 고르기 쉽다.

리셋권·즉시 리셋·사용 크레딧은 서로 다른 상품이다

Codex에는 banked reset 외에도 구매형 instant reset과 usage credits가 있다. 구매형 리셋은 결제가 끝나면 바로 적용되며 나중을 위해 저장할 수 없다. 다음 Work 또는 Codex 요청부터 새 주간 기간이 시작된다. 그 요청의 7일 뒤가 다음 자동 갱신일이 된다. (help.openai.com)

Usage credits는 한도를 초기화하지 않는다. 플랜에 포함된 사용량을 모두 쓴 뒤 작업량에 따라 차감되는 별도 잔액이다. Plus와 Pro에서 지원될 경우 Codex와 ChatGPT Work 등 여러 기능이 같은 agentic allowance와 크레딧 풀을 공유할 수 있다. (help.openai.com)

Claude도 usage credits를 제공한다. 기본 한도를 넘긴 뒤 표준 API 요율에 따른 종량제로 계속 작업하는 구조다. 크레딧을 사용해도 5시간 한도의 정상 갱신 시점은 바뀌지 않으며 구독료와 별도로 청구된다. (support.claude.com)

개인 개발자라면 며칠간 큰 리팩터링을 진행할 때 리셋이 적합할 수 있다. 반면 간헐적으로 한도만 조금 넘는다면 크레딧이 지출을 통제하기 쉽다. 소규모 팀은 기능 이름보다 ‘전체 한도를 다시 채우는가’와 ‘초과분만 결제하는가’를 기준으로 골라야 한다.

명령어보다 Usage 화면을 먼저 확인해야 한다

리셋 적용의 기준 화면은 두 서비스 모두 Usage 설정이다. Codex CLI의 /status는 현재 상태를 확인하는 명령이지만 banked reset을 생성하는 명령은 아니다. Codex에서는 웹이나 데스크톱 앱, 지원되는 Usage 화면에서 남은 리셋 수와 만료일을 확인한다. (help.openai.com)

버튼이 보이지 않는다면 새 계정을 다시 만들거나 곧바로 업그레이드할 이유는 없다. 먼저 올바른 개인 계정과 워크스페이스인지 확인하고 Usage 화면을 새로 열어야 한다. 프로모션의 대상 기간과 지역 조건을 충족했는지도 살펴야 한다.

적용 뒤에는 사용 비율, 만료일, 다음 주간 갱신 시각을 캡처해 두는 편이 안전하다. OpenAI도 문제가 이어질 때 해당 화면과 실행 시각, 시간대, 사용한 클라이언트와 모델을 지원 요청에 포함하라고 안내한다.

리셋권의 가치는 버튼 하나보다 그 버튼이 다음 사용 주기를 어떻게 바꾸는지 아는 데서 결정된다.

자주 묻는 질문

Q

Codex banked reset을 쓰면 다음 주간 리셋 날짜가 바뀌나요?

네. full banked reset은 5시간과 주간 사용 창을 복구하고 주간 갱신일도 변경합니다. 기존 자동 갱신이 임박했다면 남은 시간을 확인한 뒤 사용하는 편이 낫습니다.

Q

Claude Code 터미널에서 리셋 명령어를 실행할 수 있나요?

현재 리셋 실행 버튼은 Claude 웹과 Claude Desktop의 Settings > Usage에 있습니다. 그곳에서 적용하면 같은 계정으로 사용하는 Claude Code의 한도도 복구됩니다.

Q

구독을 업그레이드하면 리셋권을 반드시 받을 수 있나요?

아닙니다. 리셋권은 특정 프로모션과 계정 자격에 따라 지급되며 플랜 변경만으로 보장되지 않습니다. 결제 전에 해당 계정의 Usage 화면과 공식 공지를 확인해야 합니다.

Q

AI 사용량 리셋과 usage credits의 차이는 무엇인가요?

리셋은 지정된 사용 한도를 다시 채우지만, 크레딧은 기본 한도를 넘긴 뒤 종량제로 차감됩니다. Codex 리셋은 종류에 따라 다음 주간 갱신일도 바꿀 수 있습니다.
