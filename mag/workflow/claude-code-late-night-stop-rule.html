클로드 코드가 멈추기 어려운 이유, 밤 11시 종료 규칙은 어떻게 지킬까

에이전트가 계속 결과를 내놓을 때 작업을 끊기 어려운 이유와, 다음 날 다시 시작할 수 있게 세션을 마무리하는 방법

2026-09-29논의 1회 정리

에이전트가 방금 테스트를 통과했다. 새 아이디어 하나만 더 맡기면 금방 끝날 듯하다. 클로드 코드 작업을 밤 11시에 멈추자는 규칙은 이 순간 어떻게 지킬 수 있을까? 이 기사는 산출물이 다음 작업을 부르는 구조를 살피고, 진행 상황을 잃지 않으면서 작업을 닫는 방법을 묻는다.

결과가 나올수록 다음 작업을 시작하기 쉽다

클로드 코드는 질문에 답하고 기다리는 챗봇과 다르다. 파일을 읽고 명령을 실행하며 코드를 고친 뒤 결과까지 확인할 수 있다. Anthropic의 사용 가이드는 개발자가 자리를 비운 동안에도 작업을 이어갈 수 있다고 설명한다. 수정된 코드나 통과한 테스트를 보면 사람은 바로 다음 요청을 떠올리기 쉽다. (code.claude.com)

커뮤니티에서도 결과물이 쌓일수록 자리를 뜨기 어렵다는 경험이 공유됐다. 피곤해지면 접기 쉬운 다른 취미와 달리 개발에는 끝나지 않은 할 일이 계속 생긴다는 의견이었다. 게임과 어느 쪽이 더 강하게 사람을 붙드는지 입증한 비교는 아니다. 살펴볼 대목은 작업 시간이 처음 정한 범위를 넘는 순간이다.

써본 사람들 사이에서는 잠을 줄여가며 다음 프로젝트를 구상한다는 반응도, 긴 작업은 맡겨두고 자리를 비운다는 반응도 나온다. 같은 도구라도 사람마다 종료 기준이 다르다. Anthropic이 분석한 약 40만 건의 클로드 코드 세션에서는 사람이 주로 *무엇을 할지* 정하고, 에이전트가 주로 *어떻게 할지* 정했다. 새 과제를 시작하는 결정은 여전히 사용자에게 남아 있다. (anthropic.com)

‘중독’이라는 표현보다 살펴야 할 것은 수면과 작업 통제다

밤늦게 코딩했다는 이유만으로 임상적 중독을 말할 수는 없다. 세계보건기구의 게임이용장애 기준은 통제력 저하, 다른 활동보다 높은 우선순위, 부정적 결과에도 계속하는 양상을 다룬다. 그 기준을 에이전트 개발에 그대로 옮겨 진단할 수도 없다. 커뮤니티의 ‘중독성’은 우선 멈추기 어렵다는 경험을 표현한 말로 읽어야 한다. (who.int)

그렇다고 수면 손실을 가벼운 농담으로 넘길 일도 아니다. 미국 질병통제예방센터는 성인에게 하루 최소 7시간의 수면을 권한다. 수면 부족과 의사결정을 검토한 2025년 연구는 위험한 선택이 늘어난 연구들을 확인했다. 다만 과제와 수면 부족의 정도에 따라 결과가 달라 늦게 작업한 모든 사람이 같은 실수를 한다고 말할 수는 없다. (cdc.gov)

혼자 제품을 만드는 사람에게 심야의 한 시간은 단순한 작업량이 아니다. 그때 무엇을 고치고 무엇을 보류할지 판단해야 한다. 다음 날에는 변경분도 다시 검토해야 한다. 밤 11시 제한은 모두에게 맞는 의학적 기준이 아니라 커뮤니티가 제안한 개인 규칙이다. 자신의 수면 시간에 맞춰 종료 시각을 정하되, 시각만 정하고 작업을 무한히 이어갈 여지를 남겨서는 효과를 기대하기 어렵다.

밤 11시에 멈추려면 종료 산출물부터 정한다

가령 작은 웹 서비스의 로그인 오류를 고치는 중이라고 하자. 작업 시작 전에 클로드 코드에 관련 파일과 재현 상황, 통과해야 할 테스트를 알려준다. 복잡한 변경이라면 먼저 plan mode에서 탐색과 구현 계획을 검토한다. Anthropic의 가이드는 테스트나 빌드처럼 통과 여부를 확인할 수 있는 기준을 주고 작업 뒤에는 실행 결과를 확인하라고 권한다. (code.claude.com)

종료 시각이 가까워지면 새 기능 대신 인수인계 내용을 요청할 수 있다. 예를 들면 이렇게 묻는다. “여기서 새 수정은 시작하지 마. 바뀐 파일, 실행한 테스트와 결과, 아직 확인하지 못한 사항, 다음에 먼저 볼 파일을 요약해 줘.” 입력은 현재 세션의 변경 사항이고, 산출물은 다음 작업을 위한 짧은 기록이다. 요약을 받았더라도 테스트가 통과하지 않았다면 그 상태를 그대로 남긴다.

에이전트가 아직 실행 중이라면 Esc로 중단할 수 있다. 공식 문서에 따르면 중단해도 대화 맥락은 보존된다. 다음 날 같은 작업을 이어갈 때는 claude --continue를 쓰고, 여러 세션 중에서 고르려면 claude --resume을 쓴다. 세션에 /rename으로 이름을 붙여두면 찾기도 쉽다. 변경 사항의 최종 확인은 대화 요약만 믿지 말고 코드 차이와 테스트 결과로 해야 한다. (code.claude.com)

자동 완료와 사람의 퇴근은 별개의 문제다

클로드 코드에는 작업 완료 시 실행되는 Stop hook이 있다. 그러나 이름만 보고 밤 11시에 사람의 작업을 끝내주는 기능으로 생각하면 곤란하다. Stop hook은 에이전트가 응답을 마치려 할 때 검사나 알림을 실행하는 장치다. 테스트 실패 시 종료를 막는 용도로도 쓰인다. 시각에 맞춰 새 작업을 시작하지 않겠다는 판단은 별도로 내려야 한다. (code.claude.com)

오히려 종료 직전에 자동 검증을 끝없이 요구하면 잠자리에 들 시간이 밀릴 수 있다. 공식 문서는 Stop hook이 반복해서 종료를 막을 수 있다고 설명한다. 밤의 경계에는 ‘모든 문제를 해결했다’보다 ‘현재 상태를 확인했고, 남은 문제를 기록했다’가 실용적인 완료 조건일 수 있다. 검증 실패를 숨기지 않은 채 일을 멈추는 선택이다.

방에서 제안된 오후 11시 규칙의 핵심도 클로드 코드의 속도를 낮추는 데 있지 않다. 다음 요청을 보내지 않아도 내일 다시 시작할 수 있게 만드는 데 있다. 밤에 떠오른 아이디어를 즉시 실행하는 대신 다음 과제로 남겼을 때, 에이전트가 만든 산출물은 하루의 연장 사유가 아니라 다음 날 작업의 출발점이 된다.

자주 묻는 질문

Q

클로드 코드를 밤에 중단하면 다음 날 같은 작업을 이어갈 수 있나요?

가능하다. 실행 중에는 Esc로 중단할 수 있고, 이후 claude --continue 또는 claude --resume으로 저장된 세션을 이어갈 수 있다.

Q

Stop hook으로 밤 11시 종료 규칙을 설정하면 되나요?

Stop hook은 에이전트가 응답을 끝내려 할 때 실행되는 기능이지, 정해진 시각에 사람의 작업을 종료하는 기능은 아니다. 종료 시각에는 새 과제를 시작하지 않고 현재 변경 사항과 미해결 항목을 기록하는 규칙이 따로 필요하다.

Q

클로드 코드 작업을 오래 하는 것이 곧 중독인가요?

작업 시간이 길다는 사실만으로 진단할 수 없다. 계획보다 자주 늦게 끝나는지, 수면과 다른 활동에 어떤 영향을 주는지 살펴보는 편이 정확하다.
