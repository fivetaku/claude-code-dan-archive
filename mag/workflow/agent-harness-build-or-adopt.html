AI 에이전트 하네스, 직접 만들까 기존 구현을 가져올까

직접 만든 하네스를 버릴지 고민된다면, 재사용할 실행 구조와 직접 설계할 검증 조건을 나눠야 한다. 공개 구현 두 가지로 그 경계를 살펴본다.

2026-11-09논의 1회 정리

하네스를 직접 만들다 막혔다면 계속 개발해야 할까, 아니면 공개 구현으로 갈아타야 할까. 클코단에서는 수주간 실행 환경을 다듬던 참여자가 재사용할 구현을 찾으면서 이 질문이 나왔다. 이미 가져다 쓸 수 있는 하네스가 공개된 지금, 중요한 판단은 직접 작성한 코드의 양보다 무엇을 재사용하고 무엇을 남길지다. (langchain.com)

가져올 수 있는 것은 실행 구조이지 업무의 정답이 아니다

Microsoft의 Agent Framework 문서는 하네스를 모델을 실제 작업자로 만드는 실행 기반으로 설명한다. 모델과 도구를 호출하고 대화 상태와 문맥을 관리하며 승인 정책을 적용하는 구조다. 긴 프롬프트 하나나 지침 파일만을 가리키는 말은 아니다. (learn.microsoft.com)

따라서 기존 하네스를 가져오면 반복 호출, 상태 관리, 도구 연결을 전부 다시 구현할 필요가 줄어든다. LangChain은 이 선택을 층위로 구분한다. Deep Agents는 기능을 갖춘 하네스이고, LangChain은 조립용 구성요소이며, LangGraph는 실행 흐름을 세밀하게 설계하는 기반이다. (langchain.com)

하지만 어떤 결과를 성공으로 인정할지는 별개다. Anthropic의 장기 작업 실험에서는 에이전트가 코드를 수정하고도 실제 사용자 동작을 검증하지 않은 채 완료를 선언했다. 연구진은 기능 목록과 브라우저 기반 검증을 실행 과정에 넣었다. (anthropic.com)

방에서는 다른 구현을 경험하면 자기 환경에 맞춰야 하는 영역도 드러난다는 의견이 나왔다. 이 의견을 채택한다면 기존 구현은 완제품보다 비교 기준에 가깝다. 지금 만든 구조에서 어떤 문제가 사라지고 어떤 문제가 그대로 남는지 확인할 대상이다.

Deep Agents는 반복해서 만들던 기능을 묶어 제공한다

계획, 파일 기반 문맥 관리, 하위 에이전트 위임이 필요하다면 Deep Agents가 비교 대상이다. LangChain 공식 문서는 이를 복잡한 다단계 작업용 하네스로 소개한다. SDK를 자기 프로세스에서 실행하고 필요한 모델과 도구를 연결하는 방식이다. (github.com)

공식 Quickstart의 흐름은 구체적이다. Python 환경에 pip install -U deepagents로 패키지를 설치하고, 선택한 모델 제공자의 연동 패키지와 인증을 준비한다. 다음으로 검색 도구를 정의한 뒤 create_deep_agent에 model, tools, system_prompt를 전달한다. (docs.langchain.com)

실행할 때는 agent.invoke에 사용자 메시지를 넣는다. 공식 예제는 조사 질문을 입력하고 검색을 거쳐 보고서 응답을 얻는 구성이다. 개발자가 새로 작성하는 부분은 질문의 범위, 사용할 도구, 결과물의 조건이다. 모델과 도구를 번갈아 호출하는 전체 루프를 직접 작성하는 예제가 아니다. (docs.langchain.com)

파일을 다룬다는 표현도 구분해야 한다. 공식 백엔드 문서는 상태 안의 파일, 장기 저장소, 실제 디스크를 서로 다른 선택지로 제공한다. FilesystemBackend는 실제 파일을 읽고 쓰지만, 다른 백엔드까지 모두 로컬 작업 폴더를 수정하는 것은 아니다. (docs.langchain.com)

개인 개발자에게 이 구분은 도입 범위를 정하는 데 유용하다. 예를 들어 문서 조사 기능을 만드는 상황이라면 보고서 생성과 저장부터 비교할 수 있다. 처음부터 코드 실행이나 다중 에이전트까지 모두 붙여야 기존 구현의 가치를 확인할 수 있는 것은 아니다.

실행 과정을 이해하려면 mini-swe-agent가 다른 출발점이다

반대로 직접 만든 루프가 왜 실패하는지 파악하려면 작은 구현이 비교하기 편하다. SWE-agent/mini-swe-agent 공식 저장소는 Bash 중심의 도구 사용과 선형 메시지 이력을 핵심 설계로 설명한다. 에이전트 클래스뿐 아니라 모델, 실행 환경, 실행 스크립트도 분리해 살펴볼 수 있다. (github.com)

공식 시작 문서에 따르면 pip install mini-swe-agent로 설치한 뒤 mini를 실행하면 된다. 최초 설정에서 모델을 연결하며, 설정을 다시 진행할 때는 mini-extra config setup을 사용한다. 소스를 수정하려면 저장소를 복제하고 pip install -e .로 개발용 설치를 진행한다. (mini-swe-agent.com)

입력도 추상적인 목표일 필요가 없다. 공식 예제에는 현재 프로젝트의 pytest 실패를 조사하고 수정한 뒤 다시 검증하는 작업이 있다. 독자는 테스트용 프로젝트에서 같은 종류의 요청을 실행하고 코드 변경과 테스트 결과를 대조할 수 있다. 실행 이력은 별도 출력 형식으로 남아 분석에 활용할 수 있다. (mini-swe-agent.com)

두 구현은 같은 이유로 선택하는 도구가 아니다. Deep Agents는 여러 기능을 조립하는 수고를 줄이는 방향이고, mini-swe-agent는 작은 실행 구조를 이해하고 변경하는 데 초점을 둔다. 복잡한 업무 기능이 필요한지, 기본 루프를 통제하고 싶은지에 따라 비교의 출발점이 달라진다. (langchain.com)

직접 남겨야 할 코드는 완료 조건과 권한 경계다

공개 하네스를 설치했다는 사실만으로 프로젝트가 끝까지 안정적으로 진행되지는 않는다. Anthropic의 장기 작업 사례는 초기 환경 구성과 후속 구현 작업을 나눴다. 기능별 완료 상태, 진행 기록, 개발 서버를 시작하는 init.sh를 마련해 다음 세션이 작업을 이어받게 했다. (anthropic.com)

이 구조를 응용한다면 입력은 막연한 개발 목표가 아니라 검증 가능한 기능 목록이 된다. 예컨대 주문 화면에서는 버튼이 존재하는지와 주문이 저장되는지를 별도로 확인할 수 있다. 산출물도 코드만이 아니라 테스트 결과와 미완료 항목을 포함하도록 설계할 수 있다. 이 예시는 특정 방 참여자의 구현을 복원한 것이 아니라 공개 사례를 적용하는 방법이다.

권한 역시 지침 문장으로만 처리할 문제가 아니다. LangChain은 FilesystemBackend가 실제 디스크 접근을 제공하므로 민감한 파일이 노출될 수 있다고 경고한다. 웹 서버나 HTTP API에는 다른 저장 방식 또는 샌드박스를 사용하도록 안내한다. (docs.langchain.com)

같은 문서는 셸 실행 권한이 있으면 경로 제한만으로 안전을 보장할 수 없다고 명시한다. 파일 접근 범위와 명령 실행 환경을 따로 설계해야 하는 이유다. 소규모 팀이 재사용으로 아낀 시간을 투입할 곳은 자체 루프의 재작성보다 이런 경계의 검증이다. (docs.langchain.com)

수주간 만든 결과는 같은 작업으로 비교해야 판단할 수 있다

방에서는 직접 겪은 시행착오에도 가치가 있다는 격려가 있었다. 다만 학습에 도움이 됐다는 평가와 앞으로도 자체 구현을 유지해야 한다는 판단은 다르다. 이미 들인 시간은 다음 기능을 추가할 이유가 되지 못한다.

비교 방법으로는 작은 회귀 작업 묶음이 적합하다. 기존에 실패했던 요청, 기대 산출물, 통과할 테스트를 고정하고 자체 구현과 공개 구현에 각각 적용하는 것이다. 성공 여부뿐 아니라 재시도, 사람의 개입, 실행 비용도 함께 기록하는 비교를 제안한다.

LangChain도 하네스 개선 사례에서 실행 추적으로 실패 양상을 찾고 수정한 구성을 다시 평가하는 과정을 설명했다. Anthropic의 에이전트 설계 문서 역시 측정 가능한 개선이 있을 때 복잡도를 높이라는 원칙을 제시한다. 기능이 많다는 사실보다 실패가 실제로 줄었는지가 판단 근거다. (langchain.com)

그래서 이 사례의 선택은 전부 직접 만들기와 전부 버리기 사이에 있지 않다. 공통 실행 구조를 교체하되, 그동안 발견한 실패 조건을 테스트로 남기는 방식이 가능하다. 자체 코드가 살아남을 근거는 만든 사람의 애착이 아니라 같은 작업에서 입증한 차이다.

자주 묻는 질문

Q

AI 에이전트 하네스는 어디서 구할 수 있나요?

LangChain의 Deep Agents와 SWE-agent의 mini-swe-agent가 공개 구현이다. 기능을 묶어 사용하려는 목적과 작은 실행 루프를 이해하려는 목적을 구분해 선택할 수 있다. (langchain.com)

Q

하네스를 가져오면 직접 구현할 부분이 없어지나요?

프로젝트별 완료 조건과 검증 절차는 별도로 설계해야 한다. 파일 접근과 셸 실행 권한도 실행 환경에 맞게 설정해야 한다. (anthropic.com)

Q

mini-swe-agent는 어떻게 시작하나요?

pip install mini-swe-agent로 설치하고 mini를 실행한다. 최초 모델 설정을 마친 뒤 테스트용 프로젝트에서 수정 요청을 입력하는 것이 공식 시작 절차의 기본 흐름이다. (mini-swe-agent.com)
