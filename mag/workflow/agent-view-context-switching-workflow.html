에이전트 세션을 늘려도 집중력을 잃지 않는 법: Agent View의 역할과 한계

여러 작업을 동시에 맡기면 기다리는 시간은 줄어든다. 하지만 세션을 확인하고 판단하는 일까지 줄어들까?

2026-10-22논의 1회 정리

에이전트에게 일을 나눠 맡기면 기다리는 시간은 줄지만, 열린 세션마다 진행 상황을 확인하는 일은 사람에게 남는다. 작업 중 논문을 읽다가 완료 알림을 받고 돌아오는 방식은 왜 편하고, 세션을 더 늘리는 방식은 왜 버거울까? 답은 병렬 실행 자체보다 언제 돌아와 무엇을 확인해야 하는지에 있다.

세션을 늘리면 확인할 일도 늘어난다

커뮤니티 논의에서는 세션과 브라우저 탭을 계속 추가할수록 작업의 맥락을 다시 떠올리기 어렵다는 의견이 나왔다. 에이전트가 코드를 작성하는 동안에도 사람은 각 작업의 목표와 맡긴 범위, 아직 내리지 않은 결정을 기억해야 한다. 창을 하나 더 여는 일과 일을 하나 더 감독하는 일은 다르다.

소프트웨어 개발자 141명을 조사한 연구에서 응답자의 81%는 작업 전환을 일종의 방해로 여겼다. 연구진은 인지적 부담과 집중력 저하를 응답자들이 꼽은 주요 이유로 설명했다. 다만 이 설문은 에이전트 사용자를 측정한 결과가 아니다. 에이전트 세션이 몇 개부터 과하다는 기준으로 읽어서는 안 된다. (arxiv.org)

기다리는 동안 다른 일을 하는 방식에도 차이가 있다. 커뮤니티에서는 에이전트에게 작업을 맡긴 뒤 논문을 읽고 완료 알림이 오면 원래 작업으로 돌아오는 흐름이 효율적이라는 의견이 있었다. 세션을 차례로 들여다보는 대신 돌아올 시점을 정해 두는 방식이다. 다만 읽던 논문의 맥락에서 코드 검토로 넘어갈 때 드는 비용까지 알림이 없애 주지는 않는다.

Agent View는 탭 대신 작업 상태를 보여준다

Anthropic이 공개한 Claude Code의 Agent View는 백그라운드 세션을 한 화면에 모은다. 터미널에서 claude agents를 실행하면 작업 중인 세션, 입력을 기다리는 세션, 끝난 세션을 구분해 볼 수 있다. 기존 세션은 /bg로 보내고 새 작업은 claude --bg "작업 지시"로 시작할 수 있다. Anthropic은 이 기능을 연구 프리뷰로 제공하며 화면과 단축키가 바뀔 수 있다고 명시한다. (claude.com)

예를 들어 작은 팀이 오류 수정과 테스트 실패 원인 조사를 분리한다고 해 보자. 각 세션에 수정 범위와 원하는 결과를 적어 맡긴 뒤 사람은 다른 창에서 문서를 검토한다. 돌아왔을 때 모든 대화 기록을 처음부터 읽지는 않는다. 먼저 어떤 세션이 질문 때문에 멈췄고 어떤 세션이 결과를 냈는지 확인한다.

Agent View에서 행을 선택하고 Space를 누르면 최근 질문이나 결과를 살펴볼 수 있다. 짧은 답은 그 자리에서 보내고 변경 과정 전체가 필요하면 세션에 들어간다. 일반 터미널에서 연 대화는 백그라운드로 보내기 전까지 목록에 나타나지 않는다. 한 화면에 모인다는 말은 모든 대화와 하위 에이전트가 각각 표시된다는 뜻은 아니다. (code.claude.com)

알림을 기다리는 동안에도 복귀 단서는 남겨야 한다

Anthropic 문서에 따르면 Agent View가 열려 있을 때 백그라운드 세션이 입력을 요청하거나 종료되면 터미널 알림을 보낼 수 있다. Notification hook으로 데스크톱 알림을 설정하는 방법도 안내한다. 완료 여부를 확인하려고 주기적으로 탭을 열 필요는 줄어든다. 알림 설정과 전달은 사용 환경에서 확인해야 한다. (code.claude.com)

알림이 해결하지 못하는 문제는 ‘내가 왜 이 일을 맡겼는가’다. 세션을 시작할 때 작업 목표와 제외할 범위, 완료 뒤 확인할 증거를 지시에 넣으면 복귀가 쉬워진다. 오류 수정이라면 재현 조건과 테스트 결과를 요청하고, 조사라면 확인한 사실과 남은 의문을 나눠 달라고 할 수 있다. 결과가 도착했을 때 사람은 긴 대화를 재구성하기보다 처음 정한 기준과 대조한다.

논문을 읽고 돌아오는 흐름도 마찬가지다. 읽던 곳과 작업에 반영할 만한 생각을 짧게 남겨야 두 맥락을 모두 되살릴 수 있다. 연구 자료에서 발견한 주장을 곧바로 에이전트의 상시 지침으로 넣기보다 원문과 적용 조건을 먼저 확인하는 편이 낫다. 커뮤니티에서 제안된 ‘읽은 내용을 파이프라인에 흡수하는’ 구상은 흥미롭지만 논문 읽기만으로 개선이 자동으로 일어나는 기능은 아니다.

여러 에이전트가 만든 결과는 따로 검토해야 한다

Agent View는 세션을 모아 보여주지만 결과물을 하나로 합치지는 않는다. Anthropic 문서에 따르면 Git 저장소의 백그라운드 세션은 작업을 별도 worktree에서 진행할 수 있다. Git 저장소 밖에서는 같은 작업 디렉터리에 기록할 수 있으므로 여러 세션에 동일한 파일 수정을 맡길 때 주의가 필요하다. 세션 목록이 깔끔해져도 변경 파일과 테스트 결과를 대조하는 일은 남는다. (code.claude.com)

병렬 실행의 비용도 확인해야 한다. Anthropic은 백그라운드 세션에도 일반 세션과 같은 사용량 제한이 적용된다고 설명한다. 여러 작업을 동시에 끝내는 속도와 사용량을 아끼는 목표는 같지 않다. 한 파일을 순서대로 고쳐야 하는 일이라면 세션을 늘리는 편이 오히려 검토를 복잡하게 만든다. (code.claude.com)

써본 사람들 사이에서도 상태를 한눈에 보는 편리함과 승인·결과 통합은 여전히 사람이 맡는다는 반응이 함께 나온다. Agent View가 줄이는 것은 ‘어느 탭에 무엇이 있나’라는 탐색이다. ‘이 결과를 받아들여도 되나’라는 판단까지 대신하지는 않는다. (code.claude.com)

읽은 지식을 다음 작업에 반영하는 방법은 별개다

커뮤니티에서는 논문에서 얻은 내용을 이후 에이전트 작업에 반영하는 self-conditioning 구상도 언급됐다. 여기에는 서로 다른 두 단계가 있다. 이번 조사나 코딩 작업의 지시를 바꾸는 일과 다음 세션에도 적용할 프로젝트 규칙을 남기는 일이다. 구분하지 않으면 아직 검증하지 않은 아이디어가 모든 작업의 전제가 될 수 있다.

Claude Code 문서는 프로젝트 전반에 필요한 규칙은 CLAUDE.md에, 필요할 때 쓰는 반복 절차는 skill에 두도록 안내한다. 따라서 읽은 논문에서 가설을 얻었다면 현재 작업에서 적용 범위와 확인 방법을 정해 시험할 수 있다. 결과가 반복해서 유효할 때 비로소 상시 규칙이나 재사용 절차로 옮길 이유가 생긴다. 이 과정은 도구가 보장하는 자동 학습이 아니라 사람이 검증하고 기록하는 작업이다. (code.claude.com)

여러 세션을 감독하면서 다른 공부까지 병행하려는 개인 개발자에게 필요한 것은 더 많은 창이 아니다. 세션마다 돌아올 조건과 검토 기준을 남기고 알림이 왔을 때 필요한 맥락만 다시 불러오는 흐름이다. Agent View는 그 복귀 지점을 찾게 해준다. 다음 과제는 세션 수를 늘리는 일이 아니라 돌아온 사람이 판단할 근거를 결과에 얼마나 남겼는가다.

자주 묻는 질문

Q

Claude Code Agent View는 어떻게 실행하나요?

터미널에서 claude agents를 실행하면 백그라운드 세션 목록이 열린다. 기존 세션은 /bg로 보내거나 새 작업을 claude --bg "작업 지시"로 시작할 수 있다.

Q

Agent View를 쓰면 작업 전환 비용이 없어지나요?

세션의 상태와 질문을 찾는 수고는 줄일 수 있다. 다만 작업 목표를 다시 떠올리고 결과를 검토하는 인지적 비용까지 없애지는 못한다.

Q

논문에서 읽은 내용을 에이전트가 자동으로 학습하나요?

읽은 내용을 다른 작업의 규칙으로 자동 반영하는 것은 아니다. 적용 조건을 확인해 현재 작업에서 시험한 뒤, 반복해서 필요한 규칙만 CLAUDE.md나 skill에 기록할 수 있다.
