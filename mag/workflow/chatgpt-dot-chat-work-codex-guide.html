ChatGPT Dot·Chat·Work·Codex, 무엇을 어디에 써야 하나

일상 질문부터 장기 업무와 코드 수정까지 네 도구의 경계를 실제 작업 순서로 비교했다

2026-11-22논의 1회 정리

ChatGPT에 Chat, Work, Codex, Dot이 함께 보이기 시작하면서 “무엇을 어디에 맡겨야 하나”라는 질문이 커졌다. 네 기능은 모두 대화형 AI처럼 보이지만 맡는 일과 실행 환경은 다르다. 이 글은 짧은 질문, 완성된 업무 결과물, 코드 작업, 장기 프로젝트 조율을 어떤 순서로 나눠야 하는지 설명한다.

네 기능의 차이는 답변 길이가 아니라 작업 방식에 있다

Chat은 빠른 대화와 일상적인 질문에 맞는다. 아이디어를 정리하거나 문장을 다듬고 개념을 물어보는 일처럼 사용자가 매 단계 방향을 정하는 작업이 기본이다. ChatGPT 도움말도 Chat을 빠른 대화형 지원으로 설명한다.

Work는 여러 단계가 필요한 결과물을 만든다. 연결된 파일과 앱을 살펴보고 조사·분석을 거쳐 보고서나 표, 발표 자료 같은 산출물을 완성하는 방식이다. 사용자는 진행 중간에 질문에 답하거나 방향을 바꿀 수 있다.

Codex는 소프트웨어 개발 전용 작업 공간에 가깝다. 저장소를 읽고 파일을 수정하며 테스트를 실행한 뒤 변경 내용을 검토할 수 있다. “이 오류의 원인을 찾아 고치고 테스트 결과를 보여 달라”처럼 입력과 산출물이 분명한 개발 작업에 적합하다.

Dot은 직접 결과물을 만드는 네 번째 편집기가 아니다. OpenAI는 Dot을 ChatGPT 안에서 프로젝트를 계속 추적하는 상시형 에이전트로 설명한다. Dot은 필요할 때 Work나 Codex 작업을 시작하거나 기존 작업을 이어갈 수 있다.

단순한 선택표로 정리하면 이렇다. 질문과 초안은 Chat, 여러 자료를 묶은 결과물은 Work, 코드와 테스트는 Codex, 여러 작업을 계속 챙기는 조율은 Dot이다.

Dot은 Codex를 대체하지 않고 작업을 연결한다

Dot을 코딩 도구로만 보면 역할이 흐려진다. Dot이 “계산기 프로젝트의 잘못된 입력 처리를 확인하고 수정한 뒤 테스트 결과를 알려 달라”고 요청받았다고 하자. 실제 파일을 읽고 수정하는 작업은 선택한 실행 환경에서 이뤄진다. Dot은 작업을 시작하거나 진행 상황을 확인할 수 있다.

OpenAI 공식 안내에 따르면 Dot이 Work나 Codex에 위임한 작업은 해당 기능의 사용량에 포함된다. Dot과 나눈 일반 대화 자체와 위임 작업의 비용 구조를 같은 것으로 보면 안 된다.

이 구분은 1인 개발자에게 특히 중요하다. Dot에 모든 일을 몰아주면 대화는 편해지지만 코드 변경의 근거와 테스트 결과를 직접 확인하는 단계가 사라지기 쉽다. 코드를 실제로 바꾸는 요청은 처음부터 Codex 작업으로 좁히고, Dot은 반복 확인이나 다음 작업 연결에 쓰는 편이 추적하기 쉽다.

실사용 반응에서도 Dot이 여러 Codex 스레드를 대신 관리해 주는 편리함을 말하는 사람이 있는 반면, 중간 승인이나 멈춤이 잦아 직접 Codex를 여는 편이 낫다는 의견도 함께 나온다. Dot의 가치는 아직 작업의 복잡도와 설정에 따라 크게 달라진다.

로컬 파일과 클라우드 작업은 실행 조건이 다르다

Codex Cloud는 OpenAI가 관리하는 컴퓨터에서 코딩 작업을 실행한다. 준비된 환경에는 저장소, 도구, 의존성, 접근 설정이 들어간다. 작업은 별도 작업 공간에서 실행되므로 사용자의 컴퓨터가 잠자기 상태여도 계속 진행할 수 있다.

반대로 로컬 작업은 사용자의 컴퓨터와 연결된다. Dot이 로컬 컴퓨터에 접근하려면 데스크톱 앱에서 해당 컴퓨터를 연결하고 명시적으로 접근을 허용해야 한다. 컴퓨터가 온라인 상태여야 하며 ChatGPT 앱도 열려 있어야 한다.

클라우드와 로컬을 혼동하면 “연결했는데 파일을 못 본다”거나 “휴대폰에서 시작한 작업이 왜 내 폴더를 못 읽나” 같은 문제가 생긴다. 웹과 모바일의 Work는 사용자의 컴퓨터 파일에 직접 접근하지 않는다. 모바일에서 Codex Cloud를 이어가는 것과 데스크톱에서 실행 중인 로컬 Codex를 원격으로 확인하는 것도 별도 흐름이다.

실제 요청에는 실행 위치까지 포함해야 한다. 예를 들어 “GitHub 저장소의 테스트 실패를 Codex Cloud에서 재현하고 수정안을 제시해 달라”와 “내 컴퓨터의 현재 폴더에서 수정하고 로컬 테스트를 실행해 달라”는 서로 다른 작업이다. 전자는 공개된 환경 설정과 저장소 권한이 필요하고 후자는 로컬 접근 허용과 컴퓨터 연결이 필요하다.

Work를 쓰면 결과물과 승인 지점을 먼저 정해야 한다

Work는 “자료를 읽고 보고서를 만들어 달라”처럼 결과물의 형태가 있는 업무에 맞는다. OpenAI는 Work가 연결된 앱과 파일을 활용해 조사, 분석, 문서·스프레드시트·프레젠테이션 제작을 수행할 수 있다고 안내한다. 일정에 맞춰 한 번 실행하거나 반복 실행하고 지원되는 앱 이벤트에 반응하도록 예약할 수도 있다.

다만 예약 작업은 완료 표시가 나도 결과를 검토해야 한다. 공식 도움말은 예약 작업이 멈췄다면 일시정지 상태나 대기 중인 승인을 확인하라고 안내한다. 연결된 앱의 권한이 만료돼도 작업은 멈출 수 있다.

소규모 팀은 Work에 “매주 월요일 보고서 작성”만 적기보다 입력 자료, 출력 형식, 승인 조건을 함께 적는 편이 안전하다. 예를 들면 “지난주 GitHub 이슈와 지정된 문서만 사용해 한 페이지 보고서를 만들고 외부 발송 전에는 승인을 요청하라”처럼 경계를 정한다. 이 방식은 자동화의 편리함보다 검수 지점을 먼저 만든다.

Dot에서도 같은 원칙이 필요하다. 메시지 초안을 만들었다고 해서 자동 발송까지 허용한 것은 아니다. 연결된 앱에서 읽기 권한과 수정·전송 권한은 다를 수 있고 승인 규칙이 작업을 멈출 수 있다.

사용량은 기능 이름보다 작업의 무게가 좌우한다

ChatGPT와 Codex의 사용량 구조는 계속 통합되는 방향으로 바뀌고 있다. OpenAI는 2026년 12월부터 Plus, Pro, Business에서 ChatGPT와 Codex의 사용 allowance를 공유하는 전환을 준비 중이라고 밝혔다. Instant Chat은 이 사용량에서 제외된다고 안내했다.

Work와 Codex는 모델, 추론 수준, 도구 사용, 입력·출력 규모에 따라 소모량이 달라진다. 짧은 코드 질문 하나와 여러 파일을 읽고 테스트하는 장기 작업을 같은 “메시지 한 번”으로 계산하면 안 된다. Dot이 Codex나 Work에 위임한 작업도 해당 사용량을 차감한다.

그래서 작업을 나눌 때는 기능보다 검수 비용을 계산해야 한다. 한 번 답을 받으면 끝나는 질문은 Chat에 두고 반복되는 조사나 문서 생성은 Work로 분리한다. 코드 변경은 Codex에서 작은 단위로 실행하고 Dot은 상태 확인과 다음 작업 연결에 맡긴다.

현재 가장 현실적인 사용법은 네 기능을 경쟁시키지 않는 것이다. Chat에서 문제를 정의하고 Work에서 비개발 자료를 완성하며 Codex에서 코드와 테스트를 처리하고 Dot에서 장기 흐름을 추적한다. 어느 기능을 선택했는지보다 어디에서 실행되고 무엇을 검토해야 하는지를 분명히 적는 사용자가 더 안정적인 결과를 얻는다.

자주 묻는 질문

Q

ChatGPT Chat과 Work의 차이는 무엇인가요?

Chat은 빠른 질문과 대화형 도움에 적합합니다. Work는 여러 단계의 조사와 분석을 거쳐 문서, 표, 발표 자료 같은 완성된 결과물을 만드는 데 맞습니다.

Q

Dot이 Codex를 대신해 코드를 수정하나요?

Dot은 필요할 때 Codex 작업을 시작하거나 기존 작업을 이어가는 조율자에 가깝습니다. 실제 코드 수정과 테스트는 Codex가 수행하며, 위임된 작업은 Codex와 Work 사용량에 포함될 수 있습니다.

Q

Codex Cloud와 로컬 Codex는 어떻게 다른가요?

Codex Cloud는 OpenAI가 관리하는 컴퓨터에서 실행되어 사용자의 컴퓨터가 꺼져도 작업을 이어갈 수 있습니다. 로컬 Codex는 연결된 사용자의 컴퓨터와 앱이 온라인 상태여야 하며, 파일 접근을 별도로 허용해야 합니다.
