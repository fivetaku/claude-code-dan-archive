AI 코딩 에이전트 대기 시간을 줄이는 병렬 세션과 교차 리뷰

Claude Code와 Codex를 기다리는 시간을 병렬 작업과 검증 루프로 바꾸는 실전 운영법

2026-10-27논의 2회 정리

AI 코딩 에이전트가 코드를 읽고 수정하는 동안 개발자는 화면만 바라봐야 할까. 클코단에서는 여러 Claude Code 세션을 동시에 돌리고 GitHub 자료를 찾거나 다이어그램을 만드는 방식이 공유됐다. 이 글은 대기 시간을 줄이는 데서 출발해 Claude Code와 Codex를 어떤 순서로 나누고 어디에서 멈춰 검증해야 하는지 답한다.

대기 시간을 줄이는 핵심은 세션 수보다 작업 분리다

Claude Code는 대화형 REPL뿐 아니라 claude -p 형태의 비대화형 실행도 지원한다. 출력 형식을 JSON으로 고르거나 최대 턴 수를 제한할 수 있어 반복 작업을 스크립트와 연결하기 쉽다. Anthropic CLI 문서는 세션을 이어가거나 특정 세션을 재개하는 옵션도 제공한다.

방에서는 다섯 개에서 일곱 개 세션을 병렬로 운영한다는 경험이 나왔다. 다만 세션 수를 늘린다고 생산성이 자동으로 오르지는 않는다. 같은 파일과 브랜치를 여러 에이전트가 동시에 만지면 충돌을 정리하는 시간이 늘어나기 때문이다.

실용적인 기준은 작업의 독립성이다. 자료 조사, 테스트 작성, UI 검토, 문서 초안처럼 결과물이 분리되는 일은 병렬화한다. 반대로 같은 모듈의 설계와 구현처럼 상태를 공유해야 하는 일은 한 세션에서 이어간다.

여러 세션은 Git worktree로 서로 격리해야 한다

병렬 세션을 운영할 때 가장 먼저 나눌 것은 모델이 아니라 작업 디렉터리다. 기능 구현은 feature-auth, 테스트 보강은 test-auth, 리뷰는 별도 읽기 전용 작업공간에 배치하면 각 세션이 서로 다른 브랜치와 파일 상태를 본다.

작업 순서는 간단하다. 기준 브랜치에서 worktree를 만들고 각 디렉터리에서 Claude Code를 실행한다. 구현 세션에는 변경 범위와 성공 조건을 주고 조사 세션에는 파일 수정 금지와 산출물 위치를 명시한다. 마지막에는 사람이 diff를 비교해 하나의 브랜치로 합친다.

Codex 앱은 프로젝트별 스레드를 나누고 여러 에이전트를 병렬로 실행하는 방향을 공식 기능으로 내세웠다. OpenAI는 별도 작업을 병렬로 돌릴 때 에이전트 간 문맥을 분리하고 결과를 검토한 뒤 다음 작업으로 넘기는 운영을 강조한다. 개인 개발자라면 앱을 새로 도입하기보다 Git worktree와 터미널 세션만으로 같은 원칙을 먼저 재현할 수 있다.

써본 사람들 사이에서는 모델보다 사람이 병목이 된다는 반응도 있다. 세션마다 어떤 파일을 바꿨는지 추적하지 못하면 병렬화가 작업 속도가 아니라 확인할 목록만 늘린다는 지적이다.

토큰을 줄이려면 요청보다 읽는 범위를 먼저 줄여야 한다

AI 코딩 에이전트의 사용량은 질문 문장만으로 결정되지 않는다. 코드와 검색 결과, 로그, 도구 호출 결과가 함께 문맥에 들어간다. Anthropic은 긴 작업에서 관련 위치를 먼저 찾고 필요한 자료만 읽게 하며 반복 규칙은 CLAUDE.md 같은 메모리 파일에 짧게 정리하라고 안내한다.

작업 요청은 “예약 기능을 고쳐 달라”보다 구체적이어야 한다. “취소한 시간은 다시 예약할 수 있어야 한다. 확정 예약과 결제 대기 예약은 계속 막아야 한다. 관련 파일을 먼저 찾고 수정 뒤 해당 검사와 브라우저 동작을 확인하라”처럼 증상과 보존 조건을 함께 적는다.

로그도 전체를 매번 붙이지 않는다. 실패한 검사 이름과 오류 주변의 호출 흐름, 변경된 파일의 diff부터 보여 준다. 원인을 찾지 못했을 때만 읽는 범위를 넓힌다. 이는 응답을 짧게 만드는 기술이 아니라 에이전트가 불필요한 파일을 순회하지 않도록 탐색 순서를 바꾸는 방법이다.

프로젝트 규칙 파일에는 실행 명령과 테스트 명령, 디렉터리 구조, 절대 지켜야 할 보안 규칙만 남긴다. 긴 배경 설명은 별도 문서로 분리하고 필요할 때만 불러온다. 규칙 파일이 커지면 모든 세션이 시작할 때 같은 내용을 다시 읽게 된다.

Claude Code가 만들고 Codex가 검토하는 루프는 이렇게 구성한다

Claude Code와 Codex를 연결할 때 핵심은 역할 분담보다 경계 설정이다. 구현 담당은 파일을 수정하고 테스트를 실행한다. 리뷰 담당은 변경 내용을 읽고 결함과 누락된 조건, 보안 문제를 보고하되 직접 수정하지 않는다.

가장 안전한 흐름은 네 단계다.

  1. Claude Code가 계획을 작성하고 관련 파일을 찾는다.
  2. Codex가 계획이나 현재 diff를 읽기 전용으로 검토한다.
  3. Claude Code가 승인된 방향으로 구현하고 테스트한다.
  4. Codex가 codex review --uncommitted 또는 기준 브랜치 비교로 다시 검토한다.

Codex CLI는 현재 변경 내용과 특정 기준 브랜치와의 차이, 특정 커밋을 대상으로 리뷰할 수 있다. OpenAI의 Codex 플러그인은 Claude Code 안에서 /codex:review --background를 실행하고 결과를 확인하는 통합 방식을 제공한다. 여러 파일을 다루는 리뷰는 시간이 걸릴 수 있어 백그라운드 실행이 권장된다.

다만 “리뷰에서 지적한 내용을 다시 고치고 또 리뷰한다”는 루프를 무제한으로 돌리면 비용과 시간이 빠르게 늘어난다. 한 번의 리뷰에서 심각도와 재현 조건을 분류하고 수정 횟수와 종료 조건을 정한다. 예를 들어 테스트 실패와 데이터 손실 가능성, 인증 우회처럼 중대한 항목만 다음 루프로 넘기고 문체나 취향 차이는 사람이 판단한다.

바깥 실사용 반응에서도 계획을 먼저 검토한 뒤 구현하는 방식과 서로 다른 모델을 설계와 리뷰에 배치하는 방식이 반복해서 언급된다. 반면 세션 간 메시지를 계속 주고받으면 공유 상태가 불명확해진다는 불만도 있다. 리뷰 입력은 대화 전체보다 커밋과 diff, 테스트 결과처럼 고정된 산출물로 제한하는 편이 낫다.

다이어그램과 자료 탐색은 대기 시간에 하기 좋은 독립 작업이다

방에서 소개된 cathrynlavery/diagram-design은 Claude Code와 Codex에서 사용할 수 있는 에이전트 스킬이다. 저장소 README에 따르면 이 프로젝트는 브랜드 색상과 폰트를 반영한 자체 포함 HTML·SVG 다이어그램을 만들고 Mermaid나 draw.io 입력을 다시 그리는 기능을 제공한다.

사용 순서도 비교적 분명하다. 저장소를 가져오고 스킬을 에이전트에 등록한 뒤 “프론트엔드와 API 서버, 데이터베이스의 관계를 아키텍처 다이어그램으로 만들어 달라”처럼 구조와 산출 형식을 요청한다. 결과는 브라우저에서 열 수 있는 HTML이 되며 필요하면 SVG나 PNG로 내보낸다.

이 작업은 구현 세션과 파일을 공유하지 않을 때 대기 시간 활용도가 높다. 개발자가 기능을 기다리는 동안 다른 세션에서 README의 구조를 다이어그램으로 바꾸고 브랜드 사이트의 색상과 독자 수준을 입력해 문서용 결과물을 준비할 수 있다. 다만 다이어그램이 코드의 정확성을 대신 검증하지는 않는다. 실제 API 흐름과 화면 동작은 별도의 테스트가 필요하다.

GitHub 탐색도 같은 방식으로 분리할 수 있다. 구현에 필요한 라이브러리를 찾는 세션에는 후보 저장소와 최근 커밋, 라이선스, 설치 조건만 정리하게 한다. 에이전트가 찾은 자료를 바로 코드에 반영하지 말고 사람이나 리뷰 세션이 유지보수 상태와 보안 위험을 확인한 뒤 채택한다.

병렬화의 성과는 세션 수가 아니라 검증 가능한 산출물로 판단한다

개인 개발자와 소규모 팀에게 필요한 것은 열 개의 에이전트가 아니다. 서로 겹치지 않는 작업 목록과 변경 범위를 고정한 브랜치, 재현 가능한 테스트, 읽기 전용 리뷰어가 더 중요하다.

실전 템플릿은 다음과 같다. 구현 요청에는 증상·성공 조건·수정 범위를 넣는다. 조사 요청에는 수정 금지·출력 파일·확인할 출처를 넣는다. 리뷰 요청에는 대상 diff·중점 위험·종료 조건을 넣는다. 모든 세션은 마지막에 변경 파일과 실행한 검사, 남은 문제를 짧게 남긴다.

Claude Code의 병렬 도구 호출과 Codex의 멀티에이전트 기능은 기다리는 시간을 줄여 준다. 하지만 여러 모델을 연결하는 순간 사람의 역할은 입력자가 아니라 작업 큐와 검증 기준을 관리하는 감독자로 바뀐다. 대기 시간을 없애는 가장 현실적인 방법은 세션을 더 여는 일이 아니라 각 세션이 독립적으로 끝낼 수 있는 결과를 먼저 정의하는 것이다.

자주 묻는 질문

Q

Claude Code와 Codex를 함께 쓰는 가장 안전한 방법은 무엇인가?

Claude Code는 구현과 테스트를 맡기고 Codex는 읽기 전용 리뷰를 맡기는 방식이 안전하다. 리뷰 대상은 대화 전체보다 커밋, diff, 테스트 결과처럼 고정된 산출물로 제한하는 편이 좋다.

Q

Claude Code 여러 세션을 동시에 실행해도 되나요?

가능하지만 같은 브랜치와 파일을 동시에 수정하면 충돌이 커진다. Git worktree로 작업공간을 분리하고, 조사·테스트·문서처럼 독립적인 작업부터 병렬화해야 한다.

Q

AI 코딩 에이전트의 토큰 사용량을 줄이는 방법은 무엇인가?

질문을 짧게 만드는 것보다 관련 파일과 로그를 먼저 좁히는 편이 효과적이다. 증상과 성공 조건을 함께 쓰고, 반복 규칙은 CLAUDE.md에 간결하게 정리하며, 실패한 검사 주변부터 읽게 하라.
