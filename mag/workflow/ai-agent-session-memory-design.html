AI 에이전트 세션 기억, 요약 파일과 그래프는 언제 필요한가

짧은 진행 메모만으로 작업을 이어갈 수 있을까. 세션 압축과 맥락 누락을 줄이는 파일 계층·분기·그래프의 구현 방식과 비용 판단 기준을 살핀다.

2026-11-17논의 1회 정리

AI와 장기 프로젝트를 진행할 때 다음 세션에 넘길 메모는 얼마나 자세해야 할까. 클코단에서는 짧은 인계 기록으로 작업을 재개했다가 잘못된 답을 경험한 사례와 기억을 여러 층으로 나누는 실험이 공유됐다.

이 질문에 답하려면 요약문의 길이보다 무엇을 저장하고 다시 읽게 하는지 살펴야 한다.

짧은 요약이 실패했다고 그래프가 필요한 것은 아니다

방에서는 중심 대화의 목표를 유지하면서 세부 작업을 별도 세션에 맡기는 구상이 나왔다. 대화 순서 대신 정보 사이의 관계를 남기려는 시도였다. 다른 참여자는 간단한 인계 문서부터 시험했지만 비용을 줄일 수 있다는 AI의 설명은 아직 측정 결과가 아니었다.

이 경험만으로 짧은 메모가 환각의 원인이라고 단정할 수는 없다.

Anthropic의 컨텍스트 엔지니어링 문서는 압축, 외부 노트, 서브에이전트를 장기 작업의 서로 다른 대응책으로 설명한다. 압축은 기존 맥락을 요약하고 외부 노트는 세션 밖에 정보를 남긴다. 서브에이전트는 별도 맥락에서 탐색한 결과를 돌려준다. 세 방법은 대체재라기보다 함께 사용할 수 있는 장치다. (anthropic.com)

저장된 정보와 현재 모델에 전달된 정보는 구분해야 한다. LangChain 공식 문서도 대화 단위의 단기 기억과 대화를 넘나드는 장기 기억을 나눈다. 저장소에 기록이 있어도 다음 실행에서 필요한 내용을 읽어오도록 연결해야 한다. (docs.langchain.com)

인계 실험에서는 누락된 사실, 검색되지 않은 기록, 이미 폐기된 결정을 구별해서 기록할 필요가 있다. 세 문제를 모두 메모 분량 부족으로 처리하면 문서만 길어지고 실패 원인은 남는다.

파일 기반 기억은 목표와 실행 기록을 나눈다

구현을 확인할 수 있는 사례는 Git Context Controller, 줄여서 GCC다. 논문은 .GCC/main.md에 전체 목표와 이정표를 둔다. .GCC/branches/<branch-name>/에는 commit.md, log.md, metadata.yaml을 나눠 저장한다. 각각 진행 요약, 실행 기록, 구조화된 작업 정보를 맡는다. (arxiv.org)

사용 순서도 구체적이다. 프로젝트 목표와 할 일을 main.md에 적고 다른 접근을 시험할 때 BRANCH로 분리한다. 의미 있는 진전은 COMMIT으로 요약한다. 실험 결과를 본 작업에 반영할 때는 MERGE를 사용한다. 새 세션은 CONTEXT로 전체 현황을 확인한 뒤 필요한 분기의 상세 기록을 읽는다. (arxiv.org)

입력은 목표와 작업 과정이다. 산출물은 다음 실행이 단계적으로 읽을 수 있는 파일 묶음이다. 논문에서 이 명령은 에이전트에게 제공하는 제어 인터페이스다. 일반 터미널에 이름만 입력하면 동작하는 기본 명령은 아니다. (arxiv.org)

중심 기록에는 현재 채택한 결정을, 분기 기록에는 대안과 검증 결과를 남기는 설계로 방에서 구상한 중심 세션과 보조 세션을 평가할 수 있다.

다만 방의 실제 파일이나 구현은 제공되지 않았으므로 GCC와 같은 구조라고 볼 근거는 없다.

여러 프로젝트에서는 기억의 범위를 먼저 정한다

개인 개발자도 여러 고객이나 제품을 오가면 기억을 어디까지 공유할지 결정해야 한다. LangGraph는 체크포인터로 대화 실행 상태를 보관하고 Store로 대화를 넘어 사용할 정보를 저장한다. Store의 기억은 namespace와 key로 구분되는 문서다. (langchain-ai.github.io)

공식 사용법은 store.put(namespace, key, value)로 기록하고 store.search(namespace)로 찾아오는 방식이다. 예를 들어 프로젝트별 namespace 아래에 채택한 설계와 변경 이유를 저장하도록 구성할 수 있다. 다음 세션에서는 해당 프로젝트의 기록을 조회해 모델 입력에 넣는다. (github.com)

이때 LangGraph라는 이름의 그래프와 지식 그래프를 혼동하면 안 된다.

LangGraph의 Store를 쓴다고 기억이 자동으로 개체와 관계로 바뀌지는 않는다. 공식 문서의 기본 저장 단위는 JSON 문서이며 관계 모델은 별도 설계 대상이다. (github.com)

작은 팀의 시험 구성에서는 InMemoryStore를 사용할 수 있다. 다만 공식 문서는 운영 환경에 PostgreSQL 등 영속 저장소를 권한다. 프로세스 메모리에 넣어둔 시험 결과를 세션 간 영속 기억으로 오인하지 않도록 구분해야 한다. (github.com)

방의 사례처럼 다수의 업무를 함께 다룬다면 먼저 프로젝트별 인계가 정확한지 시험하는 편이 비교하기 쉽다. 공통 취향과 개별 프로젝트의 설계 결정을 같은 범위에서 검색할 필요는 없다.

관계와 변경 이력을 찾아야 할 때 그래프를 붙인다

Graphiti는 대화나 문서에서 개체와 관계를 추출하고 시간에 따라 바뀌는 사실을 관리하는 도구다. Zep 연구진의 논문은 관계의 과거 상태를 유지하면서 새 정보를 반영하는 구조를 설명한다. 단순한 최신 요약과 달리 어떤 관계가 언제 유효했는지 다루려는 접근이다. (arxiv.org)

공식 저장소 기준으로는 pip install graphiti-core로 라이브러리를 설치하고 Neo4j 같은 지원 데이터베이스와 모델을 연결한다. add_episode에 본문과 출처 설명, 기준 시간을 전달하면 정보를 그래프에 반영한다. 이후 search에 질문을 넣으면 관련 관계 객체를 반환한다. (github.com)

가령 프로젝트의 외부 API 교체 결정을 입력하고 나중에 현재 사용하는 API를 검색하는 식으로 시험할 수 있다. 이 예시에서는 입력 문장, 추출된 관계, 검색 결과를 차례로 확인한다. 검색 결과를 다음 모델 호출에 전달하는 연결 작업도 필요하다. (github.com)

그래프를 붙였다는 사실만으로 자연스러운 발화를 빠짐없이 기억한다고 말할 수는 없다.

Graphiti의 추출 과정은 LLM을 사용하며 공식 저장소도 모델의 구조화 출력 지원을 요구한다. 방에서 이야기한 일상적인 표현까지 포착하려는 목표는 별도의 입력 사례로 검증해야 한다. (github.com)

비용은 저장량보다 재개에 드는 전체 작업으로 비교한다

방에서는 기억 체계를 유지하는 데 상당한 토큰을 쓴다는 경험과 단순화한 구성을 더 시험하겠다는 의견이 함께 나왔다. 사용량이 크다는 관찰만으로 과투자라고 판단하기는 어렵다. 반대로 AI가 절약 가능성을 설명했다고 실제 절약이 확인된 것도 아니다.

Anthropic은 서브에이전트가 세부 탐색을 분리하고 핵심 결과를 반환하는 방식을 설명한다. LangChain은 기억을 응답 경로에서 갱신하면 지연이 늘 수 있다고 짚는다. 중심 세션의 입력이 짧아져도 다른 곳에서 기록을 만들고 검색하는 작업은 남는다. (anthropic.com)

비교 실험은 같은 작업을 세션 중간에 끊고 다시 이어가는 방식으로 설계할 수 있다. 짧은 인계문만 쓰는 구성과 필요한 원문을 추가 조회하는 구성을 비교한다. 입력·출력 토큰뿐 아니라 기억 작성, 검색, 재시도에 든 사용량을 함께 기록하는 방법이다. 복원 질문도 정해둘 만하다. 현재 목표는 무엇인지, 어떤 대안을 버렸는지, 마지막으로 확인한 결과가 무엇인지 묻는다.

답만 맞는지보다 해당 판단을 뒷받침하는 기록까지 찾는지 확인하면 기억 체계의 실패 위치를 좁힐 수 있다.

이번 사례에서 다단계 기억의 가치는 아직 절감률로 확인되지 않았다. 짧은 인계문으로 빠진 근거를 필요할 때 복원할 수 있느냐가 다음 검증 과제다. 세션 수명을 늘리는 것과 작업을 정확하게 이어가는 것은 같은 목표가 아니다.

자주 묻는 질문

Q

AI 에이전트의 세션 기억은 짧은 요약 파일만으로 충분한가?

파일 길이만으로 충분한지 판단할 수 없다. Anthropic은 압축 외에도 외부 노트와 별도 맥락에서 작업하는 서브에이전트를 제시한다. 중요한 기록을 다음 세션에서 다시 읽을 수 있는지 확인해야 한다. (anthropic.com)

Q

LangGraph 메모리와 Graphiti는 무엇이 다른가?

LangGraph의 Store는 namespace와 key로 기억 문서를 저장한다. Graphiti는 입력에서 개체와 관계를 추출하고 시간에 따른 관계 변화를 관리한다. (github.com)

Q

AI 기억 구조를 추가하면 토큰 비용이 줄어드나?

자동으로 줄어든다고 단정할 수 없다. 기억 작성과 검색에도 작업이 필요하므로, 같은 과제를 재개하면서 전체 사용량과 오류 수정량을 함께 비교하는 실험이 필요하다. (docs.langchain.com)
