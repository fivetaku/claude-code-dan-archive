블로그 자동화, GPT-6.1 Terra Medium으로 바꿔도 될까

GPT-6.1 Sol Medium과 비교해 토큰 비용·작성 품질·자동 발행 위험을 따져봤다.

2026-10-28논의 1회 정리

블로그 자동화에 쓰던 모델을 GPT-6.1 Terra Medium으로 바꿔도 될까. 클코단에서는 GPT-6.1 Sol Medium을 계속 쓸지, 새로 나온 Terra를 선택할지 의견이 갈렸다. 이 글은 두 모델의 공식 차이와 실제 사용 반응을 바탕으로 어떤 작업을 Terra에 맡기고 무엇을 Sol에 남겨야 하는지 답한다.

먼저 이름과 가격부터 맞춰야 한다

방에서 말한 ‘6 SOL’은 OpenAI 공식 표기인 GPT-6.1 Sol로 정리하는 편이 정확하다. OpenAI 모델 목록에서 GPT-6.1 Sol은 복잡한 작업과 높은 지능을 낮은 비용으로 처리하는 모델로 소개된다. GPT-6.1 Terra는 시각적 추론, 컴퓨터 사용, 자연스러운 글쓰기에 초점을 둔 빠른 모델이다.

API 표준 가격은 차이가 분명하다. GPT-6.1 Sol은 입력 100만 토큰당 2달러, 출력 100만 토큰당 10달러다. GPT-6.1 Terra는 입력 1달러, 출력 5달러다. 캐시된 입력도 Terra가 100만 토큰당 0.05달러로 Sol의 0.10달러보다 낮다.

두 모델 모두 최대 105만 토큰의 컨텍스트와 12만8000 토큰의 출력을 지원한다. 다만 실제 비용은 모델 이름만으로 결정되지 않는다. 추론 강도, 긴 입력, 캐시 사용 여부, 실행 모드가 함께 비용을 바꾼다.

블로그 초안만 보면 Terra가 유리하다

블로그 자동화는 대체로 검색, 자료 정리, 초안 작성, 제목·요약 생성, 검수, 발행 순서로 움직인다. 이 가운데 단순한 자료 정리와 초안 작성은 Terra Medium으로 먼저 시험하기 좋은 구간이다.

OpenAI는 Terra를 문서 작성과 수정, 화면 조작, 웹 검색, 파일 검색, 구조화된 출력에 사용할 수 있는 모델로 설명한다. 따라서 키워드 목록을 입력하고 제목, 리드, 본문, FAQ, 메타 설명을 정해진 JSON 형식으로 받는 파이프라인을 만들 수 있다.

실제 구성은 복잡하지 않다. 입력 파일에는 주제, 독자, 금지 표현, 참고 문서, 원하는 글 구조를 넣는다. 모델에는 웹 검색으로 사실을 확인하고 확인되지 않은 주장은 표시하며 결과를 title, dek, body, faq 같은 필드로 반환하도록 요구한다. 마지막 단계에서 사람이 원문 링크와 수치를 확인한 뒤 CMS API로 넘기면 된다.

이 방식에서는 Terra의 낮은 토큰 단가가 장점으로 작용한다. 같은 형식의 초안을 자주 만들고 글마다 사람이 검수한다면 Sol을 모든 단계에 쓰는 것보다 운영비를 줄일 여지가 있다.

문제 해결력은 글의 종류에 따라 갈린다

GPT-6.1 Sol은 OpenAI 모델 선택 가이드에서 복잡한 기술 작업과 여러 번 수정할 결과물에 적합한 선택으로 제시된다. 반면 Terra는 빠른 대량 작업과 화면 기반 업무를 겨냥한다. 블로그 글에서도 이 차이는 초안보다 예외 처리에서 드러난다.

예를 들어 참고 자료의 날짜가 서로 다르거나 통계의 정의가 자료마다 다르거나 한 문단에 여러 출처를 연결해야 하는 경우가 있다. 제목과 문장을 만드는 능력보다 중요한 것은 충돌을 발견하고 작업을 멈출지 결정하는 능력이다. 이런 편집 판단이 많다면 Sol Medium을 유지하거나 Terra 초안 뒤에 Sol 검수 단계를 두는 편이 안전하다.

써본 사람들 사이에서도 반응은 한쪽으로 모이지 않는다. Terra가 같은 작업을 더 빠르고 싸게 끝냈다는 경험이 있는 반면 높은 추론 강도에서는 사용량이 예상보다 커졌고 Sol Medium보다 결과가 단순했다는 불만도 나왔다. 작업별 토큰과 소요 시간을 직접 기록하지 않으면 모델 간 비교가 쉽게 왜곡될 수 있다.

특히 ‘Medium’이라는 이름만으로 비용을 비교하면 안 된다. Terra는 none, low, medium, high, xhigh, max 추론 강도를 제공한다. 같은 Terra라도 설정을 올리면 출력 품질과 비용이 달라진다.

자동 발행보다 검수 구조가 먼저다

블로그 자동화의 위험은 글이 어색하다는 데서 끝나지 않는다. 잘못된 날짜, 출처가 없는 수치, 경쟁사 문장의 재작성, 오래된 정보를 최신 정보처럼 제시하는 문제가 함께 생긴다. 자동으로 발행하는 구조라면 한 번의 오류가 여러 페이지에 반복된다.

Google Search Central은 생성형 AI 사용 자체를 금지하지 않는다. 다만 검색 순위를 조작하려고 가치 없는 페이지를 대량 생산하면 ‘scaled content abuse’에 해당할 수 있다고 안내한다. 사람에게 실질적인 도움을 주지 않는 자동 생성 페이지와 다른 웹페이지를 짜깁기한 페이지가 대표적인 위험 사례다.

그래서 최소한 세 개의 중간 산출물을 남겨야 한다. 첫째는 검색한 출처와 확인 날짜다. 둘째는 모델이 확정하지 못한 문장 목록이다. 셋째는 사람이 수정한 최종본이다. 발행 전에는 사실 확인, 중복 문장, 광고성 표현, 내부 링크, 이미지 저작권을 따로 검사해야 한다.

개인 개발자나 소규모 팀이라면 처음부터 하루 수십 편을 목표로 잡을 필요가 없다. 같은 주제의 글 다섯 편을 Terra Medium과 Sol Medium에 각각 생성하고 수정 시간과 오류 수를 기록하면 된다. API 비용보다 편집자가 고치는 시간이 더 크다면 싼 모델을 고른 의미가 줄어든다.

Terra로 시작해도 되는 작업과 남겨야 할 작업

Terra Medium은 반복성이 높은 초안 업무에 우선 배치하는 것이 합리적이다. 예를 들면 제품 설명의 형식 변환, 이미 검수된 자료의 요약, FAQ 초안, 메타 설명 생성, 내부 링크 후보 추출이 있다. 출력 형식을 고정하면 비교와 재처리도 쉬워진다.

반대로 최신 수치가 핵심인 기사, 법률·의료·금융처럼 오류 비용이 큰 글, 여러 출처의 충돌을 해석하는 글은 Sol Medium 또는 사람의 직접 검토를 남겨두는 편이 낫다. Terra가 웹 검색과 구조화된 출력을 지원한다는 사실은 자동 발행까지 보장하지 않는다.

가장 현실적인 구조는 역할을 나누는 방식이다. Terra가 검색 결과를 정리하고 초안을 만든 뒤 Sol이 출처 일치 여부와 논리 흐름을 검토한다. 마지막으로 사람이 발행 여부를 결정한다. 반대로 단순한 콘텐츠 변환이라면 Terra 단독으로 돌리고 오류가 발견된 항목만 상위 모델로 재검토할 수 있다.

모델 선택의 답은 ‘Terra가 Sol보다 좋은가’가 아니다. 블로그 자동화에서 비용을 줄이는 단계와 판단을 맡겨야 하는 단계를 분리할 수 있는가가 핵심이다. Terra Medium은 초안 생산기라면 충분히 시험할 가치가 있지만 사실 확인과 발행 승인까지 대체하는 모델로 쓰기에는 아직 운영 장치가 더 중요하다.

Q

GPT-6.1 Terra Medium과 GPT-6.1 Sol Medium 중 블로그 작성에는 무엇이 좋은가?

반복적인 초안과 요약은 GPT-6.1 Terra Medium이 비용 면에서 유리하다. 복잡한 자료 충돌과 고난도 검수는 GPT-6.1 Sol Medium이 더 적합하다.

Q

GPT-6.1 Terra로 블로그를 자동 발행해도 되나요?

기술적으로 자동화할 수 있지만, 사실 확인과 사람 검수를 거치는 편이 안전하다. 가치 없는 페이지를 대량 생산하면 검색엔진의 스팸 정책에 걸릴 수 있다.

Q

GPT-6.1 Terra의 API 가격은 얼마인가요?

표준 기준 입력은 100만 토큰당 1달러, 출력은 5달러다. 캐시 입력과 긴 컨텍스트, 처리 모드에 따라 실제 비용은 달라질 수 있다.
